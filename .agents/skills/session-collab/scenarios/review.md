# 独立复核

适用于由另一方检查已有代码、文档或方案。实施方与审查方分开；协调者可以兼任其中一方。

1. **交审。** 提供原始需求、完成条件、材料来源、完整被审对象及已知故障证据。标记被审版本和范围；文件用内容哈希，未跟踪文件也须纳入。作者的猜测和建议在审查方形成独立发现后交换。
2. **检查。** 审查方亲自阅读成果并完成必要验证，先记录发现再讨论解法；可补充材料、澄清事实。每条发现写明位置、严重度、证据、影响、建议和置信度。对被审产物只读，验证遵循[资源协调](../../../../docs/workbench/cross-session-collaboration.md#四资源协调)。
3. **处置。** 实施方逐项接受、驳回或延期，给出理由与证据；修复已接受项并说明变化。驳回或延期不能消除真实的未达标问题。
4. **复核。** 审查方直接检查修改后的成果。版本变化后先判断哪些结论依赖已变化的内容或前提，再复验这些部分；未受影响的证据保留。范围无法判断时扩大复核，详见[版本与证据规则](../../../../docs/workbench/cross-session-collaboration.md#52-独立复核)。
5. **完成。** 双方各自按[达标判据](../../../../docs/workbench/cross-session-collaboration.md#35-状态与推进)检查最终成果，再交换验收结论。残余问题和分歧如实列出，重大产物另须完成[终审质量门](../../../../docs/workbench/cross-session-collaboration.md#313-终审质量门唯一门禁清单)。

阻断问题须经修复验证、以证据纠正严重度或由用户明确接受相应取舍；审查者不能自行降低用户要求。尚有未达标项时继续修复，确实受阻则报告缺口与阻碍。

发现格式：

```markdown
- [blocker|major|minor] <标题>
  - 位置：<文件:行或缺失点>
  - 证据：<可核实的事实>
  - 影响：<对需求或结果的影响>
  - 建议：<处理方向>
  - 置信度：<高|中|低>
```
