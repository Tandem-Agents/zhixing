# 删除资源

以用户要达到的结果选择方法。移除一个项目中的引用、删除它指向的对象、释放存储空间，可能是三个不同的动作。

## 选准目标

- 核对目标所在的位置、账户或环境，以及授权覆盖的范围。用户已说清对象和处置方式时，直接执行。只有影响范围或不可逆后果仍有实质歧义时，才针对那一点确认。
- 按用途判断能整体删除的最大单元。一个已结束的实验目录可以整选；若其中混有仍在使用的工具，只下探到能把两者分开的层级。无须为证明整组可删而逐项查引用或预先遍历计数。
- 动手前核对实际选中的路径、对象标识或筛选条件。删除链接时只处理链接本身；若父对象会级联删除子项、共享副本或其他人的数据，先核清这些影响是否在授权内。

## 按资源所属系统执行

按资源的管理归属选择原生删除方式：由某个系统或应用管理的资源，用它提供的删除入口；没有专门管理者的普通文件和目录，用所在文件系统的删除。自动执行时，使用与该入口等价的自动化能力：同一个删除操作，作用于选中的整体单元，一次提交，并保留它的确认、恢复和失败处理。调用了某个系统接口不等于等价；自写递归或逐项循环不是原生删除。管理入口只处理了一部分、留下登记或本体时，再用各自的原生方式处理剩余部分，并分别核对结果。多个对象的授权范围和处置方式相同时，优先用现成的“多选后删除”或语义等价的批量接口。

批量看调用方实际提交了几次。可以逐个把标识加入同一选集，最后只提交一次，由系统决定内部如何调度。把多次单项删除包进一条命令，依然是逐项操作。已有入口能够整批完成时，直接传入选集，省去自写删除流程。

- 先按完成条件选删除方式。只需移除目标时，优先采用可恢复删除；明确要腾出空间或配额时，选择能在要求的时间内实际释放容量的方式。如果达标必须永久删除，先核对已有授权是否明确覆盖这一后果。仅要求防止资料长期累积，不构成永久删除授权。
- 让原生机制负责遍历子项、调度和进度。现有接口只能逐项操作，而用户界面支持等价的原生多选时，优先使用多选入口。已确认整个目录或容器可删，就直接提交该容器，省去自写递归、逐项限速和预先统计。
- 默认只发起一个原生批量作业，沿用系统的并发设置，避免叠加删除进程或主动调高并发。仅在入口有批量上限、缺少批量能力或确需减载时，才按已选的顶层单元分批，一批结束再提交下一批。已有指标或反馈显示持续 I/O 争用、前台响应变慢或服务限流时，优先暂停或降低当前作业的负载。

## 核实与收尾

- 会话中断、超时或回执丢失，先到实际执行任务的宿主或服务查原进程、作业标识或进度。仍在运行就接续观察；状态不明时先对账，不再启动第二份同范围操作。
- 结束后一次核对目标状态和保留项。没有全部完成时，先区分已完成、仍在处理和剩余的对象，再看具体错误；重试或换入口之前都先做这一步，同范围的操作仍在进行就不再发起。
- 按错误处理剩余对象：
  - 错误确实指向批量上限或个别对象冲突时，才针对剩余对象拆批。
  - 权限或审批被拒绝、需要授权之外的永久删除时，按原授权边界处理，不换入口、不靠递归拆小来绕过。
  - 其他错误不直接当作资源本身的问题，也不围绕某个接口的报错无界排查。资源所属系统的标准删除入口可以由自己直接操作、且本次还没实际用过时，先通过这个入口处理剩余对象；已经调用过某个原生接口，不构成跳过它的理由。标准入口也失败，或自己确实无法操作它时，再按本节的授权与能力边界处理。没有新证据或状态变化时，不重复已失败的同一路径。报占用时，先检查自己的会话（包括当前所在目录）和自己启动的进程是否持有，不擅自关闭别人的应用。
- 只有自己确实无法安全完成、缺少必要权限或能力时，才交给有权限的人，并说明已完成的部分、剩余目标和具体阻碍。
- 简要报告结果和需要关注的例外。只有目标明确要求释放空间时才核对实际容量变化。
