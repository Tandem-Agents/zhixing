# 视觉制作与嵌入

## 手法与组合

以下手法各有用途，围绕已经确定的视觉方向选取，不逐项配齐。组合时先确定主画面，再让页头、正文和辅助元素衬托它。

| 手法 | 用途与搭配方式 |
| --- | --- |
| 紧凑页头 | 名称／标识、短定位和关键入口形成清楚的开场；可局部居中，正文恢复左对齐。已有主视觉包含品牌时，缩小或省去重复的大 Logo。 |
| 品牌主视觉 | 从项目自身的形状、色彩和语义构图，增强辨识度。可以围绕真实成果组织画面；若截图或演示已承担焦点，品牌图形作为配套，不再叠一张同等醒目的横幅。 |
| 真实截图与演示 | 让读者看到能力与结果；静态图突出成果，短演示呈现关键过程。统一裁切、背景与边框，同一内容不重复放静态和动态大图；静态承接用链接。 |
| 分层动效 | 以“分层进入—完整停留—平顺结束”突出品牌或构图层次。沿用静态画面的图形语言，其他元素保持安静；只有选用动效时才制作，不为每个区块加动画。 |
| 原生正文与强调 | 标题、短列表、带语言标记的代码块形成稳定层级；短对照用表格，关键提醒用目标平台支持的提示块。强调应稀疏，图形标题不能替代真实标题，不用多列表格模拟网页卡片。 |
| 徽章、图标与短导航 | 徽章表达真实状态，图标辅助识别，导航服务主要入口。同类组件统一尺寸与风格，强调色沿用页面配色，权重低于主介绍；没有有用状态不放徽章，短页面不重复加完整目录。 |
| 简图 | 仅解释短文难以说清的关系，贴近对应内容。按目标渲染器选择原生图示或静态 SVG，沿用页面色彩与线条，不为展示而展开内部全景架构。 |
| 折叠与细节收纳 | 收起备用步骤、低频 FAQ，保持正文节奏；必要前提、主要操作与风险直接可见。 |

组合例如：有辨识度的成果图作为主角时，配紧凑文字页头、少量状态与原生正文即可；需要呈现交互过程时，让短演示成为主角，标识与辅助图解退居配套；没有合适画面时，用标识、清晰字阶和真实文本示例建立层次。

## 成品打磨

在 README 的实际显示宽度下看首屏，再看整页；素材单独打开好看，不代表嵌入后比例合适。与选定的优秀视觉参考对照层次、留白和细节完成度，保留项目自己的风格。

| 观察到的问题 | 调整方向 |
| --- | --- |
| 整齐却平淡，没有记忆点 | 拉开主角与配套元素的大小、明暗和疏密差异；从项目已有形状或成果中突出一个有辨识度的细节，不靠增加效果种类制造亮点。 |
| 首屏笨重、拥挤或空散 | 调整主画面高度与裁切、标题和入口的距离；相关元素靠近，段落之间留白。优先修比例，不一律缩小全部内容，也不把留白变成大片空洞。 |
| 颜色统一仍像拼贴 | 对齐画面边缘，统一同类素材的背景、圆角、描边和内边距；协调截图与页面底色的过渡，减少互相竞争的高饱和色块。 |
| 看得清但不精致 | 检查模糊边缘、过小标注、生硬裁切、松散对齐和不一致图标；优化原始素材与导出质量，不用阴影、渐变或动画遮掩基础问题。 |
| 首屏漂亮，往下失去节奏 | 让少量品牌细节贯穿全页，以标题、图文比例与留白形成起伏；避免连续大图、密集表格或重复横幅把页面切成互不相干的几段。 |

每轮针对实际看到的主要问题调整，再按相同尺寸对照前后效果。构图与层级先于局部装饰；明确的视觉问题解决、整页协调且使用信息完整后即可交付，不为凑轮次持续换风格。

## 主视觉与真实画面

- 主视觉采用清楚的大标题／图形与充分留白；复用同一套色彩、线条和边角。用尺寸与留白建立层次，不靠每段换一种装饰。
- 图形与排版优先保留为 SVG；截图、照片和复杂画面使用 PNG／WebP。截图裁到有信息的区域，避免整屏缩小后文字不可读。
- 横幅可以从约 1200 像素宽、3:1 比例开始制作，这是制作起点而非固定尺寸。最终以 README 实际内容宽度和窄屏效果调整；窄屏看不清时简化画面，不继续塞小字。
- 图片中的文字只承担短标题或画面必要标注。正文、用法与入口放在 Markdown 中；替代文本描述图像传达的信息，不写“图片”“效果图”敷衍。
- 深浅背景都必须可读；先尝试一份兼容素材，确有需要再提供明暗两份。不要为主题适配复制整份 README。

## 首屏动效：分层进入与停留

选用品牌动效时，以少量元素的依次显现、轻微位移与强调线展开形成动效；标题与关键入口始终可获取。

1. 先做好完整静态画面，保留可编辑 SVG 与稳定的图层标识。
2. 给重点图层分配进入时间，尽快到达完整构图；随后留出足够的静止阅读时间。可从约 4–6 秒总时长、约 2 秒完整停留开始试做，不将参数当成硬性标准。
3. 结束后停在完整画面；如果循环，首尾衔接平顺，不突然黑屏或清空信息。另保留可访问的静态版本，读者不必依靠动画才能理解项目。
4. 优先把分层动画导出为可直接嵌入的 GIF；控制尺寸、帧率与色板，优先保证文字清晰。短横幅以约 2 MB 作为优化起点，不是平台上限；过大先简化动作与画面，不牺牲可读性。
5. 检查开始、完整停留、结束／循环以及缩小后的画面。静止段应真正停止运动；不要靠增加动作来掩盖构图问题。

真实演示只展示一个完整过程，保留开始状态、关键动作和最终结果，裁去等待与无关操作。较长演示使用静态预览加可点击链接，不把整段视频转成巨大 GIF。

使用现有图形与动画工具制作，保留静态成果；动画 SVG 的支持以目标平台实际嵌入效果为准。

## 嵌入方式

以下路径使用时替换为仓库真实素材路径。

### 同一画面适配深浅主题

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="./assets/overview-dark.svg">
  <source media="(prefers-color-scheme: light)" srcset="./assets/overview-light.svg">
  <img src="./assets/overview-light.svg" alt="用一句话说明这张图传达的信息" width="100%">
</picture>
```

HTML 块前后留空行；不要把整篇 Markdown 包进 HTML 容器。普通图片使用相对路径，明确渲染目标另有要求时再调整。不要依赖 README 正文中的自定义 CSS、JavaScript 或 iframe 做网页布局。

### 静态入口与动效并存

```markdown
![描述动画中呈现的内容](./assets/overview.gif)

[查看静态图](./assets/overview.png)
```

动效不是唯一的信息来源；主介绍、关键结论与操作入口仍在邻近正文中。

### 折叠次要细节

```markdown
<details>
<summary>其他使用方式</summary>

这里放备用步骤；主路径和必要前提不藏在这里。

</details>
```

徽章使用同一视觉样式、清楚的标签和真实状态；每个可点击徽章指向对应来源，不把需要分别点击的徽章合成一张图。第三方动态图属于可选依赖，不是默认组件。
