# 上下文管理架构

本文定义上下文管理的当前职责、核心机制与设计取舍；动态信息注入见[逐轮上下文注入](turn-context-injection.md)，会话任务状态见[任务列表](../conversation/task-list.md)。上下文是模型执行的输入，不是长期记忆，也不是历史对话的存储本体。

历史保存、启动恢复、clear 与保留期，以及它们同窗口的协作和当前实现差异，见[对话持久化与注意力窗口架构](../conversation/persistence.md)。

## 目标与取舍

让知行在短问答和持续工作中获得足够且相关的输入，兼顾任务连续性、模型容量、成本与响应速度，不要求用户理解内部窗口或手工组装上下文。

- 标称上下文容量不等于有效工作容量：按模型的注意力阈值管理窗口，不以“尚未填满”判断质量足够。
- 保持稳定输入，减少无意义的前缀改写；缓存收益服从正确性与任务连续性，不承诺固定命中率或成本倍数。
- 压缩保留当前目标、任务进展、关键结论与协作锚点，而非逐条复述历史；摘要是有损工作材料，不能代替原文事实。
- 同一会话的用户历史保持连续；模型看到的工作窗口可以折叠，历史原文不能因压缩被截短。

## 状态与责任

| 对象 | 职责与归属 |
|---|---|
| 原始 run 记录 | 会话 owner 接受、提交并投影的历史事实；压缩不改写它 |
| 注意力窗口 | 会话持有的模型工作视图；由启动装填、摘要对与已接受 run 的用户／最终回复配对组成 |
| run 内消息 | 当前模型—工具循环的完整协议消息；工具中间过程不作为跨 run 窗口原样无限累积 |
| 发送视图 | 在工作消息上附加当前动态上下文、窗口级前缀等发送材料；不因此改变历史记录 |
| 段切换机制 | 估算、决策、生成摘要与窗口折叠指令；不拥有会话提交权 |
| 段元数据与窗口快照 | 支持段信息记录和窗口恢复；不替代原始 run 的权威事实 |

```text
会话窗口 → run 工作消息 → 动态注入与发送前缀 → 模型—工具循环
                               ↓ 实际请求用量校准
                        段评估 → 摘要／降级 → 窗口折叠指令
run 原文与结果 → owner 接受／提交 → 原文投影 + 窗口推进
```

窗口折叠与原文持久化分离：持久会话在原文追加成功后推进窗口；权威提交的投影按提交身份幂等应用。瞬态会话先记录 pending run，再推进窗口。失败不能靠提前更新窗口伪装成已接受。

## 窗口与发送边界

注意力窗口以消息配对维持连续性，折叠时以新摘要替代被覆盖部分，包括旧摘要，再保留未覆盖配对。中断且没有最终回复的 run 可在窗口中配空回复；这只是视图处理，不伪造历史记录。

窗口摘要以系统元信息标签标明它不是用户原话，并配套机制回执保持消息配对；模型应据此继续工作，不回应摘要本身。

运行体在窗口生命周期内维护稳定的 system prompt 和发送前缀，工具集由装配时的 profile 与实际工具绑定确定，不按每次模型调用进行 LRU 增删。换窗、clear、resume 等边界按现有生命周期重新装填；“稳定”不等于整个进程永远不能更新。

发送材料与可摘要内容必须区分：段评估计算 system、实际发送消息与 tools 的总量；摘要只消费可摘要工作消息，不把发送前缀反复蒸馏进摘要。动态注入不直接写入会话原文。持久工作约定的加载由 guidance 机制负责，本文不重复定义其文件作用域。

## 段切换与摘要

模型能力提供 `optimalMaxTokens` 与 `riskMaxTokens`，经配置覆盖、内置能力和兜底解析后交给运行体；它们是工程阈值，不是对模型质量的绝对保证。估算器覆盖 system、消息与 tools，使用实际请求 usage 校准，不能只估消息却拿整次输入用量校准。

| 当前估算量 | 动作 |
|---|---|
| 小于 optimal | 不干预 |
| optimal 至 risk 之间 | 有进行中任务则延后，否则切段 |
| 达到 risk | 强制切段，不因任务仍进行而无限延后 |

评估在循环的安全边界执行，不在流式输出中途重组消息；超限保护还覆盖发送前检查。任务状态只参与切段时机，不因切段被修改或清空。

自动切段与手动 `/compact` 共用 SegmentManager；手动路径将阈值置零，绕过进行中任务延后。当前摘要请求使用 `roles.light.model` 与 light thinking，并通过运行体的 Provider 调用适配、重试、watchdog 和校准链发送，不另建一套无保护的 LLM 出口。不能继续沿用旧文档“摘要必须与主会话同模型，因此缓存必命中”的结论。

摘要为 `facts / state / active` 三段：分别保留结论、未完成工作与用户期望、后续所需的路径／标识符／决策等锚点；语言跟随对话，模板要求简短输出。程序解析结构并拒绝全空摘要，但不能把结构可解析当作语义无损的证明。新段保留最近配对作为缓冲，默认两轮，不切断工具协议配对。

正常结果经 `segment:new_started` 携带 `windowCompact`，由运行体汇集后交给会话 owner 应用。段元数据另走会话写入端口；durable assignment 内暂存为 `segment-append`，不能在执行端另写一套权威记录。

### 失败与恢复

- 摘要调用有有界重试和中断保护；全空解析等关键失败也进入失败路径。
- 摘要调用或解析失败时，若达到 risk 且未取消，则机械截断兜底并报告降级原因；否则保持原工作消息。不得将降级称为成功生成摘要。
- Hook 的 beforeSummarize 失败中止该次正常摘要流程；摘要后的 Hook 失败报告 warning，不丢弃已生成摘要。段元数据写入失败与窗口折叠结果分开表达。
- 重启、恢复和快照消费由会话层依据已提交原文与有效窗口恢复材料完成；上下文机制不能自行删除历史或另建会话来伪装换窗。`clear` 是独立的会话用户操作，不等于压缩。
- 子智能体不启用主会话段切换；使用自身预算与上下文风险检查，失败回报主智能体决定下一步，而非偷偷继承父会话窗口。

## 演进中保留的判断

早期 v1.2 的场景分类、Pin 与分级裁剪，v2 的动态工具分层、结果锚化和滑窗编译，均不再是当前架构。保留的教训是：减少 token 不能只看单次文本长度，还要考虑前缀稳定性、模型实际表现与信息连续性；不能把模型已经输出回复等同于它已无损吸收全部工具结果。

v3 的模型驱动阈值、段式管理、任务状态跨段保留和手动／自动压缩同源仍有价值；旧 ContextEngine／MessageDrop／LLMSummarize 双链、七段摘要模板和实施分波不再保留为现行机制。当前只维护段切换一条压缩链，不预建分块摘要、召回、长期记忆或监控平台。
