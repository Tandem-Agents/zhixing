# MCP 接入与管理

系统负责查找服务、准备连接配置与验证；用户只处理必要选择、私密值输入与执行确认。正常路径不要求手写配置文件。信息不足时如实说明，不能让模型编造包名、命令、密钥要求或获取地址。

本文负责接入和配置生效，连接、工具映射与执行安全以 [MCP Host 架构](architecture.md)为准。

## 交互入口与配置状态

MCP 产品应用统一承接发现、候选与探测，以及配置提交和生效结果；CLI 面板和模型工具是不同接入面，不各自定义接入成功。Anchor 本地的主对话与工作场景可通过 `mcp_discover` 查找真实服务、读取来源，再以 `mcp_connect` 提交公开候选及原任务交接；已有工具、技能或程序能完成任务时无需注册新工具。

远端主对话与工作场景使用 `mcp_delegate` 交接原任务及公开方案；请求成功提交后，产品应用在 Anchor 创建仅接收获准材料的隔离主会话，接入仍需单独确认，结果返回原对话，不要求先创建场景或让用户重述任务。场景也可沿已有任务交接返回来源主对话；没有来源时采用同一隔离承接。承接者不加载其他对话历史、个人约定或默认工作目录，不跨设备代装或复制凭据。Anchor 新增的能力不能冒充远端已具备的能力，剩余设备或工作区任务仍由原对话处理。后台和子任务不自行承担设备配置或发起此接入委托。

返回原任务或同一任务接入后续跑时，保留原 Run 权威准入中的显式工作区引用，由新的准入重新核验绑定和权限；该引用不传给隔离承接会话，也不覆盖新进入场景或主动切换后的工作区选择。

模型接入须逐次确认执行设备和实际命令或 URL，原 Run 成功提交后才消费请求。隔离承接会话的确认根据仍有效的权威委托关系呈现在原任务接入面，推送、重连查询和应答使用同一边界；应答仍属于真实承接会话，其他观察者不因此获得控制权。若 Anchor 没有本机执行器，不创建无法运行的承接任务，而是向原任务耐久返回具体阻塞，保留原验收身份，供模型判断其他办法。

确认面板说明实际执行设备、原任务对话和安全输入入口。缺少凭据时，在该设备打开原任务对话的 `/mcp`，从仍有效的耐久任务投影出预填候选及实际“等待安全录入凭据”状态；用户无需重述技术配置，私密值只在安全面板输入。批准本身不代表接入已完成，也不代表必然缺少凭据。待接入查询属于设备本地入口，不从远端编辑器中继到 Anchor；远端没有本地自动接入任务时返回空列表，不阻塞原有本地手工管理。取消或已失效的任务不再接入，失败如实反馈；接入生效后沿原任务交接继续，保留已有独立验收和交付责任。

`/mcp` 使用配置编辑器的多步面板与事务暂存，而不是单行 typeahead：服务选择、候选、多个密钥、验证与保存需要连续交互。编辑器要求支持相应终端界面；非 TTY 入口明确拒绝。

服务列表来自配置中的全部 server（包含停用项），再叠加运行状态，不能用 hub 的启用连接列表代替，否则停用后无法重新启用。当前面板提供连接信息、启停、删除、预设与其他 server 接入；后台重连不需要手动重连操作。连接中不是配置缺失，不能因此阻止保存或阻塞整个应用。

运行态不写进配置事务。当前 `/mcp` 打开时取一次宿主状态快照，重开才更新，不是实时订阅，也不是每次按键重新向宿主查询。工具浏览、勾选及现有 server 通用编辑尚未完整提供。

## 输入到候选

| 输入 | 当前路径 | 不交给模型的事实 |
|---|---|---|
| 预设 id / 名称 | 预设转换成候选 | 连接模板、密钥字段与值模板由维护的数据给定 |
| HTTP(S) URL | 直接形成 HTTP 候选 | 地址来自用户输入，不猜地址 |
| 含空白的完整命令 | 拆成 stdio command / args | 命令来自用户输入，不猜启动方式 |
| 单 token 包名或关键词 | 搜索 → 最多五个真实包候选 → 用户选择 → 独立提取 | 包名必须出现在本轮真实搜索返回集合中 |

预设目前包含 GitHub、Notion，连接模板作为数据维护；第三方接入要求可能变化，预设不能代替实际连接探测。选择的产品边界是外部服务，不扩成内置本地工具的重复目录。

当前命令解析按空白分割，不具备 shell 引号、转义或复杂命令解析语义；多词自然语言也会进入命令分支，不能把当前输入能力描述成任意自然语言搜索。

所有路径收敛到 `McpSetupCandidate`：server id、连接 entry、多个秘密字段、来源与可选主页。不同来源不另建保存或探测流程。派生 id 必须合法，新增时拒绝与现有 id 冲突，不能静默覆盖既有连接。

## 为什么搜索与提取分开

仅凭模型记忆推断会编造包名、密钥要求和链接；仅按精确包名查询又要求用户知道技术标识。搜索引导让模型在真实索引上判断用途与适合度，既保留智能判断，又把存在性留给事实来源。

场景使用[轻量工具循环](../tools/lightweight-tool-loop.md)，提供搜索和读取包说明两个工具。模型依据包名、描述与 keywords 判断是否为 MCP server，以下载量作为流行程度的线索，拿不准时读取 README 核实用途。搜索结果累积在本轮集合中，最终候选包名不在集合或超过五项时拒绝；没有候选就如实返回没有找到。循环有轮数边界，搜索、读说明、分析等结构化进度由 MCP 场景翻译为用户可理解的文字。

候选校验只证明包名来自真实返回，不证明用途摘要、推荐理由、主流程度或服务可信。模型输出结构不合格也可能被解析为空候选，因此空列表并不总能证明现实中没有相应服务。

选择后调用独立的 `mcpExtract(packageName)`，只读选中包并提取配置。不能把精确包名再交回 `mcpResolve`，否则会重启搜索。通用循环不负责 MCP 配置、密钥或落盘。

## 真实来源与缺失信息

包源查询区分“确不存在”“查询失败”“找到”；网络不可达不能说成包不存在。当前元数据走 npmmirror，缺 README 时尝试 jsDelivr；国内可用性是选源要求，但不是对网络永远可达的保证。抓取与探测共用安全网络出口及代理配置。

有说明文本才调用 main 角色模型提取启动配置、密钥字段与获取链接。提示约束只使用给定文本，未说明的留空；当前 README 按字符上限截取，不是精准章节抽取。输出无法解析时回落到 `npx -y <已确认真实包名>`；可解析时 command 与 args 分别补缺，缺 command 用 `npx`，缺有效 args 用上述包参数。这只是待探测的基线，不能视为正确启动方式已获证明。

无 README、来源不足或查询失败时提供明确原因，允许改用预设、完整命令或 URL。密钥地址未提供则使用真实主页作查询入口，不编造链接。没有提取出秘密字段只表示“未识别到要求”，不保证免鉴权；当前面板会显示“无需密钥”，这是文案与证据强度的差异。

URL/命令直接候选的秘密字段为空，当前没有鉴权失败后自动补出任意 header/env 字段的通用流程，“需要时再手动补密钥”的接入需求尚未完全实现。基于真实文本的约束目前仍部分依靠模型遵循提示，不是对所有提取字段逐项进行来源证明。

## 探测前确认、秘密与提交

管理面板由用户显式发起临时探测：

```text
候选 → 展示实际 stdio 命令或 HTTP 地址／录入秘密 → Enter 确认
     → 带秘密临时连接并列工具 → 成功后更新编辑器暂存
     → 用户完成编辑 → 持久化配置与秘密 → Host 换代
```

stdio 探测会实际启动本机命令，确认必须在探测前，不能放到保存前。候选面板展示实际命令或 HTTP 地址，包括预设；Enter 验证代表同意。这是接入阶段的执行确认，不替代运行工具时的共同安全管线。

用户输入秘密值不传给提取模型。字段可包含多个秘密，按字段逐一收集，模板可将裸值变成 `Bearer ...` 等投影；HTTP 注入 header，stdio 注入 env。临时 probe 使用独立的 60 秒默认超时，为首次启动下载留出时间，与常驻连接的 10 秒超时不同；成功或失败均释放临时连接，不转交给正式 hub。

探测成功证明当时可建链并发现工具，不证明所有工具权限、业务结果、安全性或后续可用性。失败留在候选面板给出原因并允许修改重试，不提交半成品。取消向探测/查询传递信号；模型经宿主 RPC 调用时，本地取消等待不等于远端模型推理已被取消。

成功探测只修改 `WorkingState`，用户完成编辑才落盘；普通配置保存 server 的 transport、command/args 或 URL、启用决策，秘密由设备 SecretStore 保存并按 server id 关联。加载时停用项与非法 id 不生成运行连接规格。

保存与删除遵循以下规则：

- 编辑器持有完整配置与秘密集合，保存时对所提供的 MCP 子表采用整体替换；省略某个 server id 表示删除。部分 patch 的默认 id 级合并会保留未提及的 server，不能用它代替编辑器完整保存，否则删除会失效。
- 编辑状态中的连接条目整体替换，避免切换 transport 后残留旧 command/url；启停只更新 `enabled`、保留连接字段。秘密字段补丁则合并到对应 server，保留未提及字段，不等于删除秘密。
- 删除 server 同时从编辑状态的配置与秘密集合移除对应 id，用户完成编辑后再持久化，避免遗留孤儿凭据。两处状态同步删除不代表配置文件与 SecretStore 具有跨存储原子事务。

模型自动接入不执行独立的临时探测：先持久化已确认、与当前配置及凭据代际精确绑定的候选，再由正常 Host 连接同时验证和启用，避免提交前崩溃后重新试跑未记录的命令。提交结果不确定时先读取配置核对，不盲目再次写入或启动；已经配置但断开的连接可按正常生命周期重连，这不等于保证外部服务内部副作用恰好一次。

配置保存与运行生效是两件事。用户管理面保存后等待在途 turn，再请求 Host 排空关闭、换代并刷新；模型接入只允许新增连接，在原 Run 结束后由宿主增量添加，不替换已有连接，也不等待自己排空。新运行按执行设备实际能力重新取得工具、权限和能力说明，已发出的执行任务继续使用冻结投影，不能被后来新增的 MCP 工具改变。只有连接实际生效才续接原任务；提交、启动或探测成功都不能冒充任务完成。

调度任务每次签发读取当前 Job 角色能力，不借用对话配置或场景管理能力；签发后的工具和服务器集合贯穿本地／远端装配，执行前核对实际投影，不能被新连接扩大或越过显式工具限制。

配置提供者按当前版本比较后提交，拒绝覆盖并发修改或重新安装已被删除的服务。秘密只使用宿主启动时已经授权、与配置绑定的投影；凭据代际变化需安全换代，旧标识的孤儿凭据不能转给新服务。恢复依据已有配置与任务准入回执去重，不重复探测已提交配置或重新发起已接纳的续接。

按工具选择是 MCP 管理的需求，当前尚未形成有效过滤链：`parseServerSpecs` 不将 `tools.include/exclude` 带入规格，运行适配器映射全部已发现工具。配置形状存在不等于过滤生效。
