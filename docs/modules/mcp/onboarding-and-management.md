# MCP 接入与管理

系统负责查找服务、准备连接配置与验证；用户选择所需服务、提供私密值，并对本机执行作知情确认。正常路径不要求手写配置文件。信息不足时如实说明，允许用户提供明确 URL 或命令，不能让模型编造包名、命令、密钥要求或获取地址。

本文负责接入和配置生效，连接、工具映射与执行安全以 [MCP Host 架构](architecture.md)为准。

## 交互入口与配置状态

`/mcp` 使用配置编辑器的多步面板与事务暂存，而不是单行 typeahead：服务选择、候选、多个密钥、验证与保存需要连续交互。编辑器要求支持相应终端界面；非 TTY 入口明确拒绝。

服务列表来自配置中的全部 server（包含停用项），再叠加运行状态，不能用 hub 的启用连接列表代替，否则停用后无法重新启用。当前面板提供连接信息、启停、删除、预设与其他 server 接入；后台重连不需要手动重连操作。连接中不是配置缺失，不能因此阻止保存或阻塞整个应用。

运行态不写进配置事务。当前 `/mcp` 打开时取一次宿主状态快照，重开才更新，不是实时订阅，也不是每次按键重新向宿主查询。旧稿中的工具浏览、勾选及现有 server 通用编辑不是已经完整提供的交互。

## 输入到候选

| 输入 | 当前路径 | 不交给模型的事实 |
|---|---|---|
| 预设 id / 名称 | 预设转换成候选 | 连接模板、密钥字段与值模板由维护的数据给定 |
| HTTP(S) URL | 直接形成 HTTP 候选 | 地址来自用户输入，不猜地址 |
| 含空白的完整命令 | 拆成 stdio command / args | 命令来自用户输入，不猜启动方式 |
| 单 token 包名或关键词 | 搜索 → 最多五个真实包候选 → 用户选择 → 独立提取 | 包名必须出现在本轮真实搜索返回集合中 |

预设目前包含 GitHub、Notion，作为数据维护，不把旧稿当作第三方服务当前接入规则的证明。选择的产品边界是外部服务，不扩成内置本地工具的重复目录。

当前命令解析按空白分割，不具备 shell 引号、转义或复杂命令解析语义；多词自然语言也会进入命令分支，不能把当前输入能力描述成任意自然语言搜索。

所有路径收敛到 `McpSetupCandidate`：server id、连接 entry、多个秘密字段、来源与可选主页。不同来源不另建保存或探测流程。派生 id 必须合法，新增时拒绝与现有 id 冲突，不能静默覆盖既有连接。

## 为什么搜索与提取分开

仅凭模型记忆推断会编造包名、密钥要求和链接；仅按精确包名查询又要求用户知道技术标识。搜索引导让模型在真实索引上判断用途与适合度，既保留智能判断，又把存在性留给事实来源。

场景使用[轻量工具循环](../tools/lightweight-tool-loop.md)，提供搜索和读取包说明两个工具。搜索结果累积在本轮集合中，最终候选包名不在集合或超过五项时拒绝；没有候选就如实返回没有找到。循环有轮数边界，搜索、读说明、分析等结构化进度由 MCP 场景翻译为用户可理解的文字。

候选校验只证明包名来自真实返回，不证明用途摘要、推荐理由、主流程度或服务可信。模型输出结构不合格也可能被解析为空候选，因此空列表并不总能证明现实中没有相应服务。

选择后调用独立的 `mcpExtract(packageName)`，只读选中包并提取配置。不能把精确包名再交回 `mcpResolve`，否则会重启搜索。通用循环不负责 MCP 配置、密钥或落盘。

## 真实来源与缺失信息

包源查询区分“确不存在”“查询失败”“找到”；网络不可达不能说成包不存在。当前元数据走 npmmirror，缺 README 时尝试 jsDelivr；国内可用性是选源要求，但不是对网络永远可达的保证。抓取与探测共用安全网络出口及代理配置。

有说明文本才调用 main 角色模型提取启动配置、密钥字段与获取链接。提示约束只使用给定文本，未说明的留空；当前 README 按字符上限截取，不是精准章节抽取。输出无法解析时回落到 `npx -y <已确认真实包名>`；可解析时 command 与 args 分别补缺，缺 command 用 `npx`，缺有效 args 用上述包参数。这只是待探测的基线，不能视为正确启动方式已获证明。

无 README、来源不足或查询失败时提供明确原因，允许改用预设、完整命令或 URL。密钥地址未提供则使用真实主页作查询入口，不编造链接。没有提取出秘密字段只表示“未识别到要求”，不保证免鉴权；当前面板会显示“无需密钥”，这是文案与证据强度的差异。

URL/命令直接候选的秘密字段为空，当前没有鉴权失败后自动补出任意 header/env 字段的通用流程；旧设计要求的“需要时再手动补密钥”不能算作完全实现。基于真实文本的约束目前仍部分依靠模型遵循提示，不是对所有提取字段逐项进行来源证明。

## 探测前确认、秘密与提交

```text
候选 → 展示非预设 stdio 命令／录入秘密 → Enter 确认
     → 带秘密临时连接并列工具 → 成功后更新编辑器暂存
     → 用户完成编辑 → 持久化配置与秘密 → Host 换代
```

非预设 stdio 探测会实际启动本机命令，确认必须在探测前，不能放到保存前。当前候选面板展示将执行的命令，Enter 验证代表同意；预设不走该额外展示。这是接入阶段的执行确认，不替代运行工具时的共同安全管线。

用户输入秘密值不传给提取模型。字段可包含多个秘密，按字段逐一收集，模板可将裸值变成 `Bearer ...` 等投影；HTTP 注入 header，stdio 注入 env。临时 probe 使用独立的 60 秒默认超时，为首次启动下载留出时间，与常驻连接的 10 秒超时不同；成功或失败均释放临时连接，不转交给正式 hub。

探测成功证明当时可建链并发现工具，不证明所有工具权限、业务结果、安全性或后续可用性。失败留在候选面板给出原因并允许修改重试，不提交半成品。取消向探测/查询传递信号；模型经宿主 RPC 调用时，本地取消等待不等于远端模型推理已被取消。

成功探测只修改 `WorkingState`，用户完成编辑才落盘；普通配置保存 server 的 transport、command/args 或 URL、启用决策，秘密由设备 SecretStore 保存并按 server id 关联。加载时停用项与非法 id 不生成运行连接规格。

保存与删除遵循以下规则：

- 编辑器持有完整配置与秘密集合，保存时对所提供的 MCP 子表采用整体替换；省略某个 server id 表示删除。部分 patch 的默认 id 级合并会保留未提及的 server，不能用它代替编辑器完整保存，否则删除会失效。
- 编辑状态中的连接条目整体替换，避免切换 transport 后残留旧 command/url；启停只更新 `enabled`、保留连接字段。秘密字段补丁则合并到对应 server，保留未提及字段，不等于删除秘密。
- 删除 server 同时从编辑状态的配置与秘密集合移除对应 id，用户完成编辑后再持久化，避免遗留孤儿凭据。两处状态同步删除不代表配置文件与 SecretStore 具有跨存储原子事务。

配置保存与运行生效是两件事。当前保存后等待在途 turn，再请求核心 Host 排空关闭、连接换代并刷新；生效失败必须与已经保存区分，不能报告为已恢复运行。旧的会话内 `computeDiff` 与共享 hub 增量重连不是当前用户入口。

旧稿保留的 `tools.include/exclude` 配置形状不能当作过滤已生效：当前 `parseServerSpecs` 不把它带入规格，运行适配器映射全部已发现工具。按工具选择的意图仍有意义，但此迁移不补做该功能，也不把配置字段存在当成能力完成。
