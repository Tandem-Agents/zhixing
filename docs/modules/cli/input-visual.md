# 输入区视觉

本文承接[CLI 视觉设计语言](visual-language.md)，覆盖 REPL 与配置编辑器的 `input` / `add-model` 输入面板；候选面板、历史回显与底部信息行属于 REPL。补全触发、候选数据、材料采集和命令执行不在本文定义。

## 核心边界

正在编辑的内容必须一眼可识别；提交后的内容是历史，不再占用编辑容器。长输入通过换行呈现，不靠横向滚动隐藏内容；输入光标由输入布局决定，不随外部状态或模型输出跳动。

这不是把 shell 提示符加粗，而是为日常对话提供稳定的输入空间。只给当前编辑区域保留框体重量，避免长会话的历史反复堆框。

## REPL 各状态的形态

| 状态 | 视觉合同 |
|---|---|
| 空输入 | 圆角完整框，品牌色 `❯` 与弱化 placeholder；正文一行，不额外增加上下空白 |
| 编辑中 | placeholder 消失；光标跟随编辑位置，不能被提示文字挤动 |
| 多行 | 按内容换行扩展，续行对齐提示符之后；按可见列宽而非字符数布局 |
| 候选面板 | 输入框与候选框各自完整、顺序排列，不嵌套、不共用边框；普通选中态采用同源点阵纹理，删除准备态改用红底，不叠加纹理以免损坏可读性 |
| 已提交 | 移除编辑框，以灰底用户消息进入历史；不带 `❯`，前导留白、背景补齐行宽，长文本按宽度折行，并非强制压成一行 |
| 输入取消 | 未提交内容不作为用户消息写入历史；不能将此规则扩大成取消已执行运行时删除既有历史 |
| 普通模式底部 | 有信息行装配时，输入框下固定占一行；候选或 inline 编辑模式由自身提示区接管，不重复展示 |

历史灰底标识“谁说的”，候选纹理标识“选中了什么”，框体标识“在哪里编辑”，三者不可互相替代。历史消息不带 `❯`，既避免与当前输入混淆，也让用户复制时不夹带提示符。

## 当前布局与职责

REPL 的 `InputController` 组织输入布局及候选投影；`layoutInputBuffer` 计算正文和光标；`renderChrome` 画框，`renderSessionLines` 画候选面板。当前 REPL 输入与候选面板各自使用完整框体。

普通输入框调用 `renderChrome` 时使用 `bodyPadding: false`、`indent: 1`；空输入因此为顶边、正文、底边三行。输入是持续操作的空间，紧凑布局减少光标周围空白；Welcome 等展示容器则可用上下留白拉开阅读层次。当前 `frameWidth = max(40, getColumns())`，低于 40 列的终端尚未完整适配。正文预算和光标位置从同一布局推导，框内光标由反白单元绘制，屏幕控制层在该模式隐藏硬件光标，避免输出与输入争夺光标。

候选面板与配置列表共用 `highlightSelectedRow`，两处以上连续空格及尾部补齐采用弱化 `░`，单空格保留。原语接收不含框线的行，框体负责外边界；共用原语避免两处选中样式分别演变。

输入提交后的回显使用已确定的提交文本折行、填充灰底；这只定义展示，不代替原始材料、命令解析或对话持久化合同。

配置编辑器的 `input` / `add-model` 由独立面板渲染：圆角框承载说明，实际输入仍是框外的 `> ` 行，页脚绘制后将硬件光标移回输入末尾；敏感字段掩码显示。它尚未实现共同设计要求中的独立输入框与受控换行布局，不能用 REPL 的实现证明其已落实；配置保存也不套用对话历史回显规则。

## 底部信息行

内容来源与渲染分离：`BottomInfoModel` 按具名块保存左右两区，来源通过 `set` 更新或清除自己的块，渲染只消费 `snapshot()`，不读取输入 buffer 等来源内部状态。块顺序由注册表声明决定，不由写入先后决定。

- 当前输入来源在非空时提供 `esc 清空`，为空时清除；来源负责自身块的完整生命周期，停止时不得留下过期提示。
- 内容更新必须早于触发重绘；当前 `syncBroker()` 先同步信息行再调用 `broker.updateInput()`，启动／恢复时也同步，避免落后一帧。
- 普通模式保持一行高度，空内容也占位；候选面板存在时不追加该行。左右区独立对齐，空间不足时右区优先、左区截短，遵守可见列宽。
- 不为尚不存在的内容来源预建订阅、TTL 或通用优先级框架。
