# 输入补全架构

输入补全帮助用户发现命令、填写参数和引用文件，减少记忆与重复输入；它是输入辅助，不拥有业务状态，也不替用户决定执行权限。[命令系统](command-system.md)负责声明与分派，本文负责从草稿到候选接受的交互链。

## 总体结构与状态归属

```text
输入按键 / 粘贴 → InputController → InputBuffer（草稿与光标）
                                      ↓ 输入上下文
                                TypeaheadBroker
                                      ↓ 按优先级选择
                 ArgumentProvider / CommandProvider / FileProvider
                                      ↓ 候选与接受结果
                           InputController + 输入区渲染
                                      ↓
                         回填草稿，或提交给命令系统 / 对话入口
```

- `InputBuffer` 是输入草稿的唯一来源；Broker 持有候选、选中项、查询状态、提示及候选操作准备态。补全会话不是对话会话，取消 Broker 会话本身不修改草稿；CLI 的 Esc 清理策略由输入控制器负责。
- `core/typeahead` 提供不依赖终端的匹配、候选、排序和分派机制；CLI 装配真实来源并负责按键、显示和输入生命周期。当前生产路径由 `InputController` 直接消费 Broker，不经过旧的独立 `TypeaheadRenderer` 包装层。
- 候选生成由 Provider 负责，显示层不重新决定候选顺序；接受结果描述替换范围、光标和是否提交，不在 Broker 内执行删除、切换会话等业务。
- 与确认交互共用必要的终端原语，不继承一次性选择组件：补全是持续、非阻塞的派生态，确认是等待决定的独立交互，两者不可混成一个生命周期。

## 触发与候选来源

触发检测以光标前的 token 为准，使用 Unicode 字符与字符位置，不按 UTF-8 字节切割。默认要求行首或空白边界；输入材料占位符也是词边界。保留边界是为避免把普通路径、自然语言中的符号误当命令，不为紧贴中文的触发另建消歧义系统。Slash Provider 在 bash 模式不触发。

当前 REPL 注册三类 Provider，数字越小优先级越高；Broker 使用第一个匹配者，不混合多个来源的结果：

| 来源 | 优先级 | 当前职责 |
|---|---|---|
| ArgumentProvider | 90 | 根据命令参数位置查询静态、异步枚举或布尔候选，生成渐进提示；text/path/number 当前只提示，不生成参数下拉候选 |
| CommandProvider | 100 | `/` 命令发现，读取注册表的可见集合，模糊匹配与使用频度排序 |
| FileProvider | 200 | `@file:path` 与非空 `@path` 的目录枚举和路径前缀补全；裸 `@` 不触发，`@tool:` 让出但不代表已有工具补全 |

文件补全的相对根由 REPL 动态读取宿主解析后的 workspace，未取得时回退 cwd；Provider 不自行选择工作区。支持相对路径、`..`、`~/` 和可解析的绝对路径，显式 `@file:` 才展示点开头文件。单次最多返回 100 项，目录优先、名称排序；目录接受后继续浏览，文件接受后加空格，均不立即提交。

**设备与安全边界：**目录枚举实际使用 CLI 进程的本地文件系统，不是远端文件浏览服务。`isOutsideWorkspace` 是路径范围标记，不是授权或沙箱；候选回填的引用文本也不证明文件内容已读取或已交给模型。

## 查询、排序与稳定性

每次输入更新先取消旧查询，再通过递增的查询标识和 AbortSignal 丢弃过期结果。同步结果直接更新；异步首次触发显示加载态，同一触发下继续输入暂留上一批候选，避免列表闪烁。新结果落地后，非空列表默认选中第一项；上下导航到边界停止，不循环跳转。

Provider 查询、派生提示及订阅者异常由 Broker 隔离，错误可交给错误回调与事件接收器，不应击穿输入循环。默认查询超时为 3 秒，当前实现发出 abort 并拒收结果，**不是强制终止底层 I/O，也不保证超时立即清除加载态**；没有旧计划所述的连续三次错误自动禁用机制。

命令非空查询使用 Fuse 多字段检索，随后依次优先精确名称、精确别名、名称前缀、别名前缀，再比较模糊分数与使用分数；前缀匹配优先短名称。空查询先显示最多五项常用命令，再按类别与名称排列其余项，不重复列出常用项。

使用分数的设计采用“先按时间衰减，再加一并封顶”的有界频度：上限 32、半衰期七天，时钟回拨不反向放大分数。其价值是限制历史高频操作的长期支配，而非累计次数排行。**当前接入存在缺口：REPL 以 `rootDir: null` 装配 UsageTracker，且生产命令接受、执行链未调用 `recordUsage`，因此不能宣称常用排序已经随实际使用生效，更不能宣称跨重启持久化。**排序与计分机制存在不等于生产链已闭合；这不取消原来的常用排序目标。输入历史和对话持久化不是该分数的存储职责。

Ghost text 只由无歧义的命令名称或别名前缀生成，不用模糊结果猜测尾文；参数提示由 `ArgSchema` 随当前位置派生，避免另维护一份字符串参数表。

### 选型依据

| 选择 | 相比另一方案的理由 |
|---|---|
| Fuse 多字段匹配，而非只做 prefix | 允许用户记不准名称时仍能发现命令；纯 JS 不引入 native 构建依赖 |
| 名称、别名优先于描述 | 命令应自解释，描述中的偶然命中不能压过明确名称；当前权重为名称 4、别名 3、名称分词 2、描述 0.3 |
| 模糊候选与前缀 ghost 分开 | 模糊匹配适合“找选项”，不适合把不确定文本显示成用户即将输入的后缀 |
| 有界、衰减的使用分数，而非累计次数 | 曾经高频的命令不应永久霸榜，新习惯应能改变排序；生产接入缺口见上文 |
| Provider/Broker 与终端分离，而非把补全交给整套 UI 框架 | 候选规则可独立测试和复用，终端仍统一管理输入、模态和屏幕；不要求重写成熟的检索算法 |

原始交互调研见 [OpenClaw](../../../research/source-analysis/openclaw/slash-command-completion.md)、[Hermes](../../../research/source-analysis/hermes-agent/slash-command-completion.md)和 [Claude Code](../../../research/source-analysis/claude-code/slash-command-completion.md)，其中竞品能力描述对应各自调研版本，不代表当前版本评测。

## 接受、提交与候选操作

“默认选中第一项”的目的，是不要求用户先按方向键激活列表，**不是所有 Enter 都执行**。

| 输入状态 | 当前行为 |
|---|---|
| 普通选择面板有候选 | Enter 接受选中项，依据 `execute` 回填或提交 |
| 命令含必填参数 | 接受命令名只回填，后续参数候选决定是否继续填写 |
| 没有候选 | Enter 提交草稿，命令由统一 dispatcher 处理，不直接当模型指令兜底 |
| 管理面板（如信任规则列表） | Enter 不接受、不提交，包括加载与空列表状态；使用声明的管理动作 |
| 有 ghost text | Tab 只接受 ghost 并刷新候选；无 ghost 时 Tab 接受选中候选，是否提交仍依其接受结果 |
| Esc | 有候选时优先清理当前 token；清理无实际变化或无候选时清空草稿，避免空参数面板无法退出 |

必填参数的有效需求仍是“未填不能误执行”。当前补全提供逐步填写引导，dispatcher 并未通用执行全部 `ArgSchema` 校验；手打、不经候选的输入仍由具体 handler 校验，不能把结构化参数类型等同于统一运行时验证。

候选操作使用 `InlineActionSupport` 声明 delete/rename/create；Provider 只声明能力与提供候选，不持有物理删除方法。Broker 独占 `deletePending`，CLI 将连续两次 Ctrl+D 解释为确认删除；切换候选或修改输入应解除准备态。Ctrl+R 改名、Ctrl+N 新建只在对应能力存在时生效。

接受必须先改草稿，再让 Broker 观察新输入；`accept` 本身不发布状态变化。立即提交时只在提交清空草稿后同步一次，不能先绘制补全后的命令再立刻清空，否则会产生旧草稿帧或面板闪烁。

改名与新建通过 `inline-edit-request` 返回 REPL，由主循环挂起输入、运行 `InlineTextPromptRegion`、等待业务完成再恢复与刷新，不在候选回调中启动无人等待的并行编辑。删除由 `candidate-delete-controller` 调用对话控制器或工作场景、管理面 facade，再进入宿主；删除当前对话后的新建与指针衔接属于对话职责，不下沉到通用 Broker。

## 终端生命周期与粘贴

输入控制器持有草稿、keypress 订阅与终端资源。挂起时保存草稿/光标，摘除自己的输入订阅和鼠标租约，让模态交互接管；保留底层 stdin ownership 与 raw-mode 租约，恢复时重新订阅、还原输入并查询。停止时完整释放。不能照搬“每次挂起都卸载全部 raw-mode”或让两个面板同时处理按键。

渲染输出经当前输入区与屏幕控制器统一绘制；补全消失后不得留残行，光标须回到输入位置。滚动列表预留稳定的上下指示位置，避免到边界时高度跳动。具体布局与屏幕限制分别见[输入区视觉](input-visual.md)和[屏幕渲染](screen-rendering.md)，不在此复制视觉合同。

右键粘贴默认在支持的 TTY 输入态开启：终端鼠标租约只启用 SGR 编码及 press/release，不收 motion/hover；挂起释放、退出兜底关闭。按键解析器重组分片鼠标序列，即使没有鼠标处理器也不得让坐标串进入草稿。剪贴板内容进入与键盘粘贴相同的处理链；异步读取期间到来的 Enter 等待粘贴完成后处理，避免先提交后插入。

鼠标上报是终端级开关，部分终端需按 Shift 才能原生拖选或打开右键菜单；不能承诺只接管右键而完全不影响左键。自动化序列测试不等于真实终端鼠标兼容性验证。长粘贴的折叠、原文提交与引用保活见[文本粘贴](text-paste.md)，材料存储不由本文定义。

## 范围与维护依据

本模块提供 `/` 与 `@` 的输入范围以及默认开启、`ZHIXING_INPUT_TYPEAHEAD=legacy` 回退输入采集的约定；关闭补全不另建命令执行路径。工具/MCP/Agent 专用补全、文件命令目录、Plugin SDK 和 Web 渲染未在当前 REPL 接入。

直接实现依据：[Broker](../../../packages/core/src/typeahead/broker.ts)、[Providers](../../../packages/core/src/typeahead/providers)、[输入控制器](../../../packages/cli/src/typeahead-input.ts)、[REPL 装配](../../../packages/cli/src/repl.ts)。维护时重点保护草稿/候选分离、迟到结果拒收、接受与提交区分、管理面板空态、候选操作终态、挂起恢复和鼠标租约；不以纯候选快照代替真实输入消费链。
