# Markdown 流式渲染

正文转换必须保留内容、来源与顺序，流式、工具插入、翻阅和 resize 不重复、不丢失。屏幕职责见[屏幕渲染](screen-rendering.md)，视觉规则见[视觉语言](visual-language.md)。

## 生产链

`ConversationController / 运行投影 → N BodyProjection → 本实例有界显示存储 → U BodyView`。

N 使用 marked 解析 Markdown，将文本和样式投影为有稳定源区间的节点；U 负责布局、代码高亮、滚动与选区。N 不生成任意可执行 UI，U 不访问会话权威。原始源文本与显示元数据分开，修改样式不会重写业务消息。

解析器的临时 token 边界不是已提交事实。投影区分可稳定前缀与待定语法，使用 append/amend 及修订身份更新显示；围栏、表格、引用链接等跨片段语义保留必要上下文。单次解析、节点、载荷和存储均有界，不靠无限累积整段解决边界变化。

## 呈现与生命周期

- 段落、标题、引用、列表、表格和围栏代码保持结构；未闭合语法在流式期安全呈现，最终内容按确定结构完成。代码高亮由 U 的随包 parser 资产完成，不再使用旧 cli-highlight ANSI 块渲染器。
- 思考、正文、工具、子任务、诊断和终态分别拥有稳定身份。正文起首标记、工具状态色及 M1 动态反馈按既有视觉合同，不把显示节点数量当作消息数量。
- 源节点更新复用原生组件；显示宽度变化重新布局，阅读锚点与选区仍指向源文本。历史和当前流不依赖不可回写的终端回卷，不存在旧活动段句柄在 resize 后失效的路径。
- N 在确认载荷读取/接纳后推进消费；中间显示合并有界，末批必须发布，不能因合并省略最终文本。显示缓存、载荷与原始源文本的占用统一纳入本实例预算。
- 历史按权威身份分页读取；超出显示预算时优先释放可重读片段。不可重读内容无法接纳时明确暂停，不能后台清空正文或把本地缓存当成第二事实源。
- 32KiB源片与224KiB传输批次不是阅读页边界。U维护独立的连续有界窗口（1MiB/256片/8192节点），原生文本只挂载可见区；不足一屏时继续有限预读。阅读位置与选区按源坐标保护。
- 冷历史展示缓存只持有可重读地址与校验摘要，有限热区逐出后从权威字节页重建；实时未持久的工具 presentation 不假装可重读。N复用有界 Markdown 解析检查点，缺索引时分批恢复并可取消；不得把恢复未完成显示成最早历史。
- 非交互文本路径直接呈现文本，不建立 ANSI 屏幕或旧 render/strip 活动段状态机。
