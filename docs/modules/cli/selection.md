# CLI 选择模块架构

选择模块承载少量选项的短决策：用户看清行动与后果后选择，模块只返回结构化结果，调用方执行业务。它属于 CLI TUI 交互基础设施，不属于权限、命令或任务推进领域，也不是候选浏览器或复杂表单。

## 职责与取舍

- 调用方提供标题、说明、选项、风险文案与结果解释；选择模块统一导航、补充输入、二次确认、详情查看、取消和资源释放，不调用业务 RPC、不写配置或业务状态。
- 每次 1～5 个选项，通常 2～3 个。候选过多应先由业务收敛，或使用专用列表；选择页全部选项一次可见，不分页、不窗口化。详情页允许滚动说明，但不借此扩展选项数量。
- 通用能力因真实调用需求演进，协议不出现 Rubric、权限或 `/stop` 专属字段。需要编辑或多步决策时，由调用方承接结果并组织后续步骤，不在基础模块塞入业务流程。
- 通用选择可以吸收早期权限面板的纯状态机、输入租约和内联呈现思想，但不继承权限判定、审批队列或旧面板无高度预算的渲染方式。依赖方向是业务适配通用交互，不能反向依赖业务。
- 同一终端同一时刻只能有一个活跃选择交互；排队由调用方或上层协调，不由选择模块建立业务队列。当前实现的保障范围见“现状与设计差异”。
- 当前供本机系统功能使用，没有向 Agent 开放通用选择工具。未来若开放，需要独立的用户决策业务协议及宿主可见性、权限、超时约束，不能让模型直接操纵 TUI；本文不预建该能力。

## 请求与结果合同

公共入口为 `SelectionService.choose(request, { signal? })`。请求包含标题、可选正文、选项、初始选项与提示文案；请求和选项均可提供 `details`，选项详情优先于请求详情。

| 对象 | 合同 |
|---|---|
| 选项 | `value` 在请求内唯一；`label` 非空；`description` 解释后果；`tone` 只影响视觉，不触发行为 |
| 禁用项 | 可以显示原因，但不能提交、绑定快捷键或声明输入／二次确认；导航跳过禁用项，不能全部禁用 |
| 初始选项 | 默认第一个可用项；显式 `initialValue` 必须存在且可用，业务自行决定安全的默认选择 |
| 快捷键 | 单个可打印、非空白 ASCII 字符，大小写归一后唯一；不是 Enter、方向键或组合键的别名 |
| 补充输入 | `input.placeholder` 非空；`allowEmpty` 默认 false，空输入不提交；显式允许时返回 `input: ""` |
| 二次确认 | `confirm.title` 非空，正文与确认／返回文案可选；确认后才提交。`input` 与 `confirm` 是互斥的选项类型，不定义“输入后再确认”的复合流程 |
| 详情 | 正文数组非空，提供标题时标题非空；只供阅读，不产生提交或审批效果 |
| 成功 | `selected` 原样返回业务 `value`；输入选项必带 `input`，非输入选项不带该字段 |
| 取消 | `cancelled` 保留 `escape`、`ctrl-c`、`ctrl-d`、`aborted` 原因；取消不等于业务拒绝，更不执行默认动作 |

请求标题也必须非空。无效请求抛 `SelectionValidationError`；同一服务实例正忙抛 `SelectionBusyError`；无交互输入输出或无法容纳面板抛 `SelectionUnavailableError`。三者都不是用户取消，调用方应分别处理编程错误、竞争和不可用，不能静默选择默认项。

## 状态与交互

状态只有选择、输入、二次确认、详情四层，由纯 reducer 管理；终端按键先经统一 `keymap` 翻译，再进入 reducer。inline 与 legacy 共用这条链，避免同一按键在不同终端呈现下改变含义。

| 当前层 | 行为 |
|---|---|
| 选择 | ↑／↓ 移动，边界不循环；Enter 激活当前项；快捷键选中并激活对应项；→ 打开可用详情；Esc 取消 |
| 输入 | 字符进入缓冲，Backspace 删除末尾字符，Enter 按空值规则提交，Esc 返回选择层并清空输入；此时不触发选项快捷键 |
| 二次确认 | Enter 提交，Esc 返回选择层，不直接取消整个交互 |
| 详情 | ↑／↓ 按正文行滚动，←／Enter／Esc 返回选择层；查看详情不激活选项 |

各层均可由 Ctrl+C、Ctrl+D 或外部 Abort 结束。输入层同时接收普通按键与粘贴通道，当前粘贴忽略换行；其他层不把粘贴内容当作选项操作。终端可能把快速字符流批处理成 paste，不能简单把 paste 全部丢弃，否则会丢失实际输入。

## 呈现与屏幕预算

inline 面板嵌入当前底部操作区，不另开全屏或清掉对话回卷；屏幕的通用能力边界由[屏幕渲染文档](screen-rendering.md)负责。

- 紧凑分隔线与标题，关键说明优先与标题同行；选项以 label、hotkey、description 对齐，每项一行、项间不留空行，选项与弱化 hint 之间留一行。
- 选中项用指示符和 label 加亮，不整行反白；危险色仅辅助，后果必须由文案说明。`tone: danger` 不自动要求二次确认，调用方须显式声明 `confirm`。
- 每行显示宽度不超过 `columns - 1`，按显示宽度处理中文与 ANSI，不能依赖终端自动折行兜底。当前列数低于 24 时不可用。
- 高度预算扣除 status 和保留的对话区域。选择页优先保住标题、全部选项和 hint，正文可以折叠、长描述可以裁剪，不能通过隐藏选项通过预算检查。必要内容仍放不下时应在进入交互前拒绝，而非显示半截面板。
- 详情页在自己的预算内显示正文片段和位置提示；调用方应把决策必需的后果放在短说明中，不能依靠被裁剪或折叠的长正文承载唯一风险提示。

## 当前实现与生命周期

实现位于 [TUI selection](../../../packages/cli/src/tui/selection/)。

| 责任 | 实现 |
|---|---|
| 请求、结果及校验 | `types.ts`；服务先校验，再判断实例忙碌与终端交互能力 |
| 纯状态转换与按键翻译 | `state.ts`、`keymap.ts`；不持业务语义、I/O 或 ANSI |
| 布局与预算 | `render.ts`；返回完整行或不可用原因 |
| 服务与呈现端口 | `selection-service.ts`、`presenter.ts`；服务选择呈现方式并在 finally 清除实例 active 状态 |
| 内联呈现 | `inline-selection-region.ts`；接入 `ScreenController`，接管输入、处理 Abort 并更新面板 |
| 无 Screen 呈现 | `legacy-selection-presenter.ts`；向 stdout 逐次输出面板，沿相同 reducer、keymap 与 render 执行选择，不是另一套选择语义 |

有 Screen 时创建 inline region，先计算初始面板预算，再调用可选 `beforeShow`、运行交互，finally 调用 `afterShow`。无 Screen 时使用 legacy；完全非交互时拒绝。当前不是“inline 失败后自动切 legacy”，两条路径都可能因屏幕预算拒绝请求。

presenter 通过共享 stdin ownership 与 raw-mode lease 接管输入。正常选择、取消和 Abort 结束时移除按键与 Abort listener、释放 batcher 和租约；inline 清空自身行并请求重绘，宿主恢复原输入区。租约不是业务互斥锁：暂停原输入时应保留其底层租约，仅暂停订阅，避免 Windows ConPTY 在快速 raw-mode 翻转后不再送达按键。

资源合同要求所有退出及异常路径都释放已取得资源并恢复输入。当前 inline 的初始化和按键重绘没有像 legacy 一样统一捕获异常并清理；`beforeShow` 也在 `afterShow` 的 try/finally 外。不能据正常退出链声明任意异常均已闭合。面板尺寸目前取创建时快照，不能宣称已支持选择过程中随 resize 重新计算预算。

## 生产接入与设计差异

- **停止服务：** `/stop` 读取服务状态，按是否有其他接入面、运行或排队工作形成请求；有工作时提供等待，存在可取消工作时再提供取消工作并停止。选择服务只返回值，停止动作由命令侧的产品调用链完成。原设计要求“取消工作并停止”显式二次确认，当前选项只有 danger 视觉、未声明 `confirm`，这项差异尚未闭合。
- **任务推进：** CLI 把推进契约映射为通用选择请求，再翻译确认、取消或后续编辑结果。详情与按键升级属于通用交互；Rubric 规则、控制事件和业务状态不进入本模块。
- **工作场景创建：** 辅助创建流程经 `confirm(proposal)` 调用选择服务；创建操作与结果仍由工作场景业务负责。
- **权限确认尚未统一接入：** 当前 `TerminalConfirmationRenderer` 仍使用 `security/SelectOperationRegion`，不是 `SelectionService` 适配器。有效设计目标仍是权限侧只做请求／结果映射，通用选择 UI 不归 security 所有；不能将该目标写成已完成，也不能直接把权限的取消语义套给通用选择。
- **互斥不是进程级保证：** REPL 为一般选择与工作场景辅助创建分别装配服务，`active` 仅约束单个实例；工作场景实例不带一般选择的 suspend/resume hooks。宿主必须在受控输入流程中接入，不能把多实例当成可并行占用终端的授权。
- **呈现能力应等价：** 两条 presenter 共用协议和四层状态机；服务的 `beforeShow/afterShow` 目前只用于 inline，legacy 的输入交接由调用方负责。类型中的 input/confirm 互斥也未由运行时 validator 再次检查，不能宣称任意非类型化输入均已被拒绝。

## 维护判据

改变本模块时，应直接验证请求拒绝、输入与二次确认、详情返回、快捷键隔离、两种呈现下的取消与 Abort，以及短／窄终端预算和结束后真实输入恢复。共享 reducer 的单测不能代替宿主输入交接验证，listener 数量正常也不能证明 ConPTY 仍在送达按键。

架构成立的标准是业务只映射请求与消费结果、通用层无业务反向依赖、没有第二套通用交互状态机；产品成立的标准是用户能看清全部行动及后果，完成或取消后继续正常输入。上述已列出的实现差异不因文档迁移而视为解决。
