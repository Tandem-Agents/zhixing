# CLI 屏幕渲染与能力边界

当前交互终端由 OpenTUI/Solid 维护一个可重排的应用屏幕。总体职责见[CLI 架构](architecture.md)，进程与恢复协议见[迁移设计](../../workbench/terminal-architecture-migration.md)。

## 一个屏幕与一套输入所有权

主对话、配置、候选、权限和通用选择在同一根内切页。正文占可滚动视口，输入与左右信息行保持固定；业务代码不直接写屏或改变终端模式。旧主屏 DECSTBM、ScreenController、独立配置 alt-screen 和权限专用按键流已经退役。

主页面头部显示当前对话、工作目录及 provider/model，由 N 的公共环境投影提供；配置生效、重连与切换后刷新，更新不清空草稿。小高度优先保留正文和编辑空间，恢复尺寸后重新显示环境信息。

主会话欢迎框在同一阅读视口内，随历史卷走，不占固定顶栏；滚动轨道预留最右1列，正文留白由视口内部独立承担。

备用屏幕负责隔离应用与 shell；应用保存有界显示内容、页面、草稿、阅读锚点和选区，按新尺寸重新布局。不能把备用屏幕等同于没有历史，也不能把显示投影当成持久化业务记录。

| 场景 | 责任与可见结果 |
|---|---|
| 启动 | R 取得必要模式基线，结构性进入/退出受同一恢复责任约束；S 确认准入后授予 U 输入和渲染权 |
| 流式与通知 | 稳定源节点增量维护；通知、过程状态和正文有各自身份，不通过重写尾行覆盖彼此 |
| 阅读与 resize | 按源位置保留阅读锚点与精确选区，已保留历史按新宽度重排；滚轮只消费一次，点击正文不抢走编辑焦点 |
| 切页 | 暂停原输入场景，展示当前页面；返回时恢复适用草稿、光标、候选与阅读位置；迟到结果不能回写已结束页面 |
| 小窗口 | 保留编辑/决策状态；必要内容放不下时暂停提交并提示放大，仍允许取消，不裁掉关键操作假装可用 |
| 容量不足 | 按既定预算回收可重读内容；不能回收时显示明确暂停与恢复动作，不偷偷丢不可重读正文 |
| 退出 | 先收束本实例所有写者和 helper，原 R 最后恢复已拥有模式，S 等实际退出后返回 shell；不关闭独立 Host、不清除用户业务数据 |

## 文字与鼠标

宽字符、组合字素、换行和光标位置由原生文本布局与源坐标共同处理，不用字符串长度代替显示列数。界面只显示已提交给应用的草稿；IME 的组合文字和候选窗仍由系统负责，硬件光标对应真实编辑位置。

优先使用宿主的粘贴输入；若鼠标模式把右键交给应用，则通过 N 的受管剪贴板端口进入同一草稿/材料通路，不以关闭滚轮换取粘贴。应用选区与明确复制操作共存；跨节点和 resize 保留原始选择文本，复制不混入框线或提示符。宿主原生选择的修饰键行为与应用选区是不同机制，不据一个宿主推断所有环境。

信息行由公共容器统一分配左右栏、外侧留白及窄屏预算；场景只提供内容和有效期，不能自行叠加缩进。详细合同见[输入视觉](input-visual.md)。

## 验证与边界

优先通过真实原生组件、隔离 ConPTY、安装后的默认入口核对编辑、流式、滚动、重排、切页及退出后的 shell 行为。有效输出回执证明本次动作的帧写入完成，不等于物理显示器像素验证；普通 echo 也不能替代方向键历史验证。

模式恢复依据真实入场基线，未知不补写默认值；原 R 是最后恢复写者。自有进程身份、实际退出和有限排空共同证明关闭，不能用“已发送终止”代替。其他平台保留相同功能合同与对应实现，实测覆盖现有物理环境。

关闭先结束本面的业务消息接纳与投递，保留 `close` / `exit` 及其回执；取消显示投递不表示领域动作撤销或完成。已发生的协议、持久化、实际退出或恢复失败仍须保留。启动被取消后不进入配置补救或加载新的页面后端；已开始的资源工作仍由原 owner 收束。固定制品的只读预校验与首次使用共用一次验证，准备阶段的读句柄也纳入关闭责任。

S/N 共用最多8秒的绝对关闭截止，完成即退出；发起侧经现有通道传递，接收侧只收紧，不续期。最后500ms属于既有资源结算与恢复，日志另留150ms退出余量；锁、文件及 helper 操作受所属 owner 剩余期限约束。S 日志 owner 排空与 N/U 关闭并行，等日志 owner 结束后才裁决其助手是否残留，不把排空中的文件助手误判为泄漏。到期或写入未确认仍保留失败和实际退出证明，不吞错误冒充正常关闭。

启动日志区分 U 首帧与首次真正可发送的已完成帧；后者由 N 完成必要准备后投影就绪、U 渲染完成再回执。Host 首屏描述使用认证后的轻量 `server.info` 投影，完整状态查询仍保留原职责；平台身份/密钥保护通过共同适配端口注入，不把 UI 依赖引入内核。

R 准入及固定 UI 制品校验后，U 的受管悬挂创建可与实例容量和目录准备并行；Windows 初始线程保持悬挂，POSIX 只运行固定执行门。实例隔离环境保持，容量、创建意图和真实身份耐久绑定全部完成才放行 U；未放行的创建直接取消并等待真实退出，不等待不存在的业务监听者。准备并行不提前授予输入、渲染或文件写入权。
