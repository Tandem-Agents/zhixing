# CLI 屏幕渲染与能力边界

本文说明屏幕如何组织、为何这样选择，以及终端约束与当前实现边界。视觉语言见[视觉设计语言](visual-language.md)，输入形态见[输入区视觉](input-visual.md)；屏幕回卷不是[对话持久化](../conversation/persistence.md)。

## 核心取舍

主 REPL 使用主缓冲区与 DECSTBM 滚动区：对话输出在上方滚动，状态与输入区固定在底部，已滚出的内容交给终端原生回卷。这样保留长对话回看及终端复制体验，不必自建完整历史画面的滚动引擎；代价是应用不能直接接管已进入终端回卷的画面。

**缓冲区选择与渲染方式是两个独立维度。** 主缓冲区／备用屏幕决定终端如何保存画面；应用保留哪些内容、布局与交互状态，决定能重画什么。命令式 ANSI 输出不等于没有状态，也不意味着无法实现应用内滚动。

知行保留输入、配置面板、状态条和活动输出段等局部状态，但没有完整历史画面的可重建模型。不能把这一限制写成“全项目没有 UI 状态”，也不能把持久化对话数据当成已经实现的历史画面重排能力。

## 两种屏幕与职责

| 使用面 | 组织方式 | 责任 |
|---|---|---|
| 主 REPL | 主缓冲区：终端回卷 → DECSTBM 输出区 → 固定状态／输入区 | `ScreenController` 协调写入与生命周期；`ScrollRegion` 管滚动区、活动段和固定区布局 |
| 独占面板 | 备用屏幕（alt-screen），退出后返回主画面 | 配置编辑器等持有面板状态并重绘；使用 `Renderer` 管理 ANSI 输出和进退 |

备用屏幕没有主屏那样的原生历史回卷，但不禁止应用自己保存内容、按偏移重绘。滚动能力必须同时具备内容／布局模型与输入处理，不能只切换缓冲区就获得。

当前配置编辑器和技能管理器都有自己的渲染路径。旧技能编辑器已不在生产代码中；`composeViewport` 与 `writeFrame` 原语仍存在，但当前没有生产调用，不能据此宣称面板已具备统一视口或滚动能力。`composeViewport` 实际仅截断、填充并可提示折叠，未消费 `scrollOffset`。

## 当前生命周期与可见结果

- **首次接管：** `ScreenController` 在输入首次 attach 前缓冲输出；首次 attach 使用 `2J → 3J → 光标归顶` 清理视口及回卷，再建立滚动区与固定区。这会清掉启动前 shell 的可见输出，不等于删除 shell 命令历史。
- **局部更新：** 状态／输入区局部重画；活动段支持 replace／commit，不需要重画全部历史。已提交至终端回卷的内容没有通用的读取、修改或搬回接口。
- **独占切换：** `suspend/resume` 切入／退出备用屏幕，暂停主输出区写入；恢复时重新确认滚动区、固定区和光标。调用方须在 suspend 前结束活动段，不能让流式段与独占面板并发；`ScreenController` 拒绝嵌套 suspend。这不是任意活动段的透明暂停／恢复机制。自管面板使用 `Renderer` 管理进退；两条路径不能被误写成同一套清屏动作。切换不应以清空主画面来为面板腾位置。
- **窗口缩放：** REPL 在 resize 稳定后调用 `rebuildAfterResize`，清理视口及回卷，按新尺寸重建固定区、欢迎内容和提示；不是把完整旧对话画面按新宽度重排。已存对话数据不由这条清屏路径删除，视觉历史消失与对话数据丢失必须区分。缩放后未结束的流式输出仍应连续，但当前重建会使活动段句柄失效，具体差异见 [Markdown 生命周期](markdown-rendering.md#可见内容与生命周期)。
- **退出：** 已接管时撤销滚动区、清视口并恢复光标，不清剩余回卷；从未接管时不清 shell。退出并非完整还原启动前的 shell 画面，期间已被首次接管或缩放清掉的回卷不会因此恢复。

## 滚动区与活动段

固定输入／状态区不随输出滚走，长对话可回看，是原设计的有效体验目标。旧 tailBuffer 全帧重画把逻辑行数当作物理高度，超宽内容发生终端自动换行时会重复推送屏幕顶行。当前以 DECSTBM 隔开输出与固定区，保留局部活动段而非反复重画已确定历史；这消除了旧全帧模型，但正确性仍依赖行宽合同和终端行为，并非天然无风险。

`ScreenController` 负责写入队列、输入／状态接入与切屏生命周期；`ScrollRegion` 聚合区域几何、光标尾位置、活动段和已滚出行数。固定区高度变化会影响段位置及滚动计数，这些强关联状态由同一责任体维护，避免多处各自推算。渲染器的生产接入见 [Markdown 流式渲染](markdown-rendering.md)。

| 操作 | 核心语义 |
|---|---|
| 独立行／追加输出 | 从记录的内容尾部续写；独立行必要时先换行，不强行从输出区底部起写 |
| begin／replace | 同时只有一个活动段；begin 保证新行起手，replace 定位段的可见范围，清除旧范围及将覆盖的扩展范围，再绘新内容 |
| partial commit | 内容超过可用区域时，滚动先消耗段上方历史，再消耗段自身；记录已滚出的段行数，后续替换跳过它们，不能重新绘制回卷前缀 |
| commit／close | commit 写最终内容后释放段，close 只结束段生命周期；不等于立即把全部内容送进回卷或保存到磁盘 |
| 固定区高度变化 | 输入／状态增减触发重新划区；只滚动必要行，清理旧固定区残影，恢复内容尾位置；高度不变只重画固定区 |

可用空间从段的实际起始行计算，不能直接取整个滚动区高度。区域内滚动要同步段位置与已固化行数；固定区使用绝对定位逐行绘制，不靠尾换行推进，避免意外整屏滚动。写操作经队列串行化，不能在一次布局变更中交错其他输出。

**活动段的边界：**

- 活动段之后直接插入通知，下次段增长可能覆盖该通知；清除扩展范围只能避免残留字符，不能保证通知保留。重要通知应由调用方先结束活动输出再发出，不把终端回卷当作耐久消息通道。
- 后续替换的总行数不得少于已滚出的段行数；即使行数足够，回卷前缀也无法重新着色。长代码块可能出现早期暗色、后期高亮的分段效果；“可替换段”只对仍可控制的部分成立。

### 行宽与能力检测

| 手段 | 适用边界 |
|---|---|
| `wrapAnsiLine` | 含 ANSI 内容折行，保留样式续接与续行缩进；用于需要完整显示的正文 |
| `wrapToWidth` | 纯文本折行，不应用于含 ANSI 的字符串 |
| `clampLine` | 截断并省略，只适合允许省略的提示，不能替代正文折行 |

行宽预算须计入缩进、中文可见宽度及 ANSI 零宽序列；分段追加还须考虑已有尾列。宽度合同是调用方责任，不应把行数追踪描述成对任意输入或任意终端都精确。

`detectTerminalCapability` 只检查 TTY、TERM、Windows build 与尺寸等静态条件，并标记 tmux；不主动验证 DECSTBM 或回卷行为，也不查询光标。REPL 检测失败时实际降级为 stdout 基础模式，无固定输入区和可替换段；旧稿“失败必须退出、没有降级路径”不是现状。静态检测通过不等于所有终端组合已经实测通过。

回归关注超宽／混排输出、通知插入、长段部分固化、固定区高度变化、切屏及缩放，分别核对可见内容和终端状态；仅 ANSI 字节断言不证明真实终端全部兼容。

## 能力边界

| 能力 | 当前结论 |
|---|---|
| 对话输出原生回看 | 主 REPL 依赖终端回卷；受首次接管与缩放清理边界影响 |
| 状态与输入固定 | 主 REPL 用 DECSTBM；独占面板自行布局 |
| 当前输入、面板与活动段重画 | 有局部状态与对应渲染路径，不是“完全无状态” |
| 完整已绘历史接管与缩放重排 | 未实现；不能以存在 transcript 或局部重画能力代替 |
| 独占面板的长内容滚动 | 按面板实际实现判断；没有通用滚动视口，方向键选择条目也不等于内容滚动 |

这些是实现取舍，不是要求改用声明式框架或重建渲染引擎。任何新屏幕需求应先判断它需要改变哪条边界，不能把“目前未实现”当成终端不可能支持。

## 协议约束与防错规则

- 滚轮回卷、方向键和鼠标事件不是同一机制。xterm 的 Alternate Scroll 模式（1007）可把备用屏幕滚轮转换为上下方向键；鼠标跟踪模式配合 SGR 编码（1006）则上报事件。两者仍需应用正确消费，并管理进入、退出及交接时的模式生命周期，避免转义序列落入普通输入。协议依据见 [xterm 控制序列](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html)。
- 键盘交互不依赖滚轮上报，可作为面板操作基线；鼠标可用性须按终端宿主、版本与配置验证。PowerShell／Git Bash 是 shell 名称，不能据此断定宿主一定是 conhost；旧记录中的单环境结果不构成跨终端支持结论。
- 滚动区写入合同要求每个换行分段的可见宽度不超过 `columns - 1`；否则隐式换行会使逻辑行数与物理行数分离，破坏段位置与滚动计算。按可见列宽处理中文和 ANSI，不能只数字符。
- 清屏、清回卷、撤滚动区与切备用屏幕不是同一动作。`Renderer.clear()` 使用光标归顶后清至屏尾；首次接管／缩放与退出采用各自协议，不能为形式统一互换序列或调整顺序。

### 故障经验：备用屏幕继承滚动区

技能编辑屏曾在进入备用屏幕后丢失顶部框体、出现多余空行，书写态内容自动上滚而难以用鼠标选中。该次记录的对照实验对同一帧只改变是否先发送 `\x1b[r`：不撤销滚动区时顶行被滚掉，先撤销后顶行恢复且保持原位。这个正反对照将该次故障定位到继承的 DECSTBM 区域导致满屏输出提前滚动，排除了最初的满宽自动换行解释；它不构成所有 ConPTY／终端版本的共同结论。

当前 `Renderer.enterAlternateScreen()` 仍在进入后立即发送 `CSI r`，将备用屏幕滚动区恢复为整屏；退出仅离开备用屏幕，不顺手重置返回后的主屏滚动区。`ScreenController.resume()` 则负责重新确认主 REPL 的区域与固定区。不同终端的状态继承行为可能不同，区域恢复由对应的切屏责任体显式完成。

`writeFrame` 使用无尾换行的整帧输出，避免额外换行触发滚动；它仍不能代替对行宽和屏高的正确控制。
