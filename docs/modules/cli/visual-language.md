# CLI 视觉设计语言

本文定义配置编辑器与 REPL 共享的视觉语言；输入区具体形态见[输入区视觉](input-visual.md)。它不定义输入补全、业务流程或屏幕调度架构。

## 设计取舍

知行是日常使用的个人助手。界面应克制、清晰而有温度：首次配置不让人慌乱，日常工作不抢注意力，错误与中断让人知道如何继续。不能靠增加装饰获得层级，也不照搬其他智能体的外观。

早期界面把按钮、状态和选项都当作着色文字，导致可操作性与层级不清。保留的解决思路是用形状、留白和语义样式表达职责，而不是继续增加颜色。

- **安静**：弱化常态信息，按需提示，不使用卡通装饰或无意义闪烁。
- **边界与层级分开**：框体界定独立空间，留白、缩进和章节标记表达层级，不堆叠嵌套框。
- **状态不能只靠颜色**：图标与文字共同表达就绪、待补和未启用；颜色只作强化。
- **中文混排可读且对齐**：按终端可见列宽处理 CJK、ANSI 与换行，不以字符串长度计算布局。路径、命令和说明按语义降权，不挤压主要内容。
- **一个品牌强调色**：青绿用于品牌和关注点；成功、警告、错误各用独立语义色，不混成多个主色。
- **操作有形状**：按钮与普通文字可区分，主次明确，选中态除颜色外还应有标记。
- **输入是独立工作空间**：自适应框体、按需换行，状态变化不推动输入光标；提交后不把整套编辑框堆入历史。

配置编辑器与 REPL 可以采用不同渲染方式，但共享视觉语义与适用原语，不为风格一致强行合并渲染层。视觉变化应先在有限场景看实物确认，再推广；不以纸面示意替代终端体验。本范围不引入鼠标交互基础设施。

## 当前视觉机制

| 元素 | 合同与当前实现 |
|---|---|
| 样式 | `style.ts` 按 brand、success、warn、error、dim 等语义提供颜色、图标与框字符；调用方不另建相同角色的样式体系 |
| 容器 | `chrome.ts` 提供圆角完整框体，宽度由使用面传入；展示容器与输入容器可采用不同内边距 |
| 章节 | `section.ts` 使用 `▎`、缩进与留白组织标题、说明和入口，不沿用旧稿的 `◆` 标记 |
| 状态 | `status-pill.ts` 以图标和文字表达状态；“已配齐”不应被误读为服务已经实际验证成功 |
| 按钮 | `button.ts` 用直角三行框，短动作名在框内、说明在框外；主按钮绿色，次按钮弱化，选中以加粗及外置箭头表达，不沿用旧稿的反白按钮方案 |
| 候选行 | `highlight.ts` 统一点阵纹理：连续空白带与尾部用弱化纹理填充，保留单空格，不给框线染纹理 |
| 历史用户消息 | 灰底整行标识消息归属，与无底色的助手输出区分；不复用编辑态的输入提示符 |

宽度、间距和字符是可校准的工程取值，不是永恒产品要求。当前历史灰底优先深色终端，不能据此宣称所有浅色配色均已验证可读。

## 动态与静态分区

进行中状态在动态区表达，完成结果进入静态历史；同一状态不在两区重复显示。REPL 动画集中于状态条，spinner 与状态条重画同步，不在已落入历史的文字、工具卡片或重试提示中另开动画源。其他独占面板的加载反馈遵守同样的克制原则，不把“状态条动画”误写成所有界面都必须有状态条。
