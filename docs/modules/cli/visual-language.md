# CLI 视觉设计语言

本文定义终端各页面和历史内容共享的视觉语言；输入区具体形态见[输入区视觉](input-visual.md)。它不定义输入补全、业务流程或屏幕调度架构。

## 设计取舍

知行是日常使用的个人助手，CLI 是持续工作的“家”，不是用完即走的脚本工具。界面要有工具的克制与陪伴的温度，既不冷峻，也不卡通化；不靠增加装饰获得层级，不照搬其他智能体的外观。

| 场景 | 体验目标与设计依据 |
|---|---|
| 首次配置 | 不慌：步骤和下一步明确，允许返回修改，视觉重量轻 |
| 日常对话 | 专注：不抢注意力，只在必要时提示 |
| 长会话 | 安心：上下文余量与运行状态可见，避免毫无预告地中断工作 |
| 错误／中断 | 可控：说明哪里出错、能如何继续，错误色不刺眼 |

把按钮、状态和选项都当作着色文字，会使可操作性与层级不清；应以形状、留白和语义样式表达职责，而不是继续增加颜色。

- **安静**：弱化常态信息，按需提示，不使用卡通装饰或无意义闪烁。
- **边界与层级分开**：框体界定独立空间，留白、缩进和章节标记表达层级，不堆叠嵌套框。
- **状态不能只靠颜色**：图标与文字共同表达就绪、待补和未启用；颜色只作强化。
- **中文优先，混排可读且对齐**：中文是主要阅读语言；英文路径、文件名和命令按语义降权，让中文说明主导视线。按终端可见列宽处理 CJK、ANSI 与换行，不以字符串长度计算布局。
- **一个品牌强调色**：青绿用于品牌和关注点；成功、警告、错误各用独立语义色，不混成多个主色。
- **操作有形状**：按钮与普通文字可区分，主次明确，选中态除颜色外还应有标记。
- **输入是独立工作空间**：自适应框体、按需换行，状态变化不推动输入光标；提交后不把整套编辑框堆入历史。

页面向公共组件提供内容和语义，不自行决定相同元素的间距、颜色或标记。视觉变化须核验实际原生帧及交互，不以纸面示意替代终端体验。

## 当前视觉机制

| 元素 | 合同与当前实现 |
|---|---|
| 样式 | `terminal-ui/theme.ts` 统一语义 ANSI 色与间距。品牌 cyan、辅助/边界 dim、成功 green、警告 yellow、错误 red；默认正文使用宿主前景，不在业务文本嵌 ANSI |
| 容器 | `SurfaceChrome` 提供欢迎框、身份和环境信息；主会话欢迎框属于阅读内容，可随阅读卷走，输入与左右信息栏固定在底部。只有实际窗口等级或页面身份改变才切换头部形态，查询条数与加载状态不决定头部高度 |
| 章节与选项 | `ChoiceView` 统一章节、动作及选择反馈；页面只提供条目。选中态用标记及弱化点阵，不给框线染纹理 |
| 状态 | 领域终态决定活动结束，过程流关闭只表示过程传输结束；完成后的指标保持静止。颜色必须伴随可理解的文本 |
| 阅读导航 | 正文下方固定一行，明确下方仍有内容、正在读取或读取失败；失败/重试优先。Ctrl+End 回最新，翻页/回配置页/resize 保留源锚点 |
| 历史用户消息 | 灰底整行标识消息归属，与无底色的助手输出区分；不复用编辑态的输入提示符 |

## 正文的统一语义

N 输出稳定的消息/工具分组身份、角色和源坐标；U 用同一布局进行显示、测量、选区及窗口化。阅读视口占全宽，最右1列独立预留给滚动轨道；正文在视口内部左右各留2列，不再叠父容器留白。用户灰底内左右各2列；助手/工具使用4列标记槽；无标记系统文本不占标记槽。每层列表/引用缩进2列；输入框外边距0列、框内1列。页面与 Placeholder 场景不得另加偏移。

| 内容类型 | 层级、颜色与空间 |
|---|---|
| 用户 | 独立消息组、灰底、正文色；灰底内2列留白，无助手菱形或空标记槽，续行对齐正文 |
| 助手正文 | 独立消息组，起首菱形使用品牌色；正文默认前景 |
| 思考 | 同轮独立块、弱化色；保留其源身份，不与助手正文黏连 |
| 工具/批量工具 | 工具组共用菱形与角色色；运行、成功、失败分语义，失败历史不得投成用户消息 |
| 子任务/过程/系统反馈 | 沿用对应语义角色与明确文本；嵌套内容不另起局部间距体系 |
| Markdown | 段落、标题、列表、引用、代码、表格按节点语义布局；跨传输片的同一节点连续，不重复加空行 |
| 代码/diff | 语法色与增删色分离；行号和增删标记保留，无色仍可读；长行软换行，窄表按列标签堆叠 |

不同消息/工具组之间最多1行空白，与正文已有空行取最大值；同组续片不增加组间距。装饰槽、布局空行、软换行和窄表附加标签不写入复制文本。历史与实时内容执行相同规则。

角色/节点几何由 `body/geometry.ts` 同时供渲染和测量消费；欢迎框偏移纳入同一阅读 owner。窗口变化后等待原生布局完成再按源锚点恢复，不根据尚未重排的行映射累计偏移。轨道出现/消失不改变正文列宽，不增加第二个外层滚动容器。


宽度、间距和字符是可校准的工程取值，不是永恒产品要求。当前历史灰底优先深色终端，不能据此宣称所有浅色配色均已验证可读。

## 动态与静态分区

进行中状态在动态区表达，完成结果进入静态历史；同一状态不在两区重复显示。REPL 动画集中于状态条，spinner 与状态条重画同步，不在已落入历史的文字、工具卡片或重试提示中另开动画源。其他独占面板的加载反馈遵守同样的克制原则，不把“状态条动画”误写成所有界面都必须有状态条。
