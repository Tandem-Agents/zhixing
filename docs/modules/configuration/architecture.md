# 公开配置架构

## 产品边界与取舍

知行是个人助手，配置跟着用户走，不随启动目录隐式改变。公开配置采用用户全局单一来源，不自动发现 cwd 下的项目配置。工作场景差异由显式工作场景责任承载，不以目录散落配置模拟第二身份或隐式作用域。

| 方案 | 取舍 |
|---|---|
| 仅环境变量 | 不适合持久化结构化偏好，也不作为秘密来源 |
| 多层用户／项目／本地级联 | 启动位置会隐式改变行为，增加覆盖判断，不适合当前个人部署边界 |
| 单文件加 include | 当前没有拆分配置的必要，不预建模块化加载机制 |
| 单一用户配置、显式路径覆盖 | 保留可定位的事实来源，同时满足部署与隔离需要 |

首次运行自动生成带注释的模板，降低手工建文件和查 schema 的负担；能否启动仍取决于必要字段，不取决于文件存在。凭据与公开配置物理分离，通过稳定 id 关联；AI 读取公开配置无需确认，写入逐次确认，秘密禁止 AI 访问。秘密存储、引导及跨存储保存差异由[秘密存储模块](../secrets/README.md)负责。

## 来源与路径

[配置加载器](../../../packages/providers/src/config-loader.ts)读取 JSONC，支持注释与尾逗号；不执行旧稿中的三层配置 deep merge，也没有“全部环境变量覆盖任意字段”的通用机制。

路径按[providers 路径解析](../../../packages/providers/src/paths.ts)确定：

1. 调用方显式 `homeDir`：读取该目录的 `config.jsonc`。
2. 否则 `ZHIXING_CONFIG_PATH` 指定完整配置文件路径；其父目录用于相关配置目录解析。
3. 否则使用 `ZHIXING_HOME` 指定的数据根，默认 `~/.zhixing/config.jsonc`。

编辑与保存应使用同一选定文件；当前 `/config` 在自定义文件名下存在[读写路径不一致](runtime-application.md#当前差异与失败边界)，不属于单一来源设计允许的例外。

这是来源选择，不是多个文件叠加。缺失文件在允许自动创建时生成模板并重读；禁用自动创建时可返回空配置。已有文件读取或 JSONC 解析失败不等于“缺失”，应报告错误，不静默吞掉。加载器不等于完整产品语义校验器；废弃字段、秘密嵌入与角色配置由启动等边界进一步校验。

## 写入合同

`writeConfig` 先读现存配置，再应用传入配置并原子写入；已有文件不可读或解析失败则拒绝。不能把它描述为任意字段递归合并：

| 数据 | 当前写入规则 |
|---|---|
| 已提供的 llm、agent、intent、workspace、network、mesh | 整段替换 |
| 已提供的 messaging、mcp | 编辑器使用 replace：整表替换，省略的 id 即删除 |
| 未提供的顶层字段 | 保留现存值；不能据“完整写入”误判为全部删除 |
| 内部 `applyConfigPatch` 的 merge 模式 | messaging／MCP 按 id 合并；不是编辑器删除条目的写入方式 |

保留未触及字段与允许删除已管理条目是两项不同义务。内部 patch helper 不意味着已有新的 AI 配置工具，也不承诺所有 schema 字段都能通过当前编辑器修改。公开配置文件原子写入不等于配置与凭据共同原子提交，见[保存边界](../secrets/onboarding.md#保存取消与失败)。

## 工作区交界

工作区是用户偏好与运行上下文，不是配置来源层。解析顺序为运行时内部显式工作区（例如场景 workdir）→ 全局 workspace.root → 交互环境 cwd 兜底；非交互且未配置时可没有工作区。全局 root 必须是绝对路径，内部覆盖由调用上下文解析相对路径。cwd 兜底不意味着读取 cwd 项目配置，也不新增用户启动参数双轨。

自动模板准备默认工作区，已配置的工作区丢失时有目录保障流程；无配置的 cwd 兜底不负责创建额外目录。目录治理见[路径解析与资源隔离](../../engineering/path-and-resource-isolation.md)，操作影响与信任关系见[信任与管理](../security/trust.md)。

## 当前装配与消费

原始公开配置只在加载、编辑与组合边界处理。组合根通过[运行配置快照](../../../packages/cli/src/runtime/runtime-configuration-snapshot.ts)及[用途投影](../../../packages/cli/src/runtime/runtime-configuration-projections.ts)深拷贝、冻结，并向不同职责发放有限数据：

| 用途 | 配置范围 |
|---|---|
| 模型 | llm、模型能力覆盖 |
| Kernel 环境 | agent、workspace、network |
| 推进 | llm、workspace、advancement、模型能力覆盖 |
| MCP | mcp、network |
| 通道 | messaging、intent |
| 拓扑／工作区／凭据轮换 | 分别消费 mesh／workspace／llm 与 messaging |
| 权威身份 | 为既有执行与就绪身份哈希提供完整公开配置的专用投影，不是任意业务读取全局配置的许可 |

普通 CLI 表面通过只读 Configuration Provider 获得模型、代理展示或拓扑投影，不直接传播完整进程配置；专用配置编辑流程负责修改。运行中的冻结快照不会因文件已保存而自动改变，生效链由[运行期配置应用](runtime-application.md)定义。

## 直接验证

核对单一来源与路径覆盖、JSONC 错误及模板不覆盖已有文件、replace 删除与 merge 保留、工作区绝对路径和兜底、语义校验与秘密隔离、投影深冻结及不同用途不共享可变对象。不得把加载成功、落盘成功、宿主应用成功视为同一个结果。
