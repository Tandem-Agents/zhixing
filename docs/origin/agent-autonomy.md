# 需求原话

现在我来正式跟你说一下我们的第一个需求，这是一个开发任务需求，和先调研后开发的一个需求。这个需求的起点和来源，是我基于 B 站上的一个视频。那个视频是一个采访，我不了解采访者的身份，他又不是记者，就像是一次对谈式的采访。所以我不了解这种采访角色叫什么，但这不重要。他采访的对象是在小米公司做大模型研究的罗福利，好像是从 DeepSeek 公司挖走的。在对罗弗利的访谈中，他在讲解对 Agent 及大模型的看法时，用很长篇幅提到了 OpenClaw（小龙虾）的能力。他说一开始其实看不上这类智能体，认为 AI 的能力边界有其认知局限，觉得应用类智能体不会比模型本身带来大得多的能力，或产生更多附加价值，核心还是得依赖智能本身。但是有一天晚上，他下载了 OpenClaw，当天晚上就和 OpenClaw 聊了一整晚，通宵聊了一整晚。然后他发现 OpenClaw 给他的感觉就像个人一样，能帮助他更好地完成工作。他举了一个例子：在使用 Claude Code 时，如果需要一个视频理解模型，而 Claude Code 提供的模型效果不好，他就需要手动给 Claude 配置一个更好的视频理解模型。但在使用 OpenClwa 时，他完全不需要考虑这些，只需要发送一个视频，OpenClaw 会自动寻找具备良好视频理解能力的模型来完成任务。就这种智能体的自主性是 OpenClaw 一个很大的一个特征，我还有另一个灵感，就是 OpenClaw 作者自己说的。他在 OpenClaw 早期版本还没发布、还在开发且未接入语音能力时，用户无法通过语音使用 OpenClaw。当时他突发奇想，想实验一下 OpenClaw 的能力。虽然功能本身还没实现，但他直接给 OpenClaw 发了一段语音。OpenClaw 自己想办法，通过其他工具解析了语音内容，然后帮他完成了工作。也就是说，OpenClaw 在本身不具备语音理解能力的情况下，自主地通过其他方式完成了用户的任务。这件事当时让 OpenClaw 作者本人都很震惊。而且这个罗福利他还说，他在使用别的智能体的时候会关注不同的模型，因为模型的能力不太同，但是他在使用 OpenClaw 的时候，他不会去特别关注是哪一个模型，因为他使用 OpenClaw 本身就能够去就感觉他能能很好更好的去或者很好的去满足自己的需求，然后在他的理解里面呢，他认为 OpenClaw 这个智能体啊呃就弥补了很多模型本身做不到的一些事情。这个事情并不是说智能体本身的职责的边界，而是说我感觉他强调的还是 OpenClaw 本身的这种自主性和“更像人”的这种特征，因为它是小米公司的嘛，它用小米那些很小参数量的模型接入 OpenClaw 以后，发现它的能力发挥出来的超过了它的想象。也就是说，他认为 OpenClaw 这个智能体本身是对模型能力的一次放大，这个本身其实已经超过了我们传统理解的 Agent 能够提供的服务的边界，它更像是提供了一种自主性，或者更像人的这种特征，所以带来的这种体验感。而且罗福林认为，这个 OpenClaw 比其他智能体要好很多。我差不多把我的需求来源说完了。这个的核心就是，首先我们自己的“知行智能体”很明显没有专门做过这方面的工作，甚至之前都没有过这方面的产品设计。只是在定义上，我们之前定义为通用的智能体，后来升级定义为半身智能。但我觉得我们恰恰缺失了这种自主性，以及这种更像人的特征的能力。这个我感觉是我们现在急缺的一个产品的设计和实现。

我们现在需要一个文档来记录原始需求，也就是把我刚才的原话记录下来。但我觉得这样太暴露隐私了，不太想暴露，又需要记录。你有什么好的建议吗？先回复我这个疑问。

## 核心需求

先调研并实现知行跨场景的通用自主性与主动性，使其能够围绕用户目标，在没有预设流程或现有能力不足时自主寻找办法、组织和运用可用能力、推进任务完成，放大模型的实际作用，让用户感受到能独立解决问题的伙伴，而非需要持续配置和指挥的工具；语音、视频只是这种能力的例证，不是待补齐的功能清单。
