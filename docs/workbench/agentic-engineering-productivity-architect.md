# 智能体工程效能架构师

> 标准名称：智能体工程效能架构师（Agentic Engineering Productivity Architect）
>
> 本文是该角色在知行工程体系中的唯一概念定义。

## 定义

智能体工程效能架构师，是以整体有效交付效率和交付质量为结果责任，把人、智能体、任务契约、代码库、验证、反馈与提交组成的开发系统视为一个工程产品，设计并持续优化其角色、依赖、协作、工具、证据和控制机制的专业角色。

“架构师”意味着其工作对象不是单个提示词、工具或执行步骤，而是整个开发系统的结构、责任关系、信息流、状态转换与质量闭环。

## 核心责任

> 定义并持续优化整个智能工程系统，使它在质量、安全、成本和长期可维护性约束下，用最短时间产生正确的产品结果。

## 持续判断

- 系统究竟优化什么，而不优化什么？
- 什么结果才算真正完成？
- 哪些事实必须由谁拥有？
- 哪些工作可以并行，哪些必须串行？
- AI 可以取得什么权限，什么必须受到约束？
- 什么证据足以证明结果正确？
- 当模型能力变化后，原有流程中哪些机制应该删除？
- 谁对最终错误、成本和产品结果负责？

## 第一性原理

开发系统不可约的构成是目标、资源、执行者、约束、反馈与责任。AI 降低执行成本，却不会消除对目标、边界、证据和责任的定义；执行能力越强，错误方向、协作冲突和虚假完成也越容易被放大，因此必须有一个角色对开发系统的整体有效性负责。

模型越强，真正稀缺的越不是“谁能干活”，而是：

```text
做什么
由谁负责
怎样组合
如何证明正确
何时停止
```

## 与人工智能能力增长的关系

该角色与人工智能能力增长在角色层面是增强关系：AI 越强，它能够设计、验证和持续优化的工程系统越大，能够调动的能力越多，产生的工程杠杆越高。

## 职责

1. **定义结果。** 把产品目标转化为可验证的工程完成条件，以最终交付结果而非活动数量衡量进展。
2. **建立系统模型。** 识别任务依赖、关键路径、共享资源、信息流、反馈周期、等待点和返工来源。
3. **设计协作结构。** 明确人和智能体的角色、责任、权限、交接、并行条件与唯一所有权，防止重复劳动、责任空白和多条事实主链。
4. **设计任务契约。** 让每个工作包具备清晰目标、范围、约束、完成证据、止损条件和安全交接点。
5. **优化任务调度。** 在依赖允许时扩大真实并行，在依赖冲突时保持单一写入，以最短关键路径组织工作而不制造虚假忙碌。
6. **建立质量闭环。** 设计直接验证、独立核查、证据失效、问题回退和最终退出机制，使局部完成不能冒充整体完成。
7. **建设工程支撑。** 只对反复出现且能够量化收益的摩擦建设自动化、可观测性、验证工具和知识沉淀。
8. **持续改进系统。** 根据真实交付数据和失败事实调整协作方式，使每一轮工作减少等待、重复理解、无效验证和同类返工。

## 工作闭环

```text
产品目标
  → 可验证的任务契约
  → 依赖与关键路径
  → 角色和工作包
  → 实施与直接验证
  → 独立核查与反馈
  → 接受并形成新基线
  → 复盘并改进开发系统
```

## 判断标准

- 在产品、架构和工程质量不降低的前提下，有效交付时间持续缩短。
- 等待、上下文重建、重复调查、无效验证、冲突和返工持续减少。
- 任何任务的责任、状态、证据和完成边界都可被独立核查和可靠恢复。
- 智能体数量、代码量、提交数、测试次数和忙碌时长不被当作生产率本身。

## 责任边界

- 不替代产品负责人决定产品价值，不替代架构师决定产品架构；负责让这些目标被高效、准确地落实为生产事实。
- 不以降低质量、缩小必要验证或掩盖问题换取速度。
- 不为追求并行而拆散同一所有者、写权、生命周期或验证闭包。
- 不把流程复杂度本身当作专业性；只有能够减少交付成本或提高交付可信度的机制才应保留。

## 核心产物

- 协作体系与角色责任设计。
- 任务依赖图、工作包契约和调度规则。
- 质量门、证据规则、状态恢复与退出机制。
- 提升反馈速度的工具、自动化和可观测性。
- 基于真实效率问题形成的流程改进记录。
