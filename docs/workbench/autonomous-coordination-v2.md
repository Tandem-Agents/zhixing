# 持续协调自主开发 v2

> 状态：独立设计，尚未接入现行协调流程。

> 设计视角：以[智能体工程效能架构师](agentic-engineering-productivity-architect.md)的角色审视本体系——把人和智能体共同组成的开发系统作为一个工程产品，在不降低质量的前提下持续缩短有效交付时间。

## 目标

在不降低产品、架构和工程质量的前提下，通过并行准备、单一实现责任和独立验收，减少工作包之间的等待、重复理解与无效返工。

## 角色与职责

### 协调者

- 维护任务目标、依赖关系、整体进度和唯一接受基线。
- 选择当前价值最高的责任链，定义工作包边界、完成条件和止损点。
- 独立核查执行结果与仓库事实，决定纠正、接受、提交和下一工作包。
- 独占 Git 提交与集成责任，不参与当前工作包的并行代码修改。

### 当前实现者

- 独占当前工作包涉及的生产责任链和代码写入权。
- 同时闭合生产实现、全部直接消费端、旧路径删除、行为保护和直接证据。
- 不扩展到下一责任链，不执行 Git 写操作；在完成、阻塞或达到止损条件时留下可复核交接。

### 前置核查者

- 基于唯一接受基线，提前核实下一候选责任链的生产入口、所有者、消费者、旧路径和验证入口。
- 当前实现者交接后，独立核查最终差异、功能回退、架构残留和证据有效性。
- 不修改当前实现者负责的代码，不把前置调查结论冒充新基线上的完成证据。
- 当前工作包通过后，优先接任下一工作包的实现；上一实现者转为下一轮前置核查者。

## 协作流程

```text
协调者冻结接受基线并定义工作包 N
              │
       ┌──────┴──────┐
       │             │
当前实现者实现 N   前置核查者基于接受基线核实 N+1
       │             │
       └──────┬──────┘
              │
        实现者安全交接 N
              │
     前置核查者独立核查 N
              │
       ┌──────┴──────┐
       │             │
    发现问题        未发现问题
       │             │
退回 N 最窄纠正   协调者独立验收并提交
                     │
            两名执行者交换职责
                     │
                 开始 N+1
```

## 并行边界

1. 同一所有者、写权、组合根、生命周期或验证闭包始终只有一名代码写入者。
2. 前置核查使用固定接受基线；当前实现中的临时状态不得进入下一工作包判断。
3. 只有两个候选工作包不存在顺序依赖、所有权重叠、共同组合根、代码热点和验证资源冲突，且任一提交顺序都成立时，前置核查者才可同时转为第二实现者。
4. 条件不成立时，第二名执行者只做前置核查和独立验收；不得为了保持忙碌制造任务或重复当前实现。
5. 重型 Windows 验证按验证手册串行执行；最窄测试只有在资源、构建产物和输入相互隔离时才可并行。
6. 执行者结论只作为验收输入；协调者必须依据当前仓库事实独立裁决。

## 工作包合同

每个工作包必须包含：

- 唯一接受基线与当前检查点。
- 一个可独立验收的目标结果。
- 生产端、全部直接消费端和旧路径处置。
- 明确范围、排除范围和不可回退行为。
- 最窄直接证据、完成条件、止损条件和安全交接点。
- 哪些既有证据继续有效，哪些变化会使其失效。

## 状态转换

```text
候选责任链
  → 已核实边界
  → 实施中
  → 待独立核查
  → 待协调者验收
  → 已接受并提交

任一核查失败
  → 恢复为实施中
  → 完成最窄纠正
  → 重新独立核查与协调者验收
```

任何未提交工作区都不是接受基线；任何前置调查都不能替代新基线上的直接验证。
