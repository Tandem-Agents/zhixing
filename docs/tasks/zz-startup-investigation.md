# zz 启动与真实使用问题核实

更新：2026-09-28。

**当前结论：本轮定点优化与修复已完成，尚未证明整体启动稳定提速。** 已消除资产授权、工作场景索引对无关事件的磁盘读取，并修复平台密钥状态查询绕过初始化锁的问题；无稳定收益的身份预取已撤回。最终无探针冷启动两次为 **15.547／14.313 秒**，热启动 **1.156 秒**。功能、日志与窗口验收通过；耗时波动根因仍未查实，不宣称已达性能极限或启动性能已全部收尾。

## 目标与验收边界

- 从任意目录运行已安装的 `zz`／`zhixing`，使用用户配置的同一运行环境，不在调用目录产生无关文件。本机已配置绝对工作目录；未配置工作目录时，现行合同仍允许交互模式回退到 cwd，不能把本机结果推广为所有配置均与目录无关。
- 同时保证启动速度、日志健康和真实功能可用；不通过清空历史、降低权限／身份／资源／耐久校验、隐藏告警或把必要准备推迟到首次发送来提速。
- 验收必须先构建，再从全局入口按真实用户流程操作。单元测试、mock、日志可读或单次无告警，均不能代替实际启动、交互、执行、持久化和恢复验证。
- 本机具备条件的流程由助手完成；缺少第二台设备的配对、迁移和灾备等不作为本次实机目标，也不标为已通过。新增问题先登记查实根因，再修复及复验。

## 已确认的根因与修复结论

### 启动与运行恢复

| 问题 | 根因与最终处理 |
| --- | --- |
| 失败后仍长时间等待 | handshake 返回“启动中”后丢失子进程终态，前台又进入独立恢复窗口。启动准备、握手和发现现共用一个绝对期限并持续观察退出；保留其他合法 owner 接管机会。总期限用于容纳完整启动，延长期限本身不算提速。 |
| 首屏空白、前台加载过重 | 进度组件晚于大批模块加载创建；REPL 静态依赖带入后台实现。现从轻量入口持续反馈至输入接管，配置、故障浏览及管理按使用时机加载，前台使用窄 client／types 入口。构建导入图确认前台不再预载完整后台。 |
| 凭据准备重复且阻塞 | 前后台及同一 Host 的多个组件反复创建秘密存储；Windows 平台命令创建还会同步阻塞线程。自动启动规划移入候选 Host，进程内复用同一 SecretStore；每次准入仍重新核实配置、身份与信任。平台命令在一次性独立进程执行，DPAPI 收敛为单操作与有界二进制管道，保留 CurrentUser 保护、既有密文兼容与缓冲清理。IPC 启动规划只传模式，不传秘密。 |
| 未安装托管服务仍做完整定义查询 | Windows 在本地定义不存在时仍启动 PowerShell／COM 确认任务不存在。现先用 `schtasks /Query /TN /HRESULT` 查询系统，仅明确不存在的 HRESULT 可直接返回；任务存在仍做完整定义、主体与状态核验，权限与未知故障失败关闭。单次系统查询从约 0.46–0.80 秒降至约 0.07 秒。 |
| 资源采样缺失被误报为内存不足 | 目录创建参数暗中切换采样语义；样本过期依赖请求触发刷新，慢恢复前缀使重试反复过期。现统一生命周期内的异步采样和单调时钟；未知压力明确为 `probe-unavailable`，不伪造零内存。保留真实安全余量、持锁零等待及锁外有界接续。 |
| 旧历史阻断恢复 | 冷恢复 reducer 未先协调资源事实；已回收流的票据撤销重放不幂等。现由 Journal 沿原端口协调资源，永久回收后的撤销可重复执行；不重建流、不恢复旧权限、不要求预热或清空历史。 |
| Authority 读取放大 | 逐帧细碎 I/O、未变化投影执行写事务、单会话查询遍历全部会话、重复规范化和哈希共同放大恢复成本。现用扫描内 64 KiB 读取窗口、只读投影端口、目标流查询和有界校验证明复用。扩展列表使用只读端口，修改复用已验证游标；定向查询跳过已由当前字节摘要证明无关的单流信封解码，混合流仍正常处理。写决定仍在排他锁内基于最新事实裁决。 |
| 重复与串行准备 | 本地界面快照与会话选择、订阅与初始历史并行；同批同会话历史通知合并查询，新到事实必须重查。公共 Host 模块与启动规划并行加载，配置观察使用窄包入口，具体角色仍由可信拓扑选择。首次常规资产 GC 在原 owner 下后台执行，沿用有界批次、取消和关闭排空，不再阻塞输入就绪。 |

**Authority 优化的安全边界：** 不缓存文件字节或可变业务对象。追加后需要复核旧前缀时，在原排他锁内重新读取全部旧前缀字节，与已验证摘要比较后解析新增帧；进程内至多共享 8,192 条按实际字节摘要索引的校验证明，每个读取者仍核对日志身份、LSN、帧及前缀链。省略对象解码不省略物理校验；新字节必须完整验证，无关流损坏也必须报错。返回对象独立解码；替换、截断、半帧及 fsync 边界继续按原协议处理。未变化只读游标须匹配路径、日志身份、文件身份、长度和修改时间；任何不确定均退回正式校验。

### 日志与进程生命周期

**短时互斥是共享预算、发布水位和回收协议的正确性要求；长期持锁、写者饥饿和假写者不是正常功能的必要成本。** 最终沿用同一 Store 与协议，修复临界区和执行边界，没有另建常驻日志服务。

| 问题 | 根因与最终处理 |
| --- | --- |
| 正常追加反复做全量治理 | 每批追加重复迁移发布、清点和维护。现稳态追加只做必要发布；无变化维护不写入，初始化与成功追加推进维护时钟。受保护文件原语批量清点，同一锁周期内复用清单，变更即失效；跨锁重新取证，身份、链接与真实预算检查不减。 |
| 业务线程拖长日志持锁 | 原 native 子进程只执行文件调用，整个事务仍由业务线程串联。现把完整 Store 写事务移入独立进程；原容量 owner 在持锁前预留，写进程内计量、解锁后结算，不在持锁中依赖业务线程往返。真实故障注入确认业务线程停顿时写事务仍能完成解锁。 |
| 写者饥饿、观察滞后 | 即时抢锁与退避让等待者反复错过窗口；旧进程清单还能撤销更新登记。现使用同一 OS 字节锁的有界等待，超时取消并收束未决 I/O；旧采样不得撤销较新的登记。保留 PID＋出生身份、未知写者门禁及崩溃接续。 |
| 纯查询被当成写者 | 入口记录范围、进程分类不一致，且 preAction 一度只传顶层命令。现从 Commander 解析树取得完整命令路径，统一生命周期分类；status、doctor、workspace status/list、backup status 等纯查询不创建 Recorder，修改入口仍记录。正式 dist 回归核查失败与并行查询均不创建日志根。 |
| 只读查询撞上正常代际回收 | 治理枚举、stat、读取之间旧代际被回收。最终使用已有控制文件的有界共享读锁，仅保护治理与库存快照；正文扫描不持锁，途中淘汰按缺口合同表达。查询上界、权限复核与只读零写入保持不变；未采用无限乐观重试。 |
| 健康原因与恢复证据失真 | 通用 catch 混淆等待／故障，恢复清空原因，健康记录还可能驱动重复写入。现区分有限错误类别，保存等待、真实降级及恢复；采集缺口单独保留原因。未知写入不重放，物理或策略发布失败不再次发布不确定状态。未提高告警阈值掩盖故障。 |
| 进程扫描成本高 | 每次重新启动 PowerShell 并编译参数解析桥。现由既有原生 owner 提供有界进程清单，CLI 统一分类；身份与观察完整性规则保持不变。 |
| 后台反复弹出空白终端 | 日志写进程 fork 遗漏 `windowsHide`，退出后恢复重建再次创建窗口。唯一启动入口及测试夹具现显式隐藏；真实 Windows 验证初建、强杀后重建、关闭和前台退出后均无新增可见窗口。`stdio: ignore` 不能替代隐藏窗口选项。 |

### 真实交互发现的关联故障

| 问题 | 根因与最终处理 |
| --- | --- |
| `/stop` 及部分换代请求失败 | 客户端遗漏服务端必填 `requestId`。统一停机请求合同，同一未完成意图重试保留身份；以真实 handler 和正式入口验证，不放宽参数校验。 |
| 配置保存后重连自等待 | starting 通知内发 RPC 等待自身 reconnect；ready 回调又无法取得已经认证的连接。进度事件不触发订阅恢复，已安装的当前代连接可直接取得，旧连接换代时立即摘除。真实配置保存、换代及恢复原配置通过。 |
| 工具已产生效果却提交失败、会话悬挂 | 成功工具消息显式携带 `undefined`，且完成准备／封存未纳入异常收束。生产者省略缺省字段，本地与远端覆盖终态准备和封存失败；已封存／已确认事实不能覆盖或自动重放。历史 uncertain 通过既有 fence 裁决，补齐 `/resolve` 与普通用户输入投影。 |
| 任务维护访问旧事实源 | 任务端口仍写旧 scope meta，RPC 丢弃操作身份。现统一使用 Conversation owner journal，TaskListService 仅缓存已提交投影；重试依据原请求的权威快照，不按变化后的序号误操作，不补建第二权威。 |
| 取消后报模型错误 | executor 先结算用量再停止实际 assignment，后续真实用量产生身份冲突。现先登记取消 fence，再停止实际执行体，清理完成后结算并出具停止证明；保留取消接续，避免终态锁内自等待。 |
| 中文会话身份丢日志 | 业务身份误用 ASCII 结构名称校验。采集、关联键、地址、搜索及访问 scope 统一采用有界 Unicode 业务身份合同；控制字符、秘密检查及精确授权不减。 |
| 终端与历史反馈错误 | 异步通知绕过当前终端 owner、命令粘贴被误作路径、框体突破可用宽度、历史只显示消费状态而省略终态。现统一输出归属、先识别命令、使用 columns−1 视口，并同时投影真实运行状态。Workscene 无效参数在访问应用前拒绝。 |

### 修正后的优化计划

**保持启动功能范围与完整就绪标准，先补必要证据，再处理索引同步与 Windows 辅助进程。当前数据既未证明已达极限，也未证明能达到 6–8 秒或存在 9.5–10.5 秒下限；不预先承诺节省量。**

| 顺序 | 工作 | 判定与边界 |
| --- | --- | --- |
| 1 | 轻量补证 | 区分排队、执行和完整等待链，同条件比较优化前后完整就绪及慢样本。沿用临时探针与真实入口，不新建 benchmark／自动捕获体系，不将任意 10% 阈值设为统一门禁。 |
| 2 | 派生索引同步 | 一次锁内同步约 0.59 秒使凭据发布排队约半秒，但尚未证明是全量重建或全部可省。先核实检查点、重放范围与同步次数，减少重复工作；现有恢复会修改索引并处理损坏尾部，不能当纯读直接出锁。若确需锁外构建，必须完整保证快照一致、增量追平、发布校验及异常恢复，并证明缩短了实际等待链。 |
| 3 | Windows 辅助进程 | 一次解锁约 0.96 秒含首次文件锁取得约 0.38 秒。DPAPI 经独立 Node worker 调 PowerShell，进程身份查询直接调用 PowerShell，服务缺席检查已用 schtasks；分别核实可合并或可重叠的工作，保留身份、加密、隔离和关闭责任。 |
| 产品选项 | 提前交互与常驻 | 输入草稿、取消和本地启动进度可早于完整就绪，但不算完整就绪提速；后台复用已有实现。两级交互及常驻策略调整另行作为产品取舍，不纳入本轮技术优化。 |
| 暂不重复 | 编译缓存 | 已做临时试验：首次填充 11.891 秒、复用 15.015 秒，各一次。只能判定未证明收益，不能判定无效；缺少新假设时不重复同类一次性试验。 |

**其余暂时停止：** 代码加载、会话／任务恢复、工具装配与渠道协调按中低价值处理，缺少可直接去除的大块冗余证据；配置、目录所有权、本地连接和终端呈现收益低；首次 GC 已退出等待链。低收益不代表已达物理极限，日志并行初始化也不能重复计入总时长。

**停止条件：** 只保留收益可重复且与实现复杂度相称的修改；两项定点验证无法证明值得继续时，结束本轮性能工作，不扩建缓存、并发机制或验证设施。6–8 秒作为未验证的工程预算，不作为无限优化的硬门槛；安全、功能和耐久要求保持不变。

## OpenCode 对比与目标依据

同机核实的 **OpenCode 1.18.33** 默认终端每次新建服务线程，退出时关闭；只有 `serve`＋`attach` 显式复用服务。默认终端不连接本机另开的桌面服务。对应[启动源码](https://github.com/anomalyco/opencode/blob/v1.18.33/packages/opencode/src/cli/cmd/tui.ts)与 [attach 实现](https://github.com/anomalyco/opencode/blob/v1.18.33/packages/opencode/src/cli/cmd/attach.ts)支持这一生命周期判断。

同目录、原配置与数据、计时至输入框出现，三次默认启动为 **4.843／4.859／5.000 秒，平均 4.901 秒**，均为服务未运行条件。应与知行冷启动比较，不能用知行约 1.1 秒热启动证明默认启动更快；该对比也不是相同功能范围的性能基准。

知行约 1.06 秒为首次反馈，不能与上述输入就绪时间混比；尚无同口径的 OpenCode 首次反馈测量。

- **共同范围：** 会话与历史、模型配置、工具／子智能体、权限、插件／MCP、持久化和终端。OpenCode 默认首页不等历史列表，继续会话才等待；知行默认恢复最近对话，属于准备时机差异，见[启动同步实现](https://github.com/anomalyco/opencode/blob/v1.18.33/packages/tui/src/context/sync.tsx)。
- **知行额外责任：** 常驻服务管理、设备身份与信任、跨渠道投递、持久任务与调度恢复、效果确认和资源治理。OpenCode 另有语言服务、格式化、Git 快照等专门能力，知行并非完整包含它，见[初始化实现](https://github.com/anomalyco/opencode/blob/v1.18.33/packages/opencode/src/project/bootstrap.ts)。
- **目标依据：** 以共同能力及基础设施约 4–5 秒、额外责任对等待链净增约 1.6–3 秒作为工程预算，形成 **6–8 秒**目标。预算尚未实现验证，额外责任的当前耗时不能当作合理必需成本，也不能重复计算并行工作。

## 后续仍有价值的取舍与验证方法

- **已撤回的候选：** 整份 WAL 字节缓存未取得可靠收益，且广泛回归暴露篡改／修复序列风险；第一方依赖整体打包也无明确收益。均未进入最终实现，不应在缺少新证据时重新引入。
- **Windows 执行边界：** Worker 线程仍共享进程句柄空间，不能替代独立进程隔离子进程管道继承；必须验证真实 DPAPI 与日志 helper 并行、父进程退出、异常重建及桌面窗口状态。修改原生制品前须正常释放相关进程占用。
- **日志治理成本：** 字节少不代表清点和回收便宜，历史小段曾先触及文件数预算。后续判断存储成本须同时看字节、文件数及单次事务操作量，不能只看目录总大小。
- **入口级验证优先：** 分类函数正确不代表 preAction 接线正确；前台认证成功不代表输入已就绪；工具效果发生不代表终态已提交。分别核实真实入口、输入、外部效果和权威终态。
- **计时不污染结论：** 性能基准不与构建／测试并行，冷热分别取样；探针只记录阶段、时间和计数，不记录秘密或业务正文。密集探针结果不能冒充无探针性能，结束后恢复无探针产物运行。
- **真实终端验收：** 检查输入、响应、持久结果和实际退出；字符与 Enter 连续注入可能被终端当作多行粘贴，不能把强制清理测试进程算作 `/exit` 成功。构建和回归通过只证明其覆盖范围，不宣称全产品、全平台均已验证。
