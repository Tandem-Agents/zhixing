## 让我们以最快的速度完成发布工作

目标：尽快交付首个高质量版本，达到优秀开源项目应有的交付标准；不以首版实现全部长期愿景为前提。

最近一次核查尚未确认新的功能阻塞，但工程门禁、发布流程和最终验收仍有未完成项。以下为现有工作摘要，正式启动前需结合上述工作再次确认；详细待办、验收标准、进度与证据统一维护在[首次公开发布：标准与推进方案](../delivery/first-public-release.md)。

1. R01：修复文档迁移导致的 S7 门禁失效，恢复完整 lint 通过。
2. R02：分离候选发布与正式推广，验收完成前不提升 `latest`。
3. R03：完善 GitHub 项目信息、安全反馈渠道及中英文公开入口；可与前两项独立推进。
4. R04：固定候选版本与输入，完成构建、制品及必要工程验证。
5. R05：发布非默认候选，完成真实安装与核心用户旅程验收。
6. R06：通过发布标准后正式发布，同步 npm、Git 标签、GitHub Release 与发布说明，复验公开安装入口。

只修复有事实依据、影响首发合同的问题；复用仍有效的验证证据，不无理由重复同输入的全量验证，不把 Research 全量迁移或非必要增强变成发布前置条件。范围内的体验、正确性、安全性与耐久性不降级，发布条件满足即发布。

需要用户配合时再提出：账号登录与权限确认、用户自行输入模型或外部服务凭据，以及实际发布授权；不读取或展示秘密。
