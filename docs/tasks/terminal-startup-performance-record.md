### 关键问题与最终实现

1. **首发前准备完整且不按全历史计数。** Anchor恢复会话原来漏接运行投影准备，运行体又在首发才创建，并遍历全部旧转录统计轮数。增长后曾实测首次准入6.73秒。现在在恢复返回前准备所选投影和运行体，复用已有权威 `SessionMeta.turnCount`，只倒读原token预算内的上下文。保留原摘要选择、过大单轮压缩核及clear边界；无权威提交前缀时保留legacy兼容读法。新增等价性测试确认内容完全相同，并限制样本只读取预算内两条。正常长会话旅程9748首发99毫秒，最终候选的无检查点旅程9752首发162毫秒。
2. **消除历史正文在运行缓存中的放大。** 运行投影使用写时复制候选，失败后保留已经验证的旧前缀；完整派发首次验证后不再缓存 `windowInput`，已结束输入保留摘要而非正文，活跃输入继续保留。精确重放仍校验绑定，真实派发仍从原制品重建。v2检查点可迁移已认证v1状态，迁移不重新读取旧制品。
3. **全局队列不被休眠会话占住队首。** WDRR在当前活跃申请中挑选可调度者，耐久队位仍保留；正常忙碌会话可以逻辑排队，未执行或待确认的阻塞头不能冒充可执行任务。queued输入按真实排位排序。
4. **恢复只续算尾部。** 控制准入改为按request/ingress精确读取的耐久索引，外置输入保留原CAS引用；凭据暴露、Skill、Workscene复用当前状态索引。工作区绑定/探测使用认证检查点。正式停止补存已准备索引的有界覆盖层，不初始化未用索引或承担历史合并；空mutation不复制active Map。
5. **完整性与取消边界保留。** 认证索引清单和条目MAC绑定文件/位置/内容，固定长度MAC采用常量时间比较；无完整性密钥不信任落盘认证缓存。认证WAL读取仍核对真实帧头、帧尾、LSN和前缀。纯决定阶段发现派生损坏只在写栅栏内重建一次；终态的临时维护压力在队列外重试，不重复模型执行或已经封口的步骤，停止等待已开始步骤收束。
6. **停止成功必须是真实退出。** 原实现把PID标记消失/换代当成退出：20/20次独立探测证实返回成功时原进程仍在。进一步抓到Node `kill(0)`为ESRCH、原生等待句柄仍为同一出生时间的 `present`。现在原生三态优先，明确 `absent` 或出生换代才证明原实例退出，原生 `unknown` 不放行；没有原生适配时保留便携出生/存活校核。停止只清理原实例标记，不结束或清理PID重用后的新实例。共享探测仅从Server client窄入口导入运行值。

停止问题证据见[20次旧行为对照](../../collab/threads/20261014-startup-closure-3c71/stop-before-after-proof-baseline.json)、[两种OS探测矛盾的现场](../../collab/threads/20261014-startup-closure-3c71/coarse-native-exit-race-evidence.json)。最终冷启样本逐项含独立退出证明。

- **旅程是最坏情况**：每轮在最后一次回复后约 3 秒即正式停止 Host，空闲维护来不及执行，下次启动要追平整段会话的尾部；真实使用中 Host 常驻，空闲维护会在后台完成这些工作。

## 各版改动

**V1～V4**（摘要）：写者锁按会话持有；重依赖改为首次使用时加载；字节核验复用缓冲；日志合并发布；设备生命周期投影共享；Windows 交互终端预拉起 Host；握手等待同 home 存活的 owner；制品 JSON 读索引改为 WAL 模式的 SQLite。详见 V4 版本记录。

**V5（历史）**

9. **启动证明（`core/authority/startup-proofs`）**：已核验帧证明旁路升级为“已核验前缀”——记录全部帧所占字节的摘要与帧表（LSN、帧尾偏移、前缀摘要、载荷长度）。冷启动整段哈希比对一致、帧表与每帧帧尾记载的 LSN 和前缀摘要逐一相符时直接重建核验视图，只对其后的尾部逐帧核验；字节被改写、帧表被改写或认证不过都退回完整逐帧核验。
10. **投影检查点**：控制准入、Anchor 与执行器资源治理、会话运行日志（run/submission/publish/final）、设备生命周期（无校验器实例）、启动恢复发现。检查点绑定已核验前缀（日志身份、LSN、前缀摘要）与代码身份，加载时在日志锁内对实际字节核对边界；每推进 256 个 LSN 保存一次，**正式停止前补存一次**（日志登记补存回调，停止维护前执行），重启后只续算尾部。状态在第一次等待之前同步序列化，调用方随后原地推进同一份状态也不会写出与游标不符的状态。
11. **证明认证**：检查点与帧证明都以完整性密钥做 HMAC。密钥随机生成，存放在与设备签名密钥同一个受保护密钥库（新增 SecretRef 种类 `authority-integrity`）；不持有它就无法伪造可被采用的证明，防伪强度与回放时的签名校验相同。Host 在后台取得密钥，不串到启动关键路径；密钥库不可用时启动证明整体不启用。
12. **主日志按间隔复核**：仅对开启启动证明的 Host 主日志，文件身份与时间戳均未变时两次整份字节比对至少间隔 1 秒（默认仍为逐次比对），任何元数据变化立即重新比对；保留时间戳的带外改写最迟在 1 秒后的下一次操作被发现。核验视图上限对这些日志放宽到 64MB。替代此前“每次操作整份重读日志”（单次首发准入读约 584MB）。
13. **启动恢复发现**改为带检查点的投影折叠，只续算尾部；没有待恢复会话（常态）时不读整份日志快照。有候选时也先从检查点恢复控制准入与候选会话日志，只为恢复不了的部分读一次快照。
14. **首发准入**：控制准入已从检查点恢复时不再整份重新归约；会话恢复显示后在后台预备控制准入基线（只读、只做一次、与首发共享进行中的任务）。
15. **数据面票据**：签发、撤销与恢复路径内联的维护只做退休事务，不再做物理撤销；周期维护每轮最多 8 个，每个撤销单独排入登记表队列，前台最多等一次撤销。消除了“隔日／升级首开”时为大量过期票据逐个撤销拖慢就绪的问题。
16. **制品生命周期索引**：领用任务与退休任务的提交由“逐任务刷盘并每五个触发一次整轮合并”改为与源回放一样合入有界覆盖层按页落盘；Host 启动 60 秒后每 30 秒做一次空闲维护（追平源日志并完成挂起合并），正式停止前再做一次（上限 5 秒）。启动同步由 7～10 秒降到 0.2～0.5 秒。
17. **持久投影索引**：段文件按需打开；已核验段条目按段缓存（键、已核验的规范编码），复用前核对段数据文件身份（大小、时间戳、文件号），带外改写或删除即丢弃该段缓存回到真实读取。单次点查由 8～20 毫秒降到亚毫秒级，整段会话的索引读取耗时由约 33 秒降到约 3.4 秒。
18. 删除并收束的会话同时丢弃其投影检查点；启动新增 `create-local-executor`、`recover-workscene` 阶段观测。

## 尝试过但未采用

| 尝试 | 结果 | 处理 |
|---|---|---|
| 全部推进会话的恢复移到就绪之后 | 就绪未提前、就绪后约慢 1 秒 | 撤回（V3） |
| 整包打包依赖、V8 编译缓存 | 各模块加载阶段持平 | 不采用 |
| 进程内备忘已验证的设备签名 | 与 `device-identity` 约束“只缓存解析，不缓存信任或签名判定”冲突 | 撤回 |
| 把资产协调器的启动恢复移出关键路径（交给资产维护首轮） | 首轮维护与启动步骤争用设备读取容量，一个启动步骤拿到 backpressured 直接失败，Host 启动失败 | 撤回；改为让恢复本身变轻（第 16 项） |
| 会话恢复显示后整体预热首发准入（含会话日志） | 恢复路径本已预备会话日志，预热冗余，变异核验不区分 | 撤回，只保留控制准入基线预备（第 14 项） |
| 检查点间隔降到 64 个 LSN | 最大检查点约 5MB，热路径上周期性同步序列化 | 不采用；改为正式停止前补存（第 10 项） |
| 检查点只绑定代码身份、不做认证 | 能写文件而无设备密钥的一方可伪造投影状态、绕过回放时的验签，违反 V4 方案“与签名同等防伪强度” | 补上 HMAC（第 11 项） |
