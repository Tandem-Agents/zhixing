# 智能体评测体系

> 类型：体系建设

## 一、需求与目标

同一模型在不同智能体系统下发挥出的真实任务水平存在显著差异。知行的目标是成为最能充分释放模型能力的智能体系统，在持续演进中需要建立可靠的评测体系，用以客观检验完成真实任务的整体表现、衡量版本迭代前后的实际进退，并识别系统中影响模型能力发挥的关键因素与问题，驱动针对性改进。

本任务要求将智能体评测真正落地并内化为长期专业能力，对具体承载形态不设前置限制：一方面，依据实际需要建立适配知行的评测体系与配套机制，必要时沉淀为可复用技能或纳入工程协作体系（如 Guild）的职责；另一方面，按四层深度明确人机掌握边界——人掌握第一、二层的核心本质、评判框架与方向取舍，智能体掌握并负责第三、四层的具体方法、设施构建、评测执行与问题归因。

知行当前尚无智能体评测体系，无需开展现状梳理，直接从系统调研切入：在深入研究一流评测理论与实践的基础上，以宏观[愿景](../vision.md)和[架构演进方向](../architecture/evolution-direction.md)作为唯一顶层指引与硬性标准，结合[现行核心架构](../architecture/overview.md)系统设计并落地世界一流、经得起时间检验的智能体评测体系。

## 四、执行待办

### 4.1 通用推进规则

> **执行待办与单内高效推进规则（通用）**
>
> 1. **端到端工作流待办与子门禁原位保留。** 分割线下方以待办列表（`- [ ]` / `- [x]`）覆盖从前期定稿、独立分支与环境隔离、各执行项实施验收直至集成收尾的完整工作流程，不顺带改动分割线上方已审定的静态正文。无论任务判断不拆分（整项作为单个执行项推进）还是拆分为若干执行单元，均**保持已审定的业务范围、交付成果与完成条件原封不动**，不在待办中重拆业务单元。建单排期时，每个执行项顶部（紧接`前置依赖`之后）直接挂载三道工序门禁子待办（初始均写 `- [ ] **门禁 A/B/C（…）：** 待执行`）与 `- **完成依据：** 待验收通过后填写`；每完成一道工序，将对应子项如实改为 `- [x]` 并填写一行落实要点；整项验收达标勾选顶层 `[x]` 时，填写`完成依据`并**原位保留三道 `- [x]` 门禁子项，不折叠、不合并、不删除**。每一项待办与子门禁均须在真实执行并核验达标后勾选，严禁跳步、代勾或事后补造。
> 2. **单内三道必经工序门禁（通读、深悟、遵守三位一体）。** 每推进一个执行项，实施方在以下三个认知拐点均须完成同一完整动作——**调用工具重新通读[高效工作方法](../engineering/antigravity-gemini-4-carbon-high-efficiency.md)全文、结合当前阶段深入理解高效工作的本质、并在后续实际操作中严格遵守执行**（严禁凭记忆或以“已知悉”为由跳过通读、流于形式只读不悟，或读而不遵守）：
>    - **门禁 A（开工实现前）：** 完成上述通读、深悟并确立遵守准则后，一次性核清本项触及的一手源码契约、调用写入面、恢复与并发边界及测试替身约束，合并已知独立读写成批完成编码（编码期不零散跑重型构建与长流程验收），附一行落实要点后真实勾选 `[x]`。
>    - **门禁 B（代码落定、转入构建与实测前）：** 完成上述通读、深悟并确立遵守准则后，先做逐项代码自审与低成本定向快测（核实实际执行用例数 `> 0`；高耗时或大规模验证先做小样本测算并设硬超时），出清契约与边界问题后再集中执行构建与真实入口验收，严禁拿重型构建和正式验收充当排障调试器，附一行落实要点后真实勾选 `[x]`。
>    - **门禁 C（反例返修前持续生效、达标收口时勾选）：** 每次自验受阻或独立审查退回、动手改码前均须重新完成上述通读、深悟与遵守校准，定位问题层级并清点同类分支从共享机制根源一次性成批闭合，复用输入未变的有效证据、只复验受影响部分（严禁逐个报错叠局部补丁），按轮更新一行纠偏要点；直至双方独立验收通过后真实勾选 `[x]`（首轮零返修直通则于验收通过时勾选）。
> 3. **压缩、中断与连败即时校准及防空勾核对。** 不设按固定时长打断心流的机械定时复读；但任一工序中途一旦发生**上下文压缩、会话中断续接，或同一问题连续两次修补未果/衍生次生缺陷**，实施方须立即停手，重新通读《高效工作方法》全文、深入理解其本质并按其校准后续做法后再继续。所有门禁严禁无内容空勾，亦不写长篇过程复盘；搭档在派发、收审与退回时同步核对门禁已真实执行。
