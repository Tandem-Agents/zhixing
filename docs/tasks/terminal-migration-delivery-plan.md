## 一、已确认的方案

**保留现有主架构和产品契约，不插入独立的单机/跨端解耦项目，不替换存储引擎；完成仍成立的有界状态、恢复和终端功能体验缺口。**

必须守住用户的顶层要求：架构面向未来、品质优秀；用户用得简单、便捷，不承担内部复杂度；既有单机与跨端功能及体验不降低。普通启动、打开会话、首发准备不能反复处理全部累计历史；冷启动同条件中位数约5～7秒，允许波动。性能、功能、安全、耐久及终端与核心解耦必须同时成立。

本次长期收尾中，能够明确识别的工作主要涉及原有全量历史重放/物化的读取与恢复结构迁移；跨端相关责任是其中一部分，重复验证、错误归因、方案返工和接力又增加了成本。尚无完整工时分解，不把这一判断伪装成精确比例，也不以提交触及包数证明跨端是普通迭代的主要放大源。

选择当前路线，是因为独立解耦的额外净收益尚未得到足够证明，而激活、迁移和双路径维护成本明确存在；现有领域端口和持久索引可以承接已确认的改进。这仍包含查询、状态及恢复边界的架构修复，不是只改流程，也不是认定现架构完美。

共同责任、信任域责任、拓扑适配作为责任检查框架，不新建三套平台，不按机器数量或字段名删除本机仍需的权限、票据、代际隔离、资源准入与恢复。跨端功能及其验收义务完整保留；是否已做真机验证不作为架构方向选择依据。

**重开条件：** 实际普通需求被证实必须穿透不相关领域，或当前结构不能满足增长/体验要求时，按具体证据重开对应关键边界。普通实现问题自行闭环，不因每个困难重新讨论整套架构。

**2026-10-20战略复核：** 保留跨设备的用户价值，不把既有技术规格等同唯一实现；本次不以Reason Network替换全部运行底座、不裁功能、不插入外部执行者或通用迁移平台。网络和执行实现保持可替换，权威移动的来源、任期和承接责任应由共享边界承担。具体源码依据、取舍及未证风险见上述研究；下文规则只随当前任务处理实际越界，不承诺零领域工作或近零维护成本。开发通信改进单独安排，不夹带进产品性能包，也不因研究结论自动安装或切换通道。

### 本次路线调整的依据与完成边界

总控与战略架构师于2026-10-19分别独立分析并完成集中交叉审查，共同认可本次顺序与范围。原1b三项均有生产可达依据，但分组并非固定答案：G08/C10面向会话集合，G09余项与G24/G25共同面向打开长会话。已证交互阻塞前移，避免后续工程建立在未解释的异常等待上；这不预先证明写入底座必须重构，也不承诺机械减少固定轮数。

**前置包的完整交付：**

1. 复用现有正式日志与旅程，按接纳、派发、执行、提交、发布、显示拆账；区分模型/测试器等待、系统必要工作、排队和维护。聚合耗时不能冒充逐事务物理写计数，补证优先用已有手段，必要时只加针对性的临时诊断。
2. 在根因所在位置完成修复，包含为关闭它不可分割的直接依赖；若覆盖了后续包的某项义务，将来源、范围和完成证据写入问题台账，后续包扣除已完成部分。不能借转移扩入整个后续包，也不能以“归后续包”延后已证直接阻塞。
3. 前后版本各自冻结并标明源码/构建身份，在同一合成home或等价固定资料、无诊断钩子条件下拆账对照，证明已证异常等待被消除；修复范围内的剩余成本可解释为必要工作，不含累计历史、重复持久化或同步等待无关维护造成的放大。不以本包关闭宣称所有后续领域增长已经解决。
4. 功能F和本次必要触及项增加，可以带来有解释的成本；不要求任意投影数量下都维持一个常数。既有K准入、耐久成功、故障恢复、读者保护和认证校验不降低；受影响的B2/1a反例及增长证明保持，未失效证据复用。
5. 整轮实现、自审后集中构建；真实入口首发→思考/正文中断→续聊→配置往返→退出及同Host热入完成，亲看实际画面，核对正式错误和资源收尾。前置包不承担包7的约10次最终采样或C8全面对照，也不能通过提高超时掩盖原失败。

**1b与2的架构边界：** G08的pending发现由推进义务所有者维护，不能把“active”当全部恢复责任；C10保持现有会话目录事实来源，派生目录可校验、可恢复，覆盖跨写者与崩溃中点、旧资料初建和离线只读。现有per-id进程内锁不等于共享目录事务，不按原语名字禁止复用DPI，也不另建事实源。G09直接查询符合既有可见语义的输入集合，不能靠倒序扫描全部时间线再过滤已消费项；已验base/tail及clear/delete边界持续保持。具体字段、索引键和函数拆分由工程师自主决定。

**2026-10-20前置包R4集中返修边界（双方确认）：** 保留R3有效收益，控制准入/候选生命周期、过程来源接续、修复范围内关键路径等待三项在同一轮闭合，不预设同根。先证明采样缺失和候选失效原因，在现有统一仲裁器、许可、检查点与外层重驱机制内修复；不放宽完整occupancy/quantum、授权和永久故障边界，不预建Host常驻控制池。控制目标保持精确有界，允许必要物理读取；快速反馈、实际止损、耐久接收与最终结算分责，正常取消保持owner记账下发，有效abort票据仅按既有授权和适用条件复用。原始流合法性由既有校验器负责，当前来源由owner权威证明，展示端保留生命周期/迟到帧防护；不得把合法epoch前进误判为gap，也不得拼接不同来源的旧前缀。决定性反例与实际旅程证明修复，受影响机制复验、有效证据复用；不机械增加固定连续通过次数，不以延长超时或重跑通过代替根因关闭。必要固定成本可在明确归属后留包7，不把当前中断/展示失败推后。

**包7的交互参照：** 在可比夹具上分别运行C8旧格式合成资料与当前升级副本，比较首回、中断收束和续聊的系统分段耗时；不差于C8，或差异由可验证的新增必要工作解释。保留不可比项及原因，不把功能缺口或不同路径伪装成公平对照；不减少既有产品能力，也不以这项对照替代当前冷启动中位目标。

## 四、共同完成门与成本控制

- **来源与业务责任分开**：原生业务保持原事实与规则；完整home迁居/灾备的来源、安装、日志视图、当前owner/任期由共同边界提供；收编的认证基线、来源命名、转移状态机及原子发布由承接机制负责。领域继续负责业务映射、合法性、兼容与恢复，不把来源协议各自复制一遍。
- **边界是目标，不是免费承诺**：领域种子可以分页、读取必要制品并保存恢复进度，不冻结为“一个纯函数”；新增业务状态仍可能需要删除/clear、历史exact及回归。设备管理、信任、工作区的设备身份是合法产品语义；禁止的是普通业务自行用物理设备、导入记录或epoch猜测迁移代际与当前权威，不是一律禁用这些字段。
- **按实际越界修复**：上述约束纳入原任务的实现与审查，不新增全面审计轮次、不提前改造全部领域、不在前置长尾包夹带通用平台。共享边界确实无法承担直接义务时，按证据交总控与架构师判断，不以任意“几个包”阈值自动改变产品范围。
- **普通与升级分开**：现有索引复用/兼容转换、新索引初建、损坏修复分别记录。新二进制不等于全部新索引；不因版本号变化机械全库重建。
- **增长责任在本包关闭**：固定当前选择/活跃量/内容预算，增加已完成历史；有界读取、物化与保存/停止成本都要有依据。只对受影响增长机制做规模证明，不要求纯接线/UI包也全套做。
- **性能持续观察**：每个影响启动的后端包复用真实旅程取得可比冷启/常驻Host热启样本及阶段账；不固定复制3～5次，按可疑回退/判断不清再扩样。各包允许保留后续负责的明确成本，但不得丢失归属；7承接整链成本。
- **样本可比且不丢证据**：样本标明真实构建身份，版本对照保持夹具/配置可比，不与构建测试争抢资源；同版中位数不混构建。无钩子样本用于体验与验收统计，诊断插桩数据单独列账用于定位，不能混入达标中位数，也不能删除慢样本。
- **验收后的代码回退点**：每包验收后形成可审查、可按提交规范独立保存的成果；已有明确Git授权则依授权执行，没有授权则保留并交用户决定，不自动stage/commit/push，也不重复索要已获授权。不机械一任务包一提交，不新增逐包必停审批。代码回退点不等于承诺用户数据可降级。
- **变更必须随责任包收口**：每包交付时列明本包文件/变更块、验收状态与可提交范围；不能只关闭问题名称，却留下无法独立提交的半成品。跨包依赖须明确承接，当前包仍要构成完整终态。最终交付前核对全部范围内产品变更，不能留下归属不明、未完成或验收未通过的产品代码。“可提交但尚未获Git授权”与“不能提交”必须区分。文档按内容价值处置：长期有价值的需求、决策、根因、方案及未完成责任归入正式文档随成果提交；重复聊天、过时交接和无价值临时内容删除，不继续留下既不提交也不清理的资料。
- **每包自审后集中构建验证**：修改上游按现有要求全量构建，随后确认实际入口产物；不每个小改动构建，不在总控审查时继续改候选。
- **独立且完整**：总控审查覆盖全部义务与交界，复用未失效的既有测试，独立执行必要反例和用户路径；不以抽查代替完整责任，不机械复跑全部命令。
- **组合风险前移到当轮验收**：修改涉及锁、队列、容量、后台维护、初始化合流或恢复时，总控须审查实际持有/等待/唤醒关系、重试及观测放大、取消与停止收束，并以受影响的确定性交错和真实入口验证。严重慢样本不得以中位数、偶发、局部改善或最终能运行为由放行；先关闭其触发机制和当前责任。关键架构取舍、复杂跨机制原因或修法可能破坏既有增长/安全/耐久时，及时由战略架构师共同审视，总控仍承担独立判断和最终验收责任。不因此机械增加全套测试、全面审计或逐细节会签。
- **功能与运行形态**：相关运行/assignment、生命周期/授权及权限/安装边界在所属包完成本机/mesh等价与相应故障回归；真实用户路径依既有终端交付边界执行。跨端未验收不作为方向依据；缺少其他物理设备不新增当前模块阻塞，不能据此声称已实测。产品发布的其他平台/跨端真机与npm流程仍归既有发布计划。
- **停止条件**：范围内已知可达问题闭合，必要验证及当前性能/增长要求成立，总控整轮验收通过即结束；不继续为未来假设增强。没有证据的旧疑虑区分为未知，不冒充现存缺陷，也不冒充已经通过。

### 已验收增长约束的持续保持（强制）

依据用户2026-10-17明确要求：先彻底消除累计信息增长造成的准备放大，允许随后继续优化固定开销，但不能在两类问题之间反复折返。本规则适用于后续所有相关任务包及包7的整链优化。

1. **关闭后成为后续约束。** 每个增长机制验收关闭时，记录已关闭范围、有界条件及对应证据。后续修改必须保持这些约束；尚未处理的领域继续按既定任务包闭合，不把局部通过写成全部增长问题已经解决。
2. **优化不得重新引入历史依赖。** 后续可以优化装配、重复操作、等待和必要读取，不能重新引入全部累计历史的扫描、重放、物化或整份缓存加载，也不能将其转移到打开会话、首次发送、运行控制或保存/退出。功能、体验、安全与耐久义务同时保持。
3. **回归由引入它的整轮负责修复。** 修改触及已关闭机制时，工程师须在整轮集中验证中复用其回归用例和工作量对照，必要时补反例；总控独立核验。发现增长约束被破坏，该轮不得验收通过，必须修复并复验，不能留到以后重新立项。新证据推翻旧结论时须如实更正，不能以曾经通过掩盖缺陷。
4. **验证成比例，不制造重复劳动。** 固定当前配置、活跃量和内容预算，增加已结束历史，核对受影响路径的读取、物化及保存工作量；没有影响的有效证据继续复用。不为每个小改动全量构建或重复完整性能批次，不以耗时偶然较快替代增长证明。
5. **同一版本同时交付两项目标。** 增长改造后的阶段版本可以继续收敛固定耗时，但已关闭的增长约束持续有效。最终同一候选必须同时满足增长约束、冷启动同条件中位数约5～7秒（允许波动）及完整功能体验；旧版本的达标成绩不能替代新版本验收。工程师提供证据，总控据此放行。

## 五、角色、交接与终点

- **总控：** 把控宏观进度；负责架构设计、任务安排、整轮代码审查、问题汇总交付及最终验收。
- **工程师：** 负责执行，在已确认边界内思考实现方案，完成整轮实现、自审、集中构建与验证；对总控负责，只联系总控，不自行协调其他角色。
- **智能体架构师：** 与总控平级贡献独立判断，参与关键决策、关键选择、架构选择、关键问题分析及执行路线与任务拆分的把关；不承担普通实现细节。

**每次正式向工程师派发整轮任务前，总控与智能体架构师必须共同审视。** 这是用户2026-10-19明确的派工规则，不只限于重大架构变更。先回到整个产品和一级交付目标，判断任务是否必要、方向与边界是否正确、怎样高质量且高效率完成；双方分别独立思考，总控核实事实，不把对方当确认者，不为一致而妥协。

架构师的视野不受总控初稿、旧分包、文件清单或技术选型限制，可以质疑前提、改变顺序、调整范围，甚至判断任务无需实施。双方认可真实执行路径后才交工程师；计划变化更新回本文原位置。已证且未变的事实可复用，不机械重复调研；具体字段、函数与普通实现细节交工程师自主处理，不逐点会签。已派发且完成双方审查的正常任务不因新增约定而被零碎打断。

**关键问题必须及时共同解决，不限沟通轮次。** 复杂或棘手问题，以及关键决策、判断、架构与关键审查，必须及时请战略架构师参与；总控对其意见不清楚或不认可时，双方继续以证据独立分析、质询和优化，不能因“已经问过一轮”停止，也不能未经判断直接照搬。结束依据是实质分歧已澄清、方案符合需求且工程师高质量高效率完成的方法已明确。战略架构师承担高价值判断，普通实现细节不逐项咨询；不以增加轮次代替进展，也不为控制次数跳过必要协作。

总控与工程师严格串行：整轮实现交回→总控独立完整审查→集中交付问题→整轮返修与复审，不并行改动候选。工程师只对接总控：Codex工程师使用既有原生会话通道，外部工程师使用已登记通信桥；执行者以用户最新指定为准。总控与智能体架构师已于2026-10-20启用原会话自动通信，手动信箱仅作故障时的明确降级；入口与实测边界见[通信通道登记](../../.agents/skills/cross-agent-communication/references/codex-claude.md)。传输自动化不改变角色、审查和串行安排；发出需回信的消息后，按[协作规范§3.4](../workbench/cross-session-collaboration.md#34-消息文件与通知文件通道)向用户说明具体交付事项、收件角色与等待状态。

终点是整个终端迁移按既有需求可交付，而非只完成某个索引、某个启动样本或计划表。达到范围内完成门后结束，不追加未来功能与无依据增强。

总体方案依据为用户2026-10-17确认；2026-10-19顺序与分组调整、2026-10-20外部能力及责任边界复核均经双方独立分析和交叉审查认可。原始讨论分别保存在本机协作目录 `collab/threads/20261017-single-multi-strategy-8e1a/`、`20261015-startup-final-closure-c7b2/package-1b-direction/` 与 `20261020-reason-network-strategy-69dd/`；后续执行统一引用本文。
