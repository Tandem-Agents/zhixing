# Windows 应用状态目录迁移：权限、目录联接与持久化绝对路径

把一个桌面应用的状态目录（会话、数据库、缓存）从系统盘迁到其他磁盘时，“文件复制成功”只是第一步。本复盘总结迁移中实际遇到的三类遗漏，以及对应的核对与处置方法。

## 一、迁移过程中暴露的问题

1. **权限变宽。** 按“复制数据、跳过目录联接、不复制 ACL”的方式复制后，新目录继承了目标磁盘根目录的权限，比源目录宽：本机其他用户可以读写登录与会话数据。处置：
   - 新目录根断开继承，按源根重建权限主体，向全树传播；
   - 逐项补齐源目录里的特殊显式权限，包括拒绝项，以及指向已失效 SID 的条目。工具解析不了失效 SID 时，直接按 SID 授权。
   - 复制时被跳过的目录联接，手工重建并改指新位置。
2. **旧目录无法改名（拒绝访问）。** 树内文件都能改名，没有应用进程，杀毒与索引服务空闲。最后通过枚举资源管理器窗口，发现有一个窗口停在旧目录里，持有句柄。正常关闭该窗口后改名成功，没有强杀任何进程。
3. **重启后历史会话全部打不开**（报错显示旧绝对路径的文件不存在）。数据在新位置完好，环境变量也已生效。根因是应用的状态库把每条历史会话的文件路径存成了旧绝对路径，恢复功能按库里的路径找文件。这是迁移遗留的绝对路径引用，不是数据丢失。
   - 处置：在旧路径建一个指向新目录的目录联接（权限按旧根复制），一处联接覆盖全部存量引用。
   - 未采用的方案：批量改写状态库里的路径前缀，直接但有写库风险；放任不管，历史会话全部不可用。

## 二、验收与收尾

- **完整性**：两侧 SHA-256 清单（文件与目录数）完全一致。
- **权限**：全树有效 ACL 与源逐项比对，零差异。
- **可用性**：旧路径经联接可以解析全部仍然有效的历史引用；新会话写入新位置，旧位置不再产生实体文件。
- **清理旧副本**：确认验收通过、不再需要回滚后再删。删除前先移除旧副本内部指向现用数据的目录联接，避免递归删除误伤现用数据。兼容联接本身不保存数据，但不能删，删了旧路径引用会再次失效。

## 三、经验

- **复制成功不等于迁移完整。** 文件内容、权限、目录联接、持久化的绝对路径、新旧数据的读写，要分别核对。“全树有效 ACL 逐项相等”适用于同机迁移、保持原有权限的场景；其他环境不必照搬具体主体与配置。迁移目标也应先核对磁盘上已有的目录约定，避免新建撞名目录。
- **绝对路径是迁移的隐性债务。** 应用状态库里存的路径不会随环境变量自动迁移；在旧路径建目录联接，是成本最低的兜底。它仍有目标、权限、生命周期与清理上的风险，不是零风险保证；只对仍使用旧路径、且能经联接访问的组件有效。
- **文件占用要观测定位，不猜、不强杀。** 单凭“拒绝访问”定位不了占用者，要结合句柄或窗口枚举等直接证据，并以“关闭后操作成功”作为确认。
- **区分清理对象。** 旧副本、旧副本内部的联接、现用数据是三个不同对象；清理旧副本前，先断开它内部指向现用数据的联接。
