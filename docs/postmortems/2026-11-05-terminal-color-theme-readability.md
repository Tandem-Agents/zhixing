# 终端颜色只在深色背景下核对过

## 现象

正文阅读层级给三级标题选了 ANSI 15（亮白），想让它在深色背景下比正文更亮。方案审过，单测和原生场景也都通过。直到用浅色调色板拍真实终端画面，才发现它完全看不见：多数浅色方案把亮白定义为纯白，背景又是近白。

同一组画面还暴露了一个既有问题：行内代码底色与用户消息灰底用固定的 256 色第 236 位深灰，在浅色背景上配深色前景字也读不清。

## 原因

- 颜色是在深色方案里凭观感挑的，没有在浅色方案里核对。终端界面只能借用宿主调色板，同一个色位在不同方案里的明暗可能完全相反。
- 原生测试只核对色位编号，无法判断可读性。可读性只有在真实调色板下的画面里才能看到。

## 可复用的做法

- 需要阅读的文字，前景只用两类：宿主默认前景，或有彩的语义色位（1～6，必要时 9～14）。0、7、8、15 是黑白灰色位，在明暗方案里会互换明暗，不用于必须读清的文字。8 只用于弱化的装饰，比如框线、分隔线、提示。
- 底色不用固定的 256 色灰阶。它不随宿主明暗变化，在另一种背景下要么看不见，要么压住前景字。
- 选色在设计阶段就验证，验证要便宜：在真实终端里用 OSC 4/10/11 只改当前标签页的调色板（16 色与默认前景、背景），先后拍深色、浅色画面再定方案。标签页关闭后就失效，不改用户的终端配置。
- 审查颜色方案时，把“深浅两种背景下都可读”写成完成条件，并附两种背景的画面。
