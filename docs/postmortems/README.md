# 失败复盘与可复用教训

遇到诊断反复、架构误判或效率失控时，按下表查找相似信号，阅读对应复盘的原因与适用边界。这里用于改进下一次工作，不是事故流水账；历史实现与耗时不作为当前状态。

| 遇到的信号 | 可借鉴的经验与复盘 |
|---|---|
| 一条CLI路线失败就断言整体做不到，外围桥接反复重写 | [通信能力误判](2026-10-20-agent-communication-capability.md)：区分能力边界与搜索边界，重审变化的约束，以原会话关联回复验证闭环 |
| 真实输入不明，反复扩字符处理范围仍失败 | [起首空行诊断](2026-05-07-anchor-empty-line.md)：取得输入证据，区分视觉规范化与显示宽度，检查合法字符边界 |
| 改动后仍失败，或换宿主后文本输入消失 | [构建与输入分流遗漏](2026-05-14-confirm-input-paste-misroute.md)：核对实际运行产物，按调用者协议消费输入，区分修复依据与原因假设 |

| 过滤构建去构建了被排除的包；构建报 terminal-ui `spawn bun ENOENT`；测试报“X 不是 X 的实例”；代码没变却成片失败 | [小写盘符工作目录](2026-10-24-lowercase-drive-letter-cwd.md)：先读构建日志第一处异常，怀疑模块重复加载；昂贵验证前用 node 核对工作目录盘符，构建失败即中止整条链 |
