# 2026-05-20 · 确认面板退出后输入冻结：资源交接与诊断维度遗漏

这是 Windows CLI 输入故障的诊断复盘，适用于切换组件后功能失效、状态快照却看似正常的场景。以下过程与成本来自历史记录；已观察的故障和修复效果不等于 ConPTY 内部故障机制已被独立证实。

## 现象与诊断轨迹

直接对话的 turn 1 输入正常；turn 2 调工具并退出确认面板后，字符、Ctrl+C、Esc 和斜杠均无响应，只能强关终端。allow、deny 和 Ctrl+C 取消都触发，因而不应只追查取消分支。

| 阶段 | 当时动作与观察 | 诊断得失 |
|---|---|---|
| 1 | 反复追踪 stdinOwnership、rawModeController、batcher 和闭包 listener | 从“代码看来应该正常”得不到真实输入仍在流动的证据 |
| 2 | 用户补充 allow 也失败、Ctrl+C 也失效；增加挂起、恢复和键盘交接观测 | 将范围从取消特例转向面板共同退出路径，是关键缩小范围的信号 |
| 3 | 第一份日志停在 detach；怀疑异步缓冲丢尾，改同步追加后再次取证 | 第二份日志仍无后续按键；缓冲丢失是需检查的可能性，不是原日志断尾已被证明的原因 |
| 4 | 增加 flowing、paused 等字段与周期采样；约 32 秒、60 条快照均看似正常，但无按键事件 | 说明现有快照不足以解释功能，不证明应用代码无错或 OS 已被定位 |
| 5 | 对比 raw mode 引用计数交接，改为跨面板保留物理资源租约 | 修复后日志显示挂起时 raw 保持开启，面板退出后 backspace 等重新触发事件 |

历史快照显示 `isRaw=true`、`isPaused()=false`、`flowing=true`，keypress/data listener 数各为 2。但 listener 数量不能证明身份、顺序和消费链正确，状态终值也不能还原中间发生过的资源重置。

## 关键取舍：保留物理资源，交接输入订阅

当时对照的资源轨迹：

```text
旧路径：
typeahead.suspend 释放租约 → 面板获取 → 面板释放 → typeahead.resume 获取
引用计数 1→0→1→0→1，期间反复关闭/开启 raw mode

修复路径：
typeahead 挂起仅摘输入订阅，保留 raw mode 与 stdin ownership 租约
面板叠加获取、退出释放；typeahead 恢复订阅
引用计数 1→2→1，面板交接期间不关闭 raw mode
```

当前 [typeahead](../../packages/cli/src/typeahead-input.ts) 的 `suspend`/`resume` 仍保留这一边界：[确认面板](../../packages/cli/src/security/select-operation-region.ts) 获取自己的租约，挂起不等于销毁输入资源；最终生命周期结束仍应释放。现行职责由 [CLI 选择与确认](../modules/cli/selection.md)说明。

旧记录将原因直接归于 Windows ConPTY 快速 raw-mode 翻转产生的死锁。现有证据支持“避免这段翻转后，所观察的输入冻结消失”，但没有独立的 OS/ConPTY 层证据排除其他交接因素。即使源码注释沿用该解释，也不能据此把推断升级为独立验证结论。

共享资源只有在交接期间确需连续、且调用者允许重叠持有时，才应保持租约重叠；也可以在有必要时显式交接所有权。不能推广成“引用计数永不归零”，也不要求为所有资源建立新 handoff 框架。

## 成本与方法复用

旧记录统计用户复现 4 次、约 8 轮对话、3 次观测面扩展，最后修复交接路径。用户提供的“不同退出选择都失败”和“全部按键无响应”本可更早用于设计有区分力的观测。更有效的路径是先比较共同路径及事件到达情况，但不能保证一次复现便定位 OS 原因。

关联复盘已有启示，但须按实际内容复用：[起首空行](2026-05-07-anchor-empty-line.md)说明先取得真实输入；[输入分流](2026-05-14-confirm-input-paste-misroute.md)说明核对构建和调用者协议。

## 行动转化

| 信号 | 应采取的动作及边界 |
|---|---|
| 指标正常但功能失效 | 检查指标覆盖盲区，沿输入产生、事件到达、消费和显示链取证；结合宿主操作，不能停止所有应用层检查 |
| 无面板正常，经过面板后冻结；不同选择都触发 | 对比共同交接路径和资源生命周期，避免把所有注意力放在某个取消分支 |
| 交接的终态相同，中间经历释放再获取 | 确认重置是否破坏必要连续性；有依据时保留重叠租约或传递所有权，并验证最终释放 |
| 强关后日志断尾 | 分别检查事件未发生、日志未提交及进程终止；按现场需要改善写入/刷新，同步追加也不保证硬终止前所有事件或持久化数据完整 |
| 诊断反复且已有相关案例 | 按[复盘索引](README.md)的信号挑选匹配经验，检查前提；不要求每次扫描所有正文或机械套用历史方法 |

诊断设施应服务于当前证据缺口。周期采样和同步写入是本案采用过的手段，不是所有 CLI 调试的默认强制机制。
