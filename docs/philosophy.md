# 知行哲学

只收录贯穿项目全周期、指导根本取舍的思想，不收具体功能、实现方案、阶段计划或空泛口号。

## 产品哲学

- 知行服务于人的生活与工作，长期走向陪伴在身边的智能，而不是停留在打开才能使用的工具。
- 从用户的真实需要出发选择技术，不让技术定义产品；外部优点只有符合知行方向才值得吸收。
- 适应用户的真实环境与使用方式，不要求用户迁就系统。
- 以完整兑现用户价值为尺度，而非功能数量；可以缩小范围，不能降低承诺范围内的质量。

## 架构哲学

- 产品不依附于特定模型、界面或设备；实现可以更替，产品的完整性不能因此受损。
- 让模型充分发挥智能，而不让系统的可靠性依赖模型永不犯错。
- 用满足真实需求的最简单完整结构承接变化，不为未知未来预建复杂度。

## 体验哲学

让用户只关注值得他关注的事，系统自身的复杂度由系统承担。
