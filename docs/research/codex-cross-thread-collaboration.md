# Codex 跨会话协作能力调研

依据：2026-09-16 当前 Codex 桌面环境提供的 `codex-app-tools` 工具说明与参数合同。以下接口省略统一前缀；能力范围不外推到所有版本或客户端。

## 核心能力

这里的“任务”是用户可见的对话（thread），不是单条待办，也不等同于后台子智能体。

| 能力 | 接口 | 核心语义 |
|---|---|---|
| 找到其他对话 | `list_threads` | 列出对话的 ID、标题、状态、项目及可用摘要；已有对话也能成为协作对象，不要求由当前对话创建。 |
| 阅读其他对话 | `read_thread` | 无须打开页面即可读取状态、轮次摘要，并分页读取更早内容；可附带截断的工具或命令输出，不保证取得完整逐字历史。 |
| 发送消息、继续任务 | `send_message_to_thread` | 向指定对话发送后续指令，让它继续工作；消息在目标对话中对用户可见。可保留其模型设置，也可按请求调整 Codex 任务的模型和推理强度。 |
| 新建任务 | `create_thread` | 在用户明确要求新建时，创建独立、用户可见的任务并传入初始指令；可绑定项目，选择原工作目录或独立 worktree，也支持无项目任务。创建是异步的。 |
| 从已有上下文分叉 | `fork_thread` | 从当前或指定对话复制已完成的历史，形成新对话；不复制正在进行的轮次及未完成回答。可共用目录或使用独立 worktree，再发消息继续执行。 |
| 等待结果或求助 | `wait_threads` | 一次等待最多 8 个 Codex 任务，任一完成或需要关注时返回；也可立即读取进度快照。游标避免重复返回已读结果，8 是单次等待上限。 |

## 如何形成协作

对话 A 找到 B，读取其状态，发送目标与材料；B 在自己的上下文中执行，A 等待或读取结果，再决定下一步。双方具备相应工具与授权时，也可主动向对方回信。执行与审查、并行分工、接力推进都是这些接口的组合，不需要先绑定固定的团队角色或流程。

## 关键边界

- **消息不是共享上下文。** 发送消息不会自动复制发送方全部历史；必要背景须随消息提供或由接收方读取。分叉继承的是过去的快照，不是后续同步。
- **发送成功不等于完成。** 结果通过等待、读取或明确回信取得；不能把发送接口当成同步返回工作成果的调用，也不能假定对方会自动回信。
- **独立对话不等于文件隔离。** 共用目录时仍操作同一批文件；worktree 隔离代码工作树，成果仍需整合。跨会话工具也不等同于当前任务内的 `spawn_agent` 子智能体机制。
- **运行位置迁移不是消息委派。** `handoff_thread` 搬迁另一个任务及其 Git 状态，运行中任务会先被中断；不是把一条工作请求交给另一对话。

因此，这组能力提供的是“可定位的对话、可见的消息、可读取的上下文与可等待的执行状态”。协作关系由用户和任务组织，而不是接口预设。知行的方向思考见[多智能体机制梳理](agent-concepts-and-multi-agent-direction.md)。
