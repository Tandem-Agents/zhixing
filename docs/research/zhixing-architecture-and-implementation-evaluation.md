# 知行架构与实现综合评估（对比 DeepSeek Harness 与 OpenClaw）

日期：2026-11-12。性质：架构与工程实现评估研究，供技术审视与后续演进取舍参考，不替代产品需求、架构权威或发布验收合同。

评估基线与证据边界：

- **知行（Zhixing）**：基于当前仓库 `0.1.0` 开发基线的 18 个包真实生产源码（`packages/` 下排除测试与 `test-utils` 共 1,270 个 `.ts`/`.tsx`/`.c` 文件、约 40.5 万行代码）、构建与门禁脚本，以及[架构概述](../../research/design/architecture/overview.md)、[AE-001 伴身智能架构演进](../../research/design/architecture/evolutions/AE-001-companion-intelligence.md)和[首发推进方案](../delivery/first-public-release.md)核实；未参考正在改写中的根入口文档。
- **DeepSeek Harness（`dsh`）**：基于 `v0.1.0-rc.7`（提交 `99f6f02`）的[架构调研基线](../../research/knowledge-base/deepseek-harness-architecture-research.md)核对。
- **OpenClaw**：基于 `2026.8.1`（提交 `5e3e524`）的[架构调研基线](../../research/knowledge-base/openclaw-architecture-research.md)与提交 `6be1a9675da0` 的[通用自主性研究](./openclaw-autonomy.md)核对。

## 1. 核心结论与评分标尺

### 1.1 标尺定义（0–10 分）

为避免分数膨胀，三个项目统一映射在同一套系统工程标尺上：

- **9.5–10.0 分**：架构纯粹、复杂度与问题规模严格匹配、无已知结构债务，且经受过大规模跨平台真实负载长期检验的教科书级系统。当前个人智能体领域尚无项目达到该区间；即便以工业界成熟度标杆 OpenAI Codex 作参照，在同一标尺上也约为 **8.8–9.0 分**。
- **8.0–8.9 分**：第一梯队顶尖工程水准。具备自洽且领先的架构主见，核心状态、安全与运行机制真正做成了闭环系统工程；扣分主要来自实现体积代价、局部迁移收尾未竟或跨平台实战覆盖缺口。
- **7.0–7.9 分**：在特定方向（如生态触达或插件灵活性）表现突出，但在状态权威、正确性底座、故障隔离或成品成熟度上存在明显折衷。
- **5.0–6.5 分**：常见的拼装型开源智能体（将模型调用、工具循环、轻量存储与聊天 SDK 直接串接，并发、中断、恢复与权限边界缺乏系统级保证）。

### 1.2 综合得分与生态位

按**“从顶层架构到底层实现”**加权评定：

| 项目 | 综合得分 | 一句话定位 |
| --- | :---: | --- |
| **知行（Zhixing）** | **8.4 / 10** | **系统工程底座最硬、长期演进上限最高的“伴身智能基座”**：架构与正确性底座已达 8.9–9.1 水准，当前主要被 40 万行级重度实现与首发前跨平台真实验证缺口拉回 8.4。 |
| **DeepSeek Harness** | **8.1 / 10** | **插件组合模型最优雅的“智能体元运行平台”**：空间依赖与可逆生命周期设计领先业界，但概念与装配复杂度高，且仍处 Developer Preview。 |
| **OpenClaw** | **8.0 / 10** | **当前最成熟的“全渠道个人助手成品”**：赢在聊天入口广度、跨端节点触达与角色提示驱动的自主办事体感，短板在中心化 Gateway 耦合与较软的正确性/沙箱默认边界。 |

## 2. 六维评分矩阵与逐维依据

### 2.1 评分总览

| 评估维度 | 权重 | 知行 Zhixing | DeepSeek Harness | OpenClaw |
| --- | :---: | :---: | :---: | :---: |
| 1. 顶层架构与职责边界 | 25% | **8.8** | **8.8** | 7.9 |
| 2. 正确性、持久恢复与安全底座 | 20% | **9.1** | 8.0 | 7.3 |
| 3. 智能发挥与长程自主推进 | 20% | 8.3 | 8.1 | **8.6** |
| 4. 交互表面与端到端体验工程 | 15% | **8.6** | 7.8 | 8.5 |
| 5. 实现收敛度与可维护性 | 10% | 7.4 | **7.9** | 7.4 |

| **加权总分** | **100%** | **8.4** | **8.1** | **8.0** |

### 2.2 逐维对比分析

#### （1）顶层架构与职责边界（25%）

- **知行（8.8）**：确立了极清晰的“一心多身”母架构——产品语义与状态机归属 12 个垂直领域，[ProductApiDispatcher](../../packages/core/src/product-api/catalog.ts) 在构造期 `Object.freeze` 密封精确操作集（26 Query / 44 Command / 11 Fact Event），认知推理收窄为只产出提议与证据的 `Intelligence Kernel`，外部后果统一走“领域裁决 → 权威提交 → 安全/确认/资源准入 → 受控效果 → 证据提交 → 表面投影”，唯一组合根 [PersistentApplicationHost](../../packages/cli/src/serve/application-host.ts) 退出业务调用链，并由 [s7 架构门禁](../../scripts/s7-entry-coverage.mjs)做 AST 级入口覆盖与写权限守卫。未给到 9.0+ 的原因是 AE-001 的最终复杂度清理（A7）尚未收官，`@zhixing-ai/core` 子路径与 `packages/cli/src/serve/` 物理装配仍偏厚重。
- **DeepSeek Harness（8.8）**：基于 Cordis 同时解决了声明式服务依赖（空间组合）与可逆 Effect/Fiber 清理（时间组合），配合 Profile / Bundle / Preset / Scope 四层装配与“模型可见即已记录”的会话事件流，形成了极自洽的可编程智能体容器。未给到 9.0+ 在于它是**最优插件容器架构而非最优个人助手成品架构**：对终端产品而言概念层级偏多，装配失败采取 fail-loud 拒绝启动，且 Host/Client 因 Context 声明合并冲突必须拆成两套 TypeScript 程序编译。
- **OpenClaw（7.9）**：以单个常驻 Gateway 统管通道连接、路由绑定、Agent/Session 与可插拔 Agent Runtime（内置循环 + Codex/ACP 等外部 Harness），架构极其务实且贴合多渠道助手场景。扣分在于单 Gateway 集中了状态与故障域，且内置 Runtime 与外部 Harness 在工具、Hook、压缩和终态所有权上无法天然等价，适配层长期承受语义裂缝。

#### （2）正确性、持久恢复与安全底座（20%）

- **知行（9.1）**：在个人 Agent 中罕见地按分布式存储与高可靠系统标准构建底座：
  - **存储与重放**：零外部数据库依赖，自研带链式摘要与 SHA-256 帧尾的二进制 WAL（[commit-log.ts](../../packages/core/src/authority/commit-log.ts)）、写时复制持久化 B+ 树投影、CAS 制品库与 A/B 双根对话分片；中断或报错的运行绝不写入持久注意力窗口。
  - **未知副作用诚实结算**：会话运行或外部通道投递一旦因崩溃/超时处于结果未知态，显式定格为 `uncertain` 并要求带乐观锁栅栏的人工消歧，既不静默吞错也不盲目重放。
  - **秘密与跨机安全**：凭据禁读环境变量，统一经 [EncryptedVaultSecretStore](../../packages/secrets/src/vault-secret-store.ts)（AES-256-GCM + Windows DPAPI / macOS Keychain / Linux Secret Service）保护并在内核工具层硬屏蔽路径；网络抓取带 DNS Pinning 防 SSRF；多机采用 SPAKE2+ 配对、双向 TLS 1.3、零丢数计划内值班迁移与 `ZXCP1` 公钥加密灾备检查点。
  - **扣分点**：缺少 OS 内核级命令执行沙箱，已获放行的 `bash` 子进程内部行为仍依赖宿主 OS 用户边界。
- **DeepSeek Harness（8.0）**：append-only `SessionEvent` 保证了上下文可重放，且本地命令默认接入平台文件效果沙箱（Linux bubblewrap/Landlock、macOS Seatbelt、Windows restricted token），这一点优于知行与 OpenClaw；但它不覆盖跨通道投递账本、`uncertain` 副作用消歧、多机值班迁移与离线灾备恢复，且同进程插件与 `node:vm` 动态代码并非安全隔离边界。
- **OpenClaw（7.3）**：具备单会话串行队列、writer claim、SQLite 锁、配对白名单与可选 Docker 沙箱；但默认关闭沙箱、主会话工具直接在宿主机执行，控制面事件流不提供通用重放，跨设备属于中心—边缘命令调用而非可迁移权威系统。

#### （3）智能发挥与长程自主推进（20%）

- **OpenClaw（8.6）**：当前三者中开放任务的“活人办事体感”最强。它通过 `SOUL.md`、`Execution Bias`、`Promised Work`、工具报错恢复指引、插件热变更续接，以及空闲时自动复核并沉淀可复用经验到 Skills 的闭环，让模型主动找路径、遇阻换路并对跨轮次承诺负责。
- **知行（8.3）**：内核循环（[agent-loop.ts](../../packages/core/src/loop/agent-loop.ts)）极其扎实——系统提示词按窗口代际锁定保证 Prompt Cache 字节级命中、结合在途 `task_list` 推迟段压缩避免任务中途失忆、支持 6 种推理思考方言与并发安全工具保序重排；更独创了两项高上限机制：**Advancement**（契约起草 + 独立 Reviewer 模型按客观证据裁定 + 自动代理续推）与**受管扩展自主接入**（模型基于随包 `extension-kit` 编写通道适配）。扣分在于：尚未内置开箱即用的 `web_search`；旧 Memory 清退后暂无跨会话个人经验记忆机制；模型无人辅助自主修包/接新平台的真实成功率仍需更多实战打磨。
- **DeepSeek Harness（8.1）**：`dsh-agent-loop` 极薄，充分释放模型推理，且通过 `cordis_*` 五个工具让模型在当前进程内检查运行时并现场编写、挂载、卸载临时插件与前端插槽，在研发与自演化实验上极具想象力；但缺少面向日常个人助手的主动日程、跨通道投递闭环与独立契约验收机制。

#### （4）交互表面与端到端体验工程（15%）

- **知行（8.6）**：把终端体验做成了硬核系统作品——S/N/U/R 四进程分离（[supervisor.ts](../../packages/cli/src/terminal/supervisor.ts)、C 原生 `recovery` 进程崩溃兜底还原终端状态、Bun + Solid + 定制补丁 OpenTUI + Zig 原生渲染库沙盒 [root.tsx](../../packages/terminal-ui/src/root.tsx)、Windows 后台宿主并行预拉起、超大粘贴滑窗原子编辑、`F2` 离线直读本地历史）。扣分在于当前触达面较窄：仅有极致 TUI 与飞书单通道种子（暂不支持富媒体入站与流式消息编辑），尚无 Web 或移动端原生表面。
- **OpenClaw（8.5）**：单端精细度不及知行 TUI，但赢在全场景触达广度——覆盖主流聊天软件通道、Web Control UI、CLI/TUI 以及桌面与移动设备节点，用户几乎零迁移成本即可在日常软件中使用。
- **DeepSeek Harness（7.8）**：`npx @deepseek-ai/dsh web` 本地 Web 工作台、headless、ACP 与 TS/Python SDK 入口齐全，双端动态 UI 也很有特色，但整体交互形态面向开发者而非全天候个人生活与工作助手。

#### （5）实现收敛度与可维护性（10%）

- **DeepSeek Harness（7.9）**：核心循环与能力包拆分粒度细，依靠自动生成目录图与新鲜度门禁维持大规模插件树秩序；主要维护成本来自类型声明合并、双程序构建与旧代 Preset 资源回收细节。
- **知行（7.4）**：这是知行当前**最突出的失分项**。虽然零外部数据库依赖、零 npm 安装生命周期脚本、门禁严密且核心循环/目录代码干净，但全仓非测试生产代码已膨胀至 **40.5 万行**。为实现严丝合缝的跨设备运行与恢复，分布式状态机与宿主装配出现了显著的巨型文件集中（例如 [conversation-assignment.ts](../../packages/owner-kernel/src/conversation-assignment.ts) 单文件 **13,056 行**、[job-assignment.ts](../../packages/owner-kernel/src/job-assignment.ts) **11,681 行**、[assignment-ledger.ts](../../packages/executor/src/assignment-ledger.ts) **6,514 行**、[command.ts](../../packages/cli/src/serve/command.ts) **3,803 行**、[session.ts](../../packages/server/src/rpc/methods/session.ts) **3,407 行**），单点改动的理解与回归成本偏高。
- **OpenClaw（7.4）**：核心分层清晰，但单仓承载了海量第三方聊天渠道、跨平台节点客户端、多套外部 Harness 桥接与旧格式兼容，外部协议变动带来的日常维护负担极重。

#### （6）产品成熟度与真实环境验证（10%）

- **OpenClaw（8.3）**：已历经多个正式版本发布与真实用户群体的长期在线运行，daemon、doctor、audit、safe mode 等运维链路经受过实战检验。
- **知行（7.3）**：两阶段 npm 发布管线（[publish-npm.mjs](../../scripts/publish-npm.mjs)，分离 `candidate` 校验与 `promote` 升 `latest`）和 5 平台无脚本制品检查非常专业；但客观上 `0.1.0` 尚未正式公开上架，macOS / Linux 真机安装与功能验收、外部通道无交互卡片时的纯文字确认回路等端到端旅程仍待最后闭合。
- **DeepSeek Harness（7.2）**：官方明确处于 `v0.1.0-rc.7` Developer Preview，配置、磁盘格式与插件公共合同均未冻结，不承诺向后兼容。

## 3. 知行的核心壁垒与“1.6 分差距”账单

### 3.1 已经建成的两道硬壁垒（得分根基）

1. **用系统刚性托底模型不确定性**：没有把智能体做成“祈祷模型不犯错的提示词脚本”，而是用密封 Product API、二进制 WAL、CAS、7 级安全管线、串行耐久确认、独立 Reviewer 契约审查和 `uncertain` 显式消歧，保证了即使模型幻觉、网络超时或进程掉电，用户的真实资产与状态账本依然干净可恢复。
2. **吸收外部优点而未沦为“缝合怪”**：面对插件化与自主性趋势，知行守住了“核心封闭、边缘按窄类型合同动态受管”的原则——把外部 APP 接入做成独立子进程 + AST 静态审查 + 外部真实账号双向挑战验证 + 故障自动回滚/转修，既获得了动态扩展的产品价值，又没有破坏核心权威与安全边界。

### 3.2 距离满分 10 分所扣的 1.6 分去向

1. **“底座过厚、上层偏瘦”的重度失衡（约 −0.7 分）**：分布式协同、租约账本、值班迁移和灾备恢复投入了极高代码密度（贡献了数十万行代码与多个万行级文件），而单机用户高频直接感知的能力——开箱联网搜索、更多主流即时通讯软件现成适配、跨会话个人经验与偏好的轻量延续——反而尚未补齐。
2. **架构迁移收尾与局部物理集中（约 −0.4 分）**：逻辑责任虽已按 AE-001 归位，但 `packages/cli/src/serve/` 仍承担过重的组合装配细节，部分迁移期留下的转发层次与大文件复杂度仍待按 AE-001 A7 标准做最终减法。
3. **跨平台真机与野生环境验证未闭环（约 −0.5 分）**：单元测试与静态门禁无法替代 macOS / Linux 实机全链路验收、真实在线模型独立编写/修复未知平台适配的稳定性检验，以及公开发布后真实用户环境的反馈闭环。

## 4. 视角敏感性与适用边界

综合分反映的是“架构与实现整体工程水准”，不同决策问题下三者的优劣排序并不相同，使用时须区分前提：

- **若问“今天普通用户装上就能在各类聊天软件和手机/电脑节点间顺畅使用的成熟个人助手”**：当前 **OpenClaw > 知行 > DeepSeek Harness**。知行需先完成 `0.1.0` 跨平台发布并扩充高频日常通道与搜索/连续性体验，才能在这一维度反超。
- **若问“智能体研究者用来自由拼装能力树、实验运行时自修改与双端动态插件的开发平台”**：**DeepSeek Harness > 知行 > OpenClaw**。知行刻意封闭核心循环与领域模型，不追求成为任意重组内核的元框架。
- **若问“能够长期放心托管个人真实工作与生活、向多设备伴身智能演进而不必推倒重来的系统基座”**：**知行 > DeepSeek Harness > OpenClaw**。最难后补的权威事实归属、崩溃与未知状态恢复、硬件级秘密隔离、四进程原生终端与跨机主权交接，知行已经在首版底座中一次做实。
