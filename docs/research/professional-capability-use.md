# 智能体专业能力的使用形态（草稿）

## 一、问题与需求

不同专业的思考方式、工作习惯、标准和经验，应该怎样参与智能体的实际工作，才能共同提高完整任务的质量与效率，同时避免不必要的信息交接、协调和反复切换成本？需要找到这种专业能力的使用形态，并给出具体、可落地的方案。

## 二、思考方式

**从专业要产生的作用出发，推导让作用真实发生的机制，再用完整工作的结果选择形态。**

1. **明确作用与缺口。** 从真实工作的需求、过程和结果中，辨明专业内容应改善哪些问题识别、判断、行动与成果，以及原设想尚未解决什么。区分增益来自补充知识或方法、让已有能力恰当起效，还是不同判断之间的相互影响，不默认已有专家材料全部有用。设想案例用于检验推理，不能冒充已观察到的效果。
2. **推导真实运作机制。** 说明这些作用何时需要发生、依赖什么信息、怎样相互影响并进入行动，以及怎样获得反馈。关键环节不能藏在“自动识别、综合考虑、共同协作”中。由此形成有实质差异的候选，不先定主体数量、角色或载体；可以包含路径明确的新开发，但不假设未知能力已经具备。
3. **以对照、反例和条件变化择优。** 在相同完整任务与约束下，与现有做法、直接使用现有智能体等可行基线比较，检查是否补上缺口、质量和总投入怎样变化。移除或简化安排以检验必要性，加入新事实或冲突检查能否继续，并考察模型能力变化后哪些安排应保留、简化或撤除。

思考可以往返修正，始终对照已确认的需求，不能把例子变成任务、术语变化当成机制变化，或将原设想未补缺口的版本换名交付。推演用于形成和筛选候选，必要的真实验证用于支持效果判断。最终方案必须讲清完整工作怎样运行、专业增益在哪里发生、代价在哪里、关键依据与适用条件是什么；只有原则或名称不算完成。达到需求且关键依据足够时停止，不追求穷尽所有未来。

## 三、入口方向（待定）

当前更倾向根目录入口。

- **Skill 入口：** 通过技能接入专业体系，引导智能体按任务采用相关专业角色的工作方式。
- **根目录入口：** 以 Guild 根目录作为统一工作入口，由根级宏观角色承接任务并路由至相应专业角色。
