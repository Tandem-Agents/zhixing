# 关键任务记录

## 建立或接续记录

记录对象是用户调用时指定的任务。

**先找现成记录：** 看用户给的路径，或下面位置里同一任务的记录。有就接续，没有再新建。一个任务只有一份记录，开始时告诉用户路径。

**存放位置：**
- 优先用项目已有的任务或临时文档目录；
- 没有的话，项目有 `docs/` 就用 `docs/tasks/`，否则在当前工作目录建 `task-records/`；
- 文件名 `YYYY-MM-DD-<任务短名>-record.md`，短名要让人一眼认出是哪个任务；
- 不放进 Git 忽略或用户看不到的位置，也不登记到长期索引。

记录样式：

```markdown
# <任务名>（临时记录）

## 目标与要求
- 目标：
- 完成条件：
- 约束与授权范围：
- 已知前提与当时条件：

---

## 当前状态
- 更新时间：
- 已确认完成：
- 进行中与下一步：
- 阻塞与未知：
- 关键取舍：

## 执行记录
1. <时间> 环节：<名称>。方案：<做法与依据>；预期：<预期结果>
2. <时间> <动作> → <结果>（<证据>）
3. <时间> <动作> → <偏离的结果>（<证据>）
   - 排查：
   - 归因：
   - 调整：

## 结果
- 实际结果：
- 未完成事项：
- 记录处置：
```

## 登记过程

- **当前状态：** 这是分隔线以下唯一可以覆盖改写的部分。
  - 在关键状态变化时、停顿或交接时、交付前同步更新；只写当前必要的信息，并指向条目号，不复写时间线。
  - “已确认完成”只列有证据的事项。
  - “关键取舍”一栏写对应的条目号。
- **执行记录只追加：**
  - 每个环节开始时，先写一条方案：做法、依据、预期。同一方案下的后续机械步骤不再重复方案。
  - 每步一条，带时间。能从证据确定的，写操作或回执的时间；不能确定的，注明是记录时刻，不要把补记的时刻当成发生时刻。顺利的步骤写成一行：动作、结果和证据。
  - 结果偏离预期时，在该条下展开：排查的假设与已排除项、原因归类及依据、下一步调整。每次失败、重试、转向都单独成条，不能只留下最终有效的做法。
  - 换方案或做关键取舍时，当时就写下：考虑过的选项、选择依据、接受的后果。不要编造没考虑过的选项。
  - 计划了但没执行的，不写成成功；事后补记的，标明“补记”；纠正旧条目时，写新条目并指向旧条目。
- **外部操作只记观察到的事实：**
  - 会改变外部状态、不能直接重做的操作，执行前写一条“准备执行”，写明动作和需要核对的对象或标识。如果所在环节的方案已经写清这些，就沿用那一条；只读查询不用另写。
  - 观察到操作实际发出或对方受理后，才记为已发出或已受理；
  - 没有观察到的，不写成已经发生。
- **证据要在交付时仍能核对：**
  - 会消失或可能变化的（终端输出、临时文件、网页内容），摘录关键原文并注明时间；
  - 持久的给路径或链接。
- **只记事实：**
  - 分清确认、推测和未知，不写内心推演；
  - 只写任务本身的事实与依据，不抄写本技能的规则、自查过程或重复的免责声明；
  - 共同的背景和共同的未知都只写一次，后文引用；
  - 目的相同、结果一致的机械操作可以合并成一条，但不能借合并隐藏失败或转向。
- **上部保持为当前事实：**
  - 目标、完成条件、约束与授权范围，只随用户的有效变更而更新；
  - 已知前提或当时条件被新证据推翻时，按证据改成当前事实；
  - 两种更新都要在执行记录里登记变化内容与依据，这样上部始终准确，历史可以从执行记录追溯。
- **不记秘密：** 不写密码、令牌、验证码等秘密，也不写与任务无关的私人信息；任务必需的账户标识等，按可见范围脱敏后可以记。证据只留必要部分，不整段复制工具输出。
- **中断后恢复：**
  - 先读当前状态和最后几条记录；
  - 记录里只有“准备执行”、或缺少回执的外部操作，不能推断它没执行，也不能推断已执行。先核对实际状态，再决定是否执行，并把核对结果记下来；
  - 接手后先更新当前状态。

## 区分原因

每次偏离都按证据归类，证据不够时不硬归：
- **执行侧：** 自己的判断、操作或能力造成的。
- **外部：** 平台、环境或第三方的真实行为与限制。依据要能独立成立，比如官方说明或可复现的检查。
  - 一条报错本身不足以证明是外部原因；
  - 不能把自己的失误说成平台问题；
  - 外部的正常规则或限制，也不等于对方有缺陷。
- **混合：** 两方都有，分别写出依据。
- **待查：** 只记现象和已排除项，不下结论。

## 收尾

1. **交付前检查记录本身。** 发现缺口先补证据；补不了的，写明“无法取得”及原因：
   - 没参与的人只凭这份记录，能按顺序说出每次尝试、结果和转向的原因；
   - 失败、排查、重试、转向、事实更正都在；
   - 证据此刻仍能核对；
   - 确认、推测、未知分开，当前状态与执行记录一致；
   - 删去重复的背景和说明，但失败与转向不删。
2. **写结果并交付。** 在“结果”一节对照完成条件写实际结果，列出未完成事项，把当前状态更新为最终状态，然后向用户交付完整记录和它的路径。
3. **保留或清理：**
   - 按用户确认的约定保留或清理，并写在“记录处置”；
   - 约定不明确时保留记录并向用户说明，不因任务结束就自行删除；
   - 清理后核实路径已不存在。
4. **任务中断不算结束。** 在当前状态里写明中断点和未决事项，保留记录以便接续。
