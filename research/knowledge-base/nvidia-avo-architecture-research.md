# NVIDIA AVO 架构调研

> **范围**：说明 AVO 是什么、解决什么问题、核心产品思路、架构与证据边界；不把研究结果推断为已发布的产品能力。

## 结论

AVO（Agentic Variation Operators）是一套**面向长时程自主工作的智能体 Harness 架构**：它让通用编码 Agent 围绕可执行目标持续观察、假设、修改、验证和纠错，并用持久记忆、成果谱系与停滞监督保持跨上下文进展。

AVO 不是记忆组件。记忆只是其中一层；完整系统还包括自主执行循环、领域知识、工具、客观评价函数、版本准入和监督机制。所谓“持续进化”，进化的是候选成果、问题认识与外部状态，不是修改大模型权重。

当前 AVO 是研究项目和架构方法。公开材料没有提供官方代码仓库、SDK、安装包或稳定协议，论文使用的是内部开发的通用编码 Agent，不能把它当成已经交付的通用产品。

## 1. 产品思路与核心价值

AVO 面向的不是一次问答，而是可以连续实验并客观验证的长期目标。人提供目标、知识、工具、评价标准和边界，Agent 自主决定查什么、改什么、何时测试以及失败后如何重来。

它的核心价值是：**把模型的一次性生成，升级为可验证、可积累、可恢复的持续搜索过程。**

- **目标不丢失**：评价函数始终定义什么才算正确、什么才算进步。
- **经验可积累**：历史实现、得分、编译与性能反馈成为后续探索的正式输入。
- **进步可验证**：只有通过正确性检查且不弱于当前最佳结果的版本才能进入成果谱系。
- **失败可利用**：失败尝试留在搜索轨迹中，供主 Agent 诊断和监督器复盘。
- **停滞可打破**：系统发现长期无进展或重复失败后，重新审视轨迹并引导新的方向。

AVO 最适合代码优化、算法搜索和自动研究等存在可靠评价器的任务。它的质量上限不仅取决于模型，也取决于评价函数能否真实代表目标；评价器错误或片面，系统就可能稳定地优化错误方向。

## 2. 核心架构

论文将 AVO 形式化为：

```text
Vary(Pₜ) = Agent(Pₜ, K, f)
```

- `Pₜ`：候选成果及其得分构成的完整历史谱系。
- `K`：领域知识库，例如技术文档、硬件资料和参考实现。
- `f`：可执行评价函数，负责正确性验证和多维性能评分。

```text
       历史谱系 Pₜ ─────┐
       领域知识 K ──────┤
       评价函数 f ──────┤
       工具与执行环境 ──┤
                         ▼
                    通用大模型
                         │
                         ▼
        ┌─ 观察 → 假设 → 修改 → 执行 → 评价 ─┐
        │                 AVO 主循环           │
        └──── 诊断失败 ← 不通过 ←─────────────┘
                         │
              正确且不退步│        长期停滞
                         ▼             ▼
                 提交新版本       监督器重定向
                         │             │
                         └── 更新 Pₜ ──┘
```

### 主 Agent 循环

主 Agent 可以查看多个历史版本，比较其评测与分析结果，查询领域资料，然后自主修改、执行和评价候选成果。候选失败时，它继续执行“诊断—修正—再评价”，而不是把第一次输出直接作为答案。

### 持久记忆与成果谱系

AVO 的记忆由两类状态组成：

- 会话历史保存既往修改、编译输出、性能分析、失败与推理轨迹。
- Git 提交与得分保存已经通过准入的成果谱系，形成可恢复、可比较的稳定基线。

二者不能混淆：搜索轨迹允许失败，成果谱系只接纳经过验证的版本。

### 评价与版本准入

评价函数是系统的事实锚点。论文实验同时检查数值正确性与吞吐性能；正确性失败直接记为零分，只有正确且匹配或超过当前最佳得分的候选才会提交。它防止 Agent 用自我评价冒充真实进步。

### 停滞监督

监督机制检测探索耗尽或重复无效循环。触发后，它复查整体演进轨迹并提出若干新方向，将主 Agent 从局部最优或错误路径中拉出。监督器负责改变搜索方向，但不能替代客观评价器决定结果是否成立。

## 3. 运行闭环

1. 从初始成果、领域知识和评价函数开始。
2. Agent 查看历史谱系与当前反馈，形成下一步假设。
3. Agent 使用工具修改成果并执行真实测试。
4. 失败则诊断并继续迭代；正确但退步则拒绝提交。
5. 正确且不退步的版本进入 Git 谱系，成为后续搜索的新基线。
6. 长期无进展时启动监督，重新选择探索方向。
7. 持续循环，直到外部终止条件成立。

这种架构的可迁移性来自替换 `K`、`f` 和环境工具，而不是不需要领域集成。GPU 内核优化使用编译器、性能分析器和吞吐测试；交互推理任务则使用环境状态、动作与结果反馈，但主循环仍是“提出假设—行动—观察证据—更新状态”。

## 4. 证据与边界

- 在论文的 GPU 内核实验中，AVO 连续运行七天，探索超过 500 个方向并提交 40 个版本；在指定配置下，最终成果相对 cuDNN 最高提升 3.5%，相对 FlashAttention-4 最高提升 10.5%。
- 在 ARC-AGI-3 的 25 个公开环境中，AVO 使用 Claude Opus 5 完成全部 183 个关卡，取得 100.00 RHAE。
- 该 100 分只属于公开集，不包含半私有或完全私有集；RHAE 统计环境动作效率，不统计内部推理、工具调用和重试成本。
- 公开材料明确说明，约 30% 的模型基线与 AVO 结果使用了不同推理设置、观察表示、记忆和评测系统，不构成受控消融，不能把 70 个百分点全部归因于 AVO。
- 当前论文只验证了单谱系连续演进；种群分支和档案管理仍属于未来扩展。持久记忆、监督器和内部 Agent 的实现也尚未完整公开。
- AVO 解决的是行为组织与长时程进展，不等于安全边界。公开架构没有给出产品级沙箱、授权、协议兼容和崩溃恢复合同。

## 5. 独立判断

AVO 最有价值的创新不是“给模型增加记忆”，而是建立了四个彼此制约的责任：**Agent 负责探索，评价器负责判断事实，谱系负责保存进步，监督器负责打破停滞。**

这套结构说明，长时程智能首先是系统能力：模型提供推理，工具提供行动，反馈提供现实约束，记忆与版本保存让证据能够累积。但现阶段 AVO 的产品化、可复现性和安全工程仍未完成；它是一项架构价值很高的研究成果，不是已经成熟交付的通用智能体平台。
