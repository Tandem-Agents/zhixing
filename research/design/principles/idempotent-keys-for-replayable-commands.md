# 可重放介质中的控制动作必须有幂等键

## 规则

凡经过"可能不止一次到达"的介质传递的控制动作,必须绑定稳定幂等键与耐久消费记录;**无键的一次性动作被重放即二次生效**。无法幂等化的动作,隔离在可重放域之外。

## 适用场景

动作、指令或请求经过任何不保证 exactly-once 的通道:网络重试、消息渠道 at-least-once 重投、崩溃恢复后的重驱、outbox 重发、**对话历史压缩后的有损重述**。识别信号:你正在设计一个"一次性动作",而它的载体天然允许重复出现——破坏性/非幂等动作在此风险最高。注意:压缩摘要、任务转述、交接文档都属于可重放介质,不只是网络。

## 裁决

1. 每类动作定义**身份键**:由授权动作分配、恒稳定(如目标编号 + 代次);不用内容哈希——内容会漂移,身份不能漂移。
2. 消费记录**耐久且分两步**:接收事实先独立耐久(received);生效时 applied 与权威变更、可回放结果**同一原子提交**——重复到达按键回放原结果,绝不二次生效,也绝无"已生效但无记录"的半提交态。
3. **键与规范载荷绑定**:同键同载荷 → 回放原结果;同键异载荷 → 显式拒绝(idempotency-conflict),不得静默吞并或覆盖——否则键被误复用时,合法的新请求会被当作旧请求的重放吞掉。
4. **执行前提不可作为"是否已执行"的判据**——前提在重放时刻往往依然成立(甚至被动作自己的产物强化),它只会与重放指令互相印证。判据只能是耐久消费记录。
5. 幂等不了的(真正一次性的破坏动作):不进入长任务的指令域/可重放通道,由通道之外的角色单独执行。

## 边界

纯读与天然幂等动作无需此机制。键的粒度即去重语义:过粗会吞掉合法的新请求(同一目标的合法重开需要代次键,如 generation/attempt),过细则失去去重效果。

## 起源与验证案例

- 知行分布式运行时控制面:`(surfacePrincipal, ingressId)` 入口幂等 + ControlRequestJournal 的 received→applied(`research/design/modules/distributed-runtime/specification.md` §5.1/§4.3),覆盖渠道重投、响应丢失、权威重启。
- 工作台压缩重放死循环:"重置文档"作为无键破坏指令留在对话史,压缩还原成待办被重放,工作成果反复归零(`research/agent-workflow-issues/2026-07-14-compaction-replays-destructive-reset.md`);根治 = 登记式进场,键 = (unitId, generation)。
