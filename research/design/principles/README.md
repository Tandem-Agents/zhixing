# Principles — 架构决策规则

> 收录从真实决策中提炼的**架构决策规则**:遇到一类场景时的默认最优裁决。起点可以是某个具体场景,但每条必须给出**通用适用场景**——写给未来的决策看,不与起源案例强相关。
>
> 分层边界:本目录是原则域的**操作层**;价值观层(核心设计哲学)与域入口在 [../principles.md](../principles.md),单点决策记录(ADR)在 `../architecture/decisions/`。规则高于单点决策(从多个决策中提炼)、低于哲学(有明确触发条件与备选对比)。

## 准入标准

- 至少在**两个互相独立的决策点**上被验证过(单案例的"规则"只是那次决策的理由,不入库)。
- 有明确的适用信号与不适用边界——防止规则被教条化。

## 写作纪律

每条一个文件,固定五节:**规则**(一句话)/ **适用场景**(通用化,什么信号说明你遇到了这类问题)/ **裁决**(默认选什么、不选什么、为什么)/ **边界**(何时不适用、代价)/ **起源与验证案例**(一两行 + 链接,放最后)。

全文一屏内说清;凝练是硬要求,长篇大论不收。文件名英文 kebab-case。
