# 跨单元验证运行手册

仅记录已经确认由运行方式或环境导致、且正确方式已经验证通过的失败；功能错误和断言失败不得登记为噪声。通用纪律以工作台静态区为准，本表只保存可按具体任务复用的运行方案。执行相同验证前查表，新经验验证成立后在表尾追加一行。

| 验证任务与适用条件 | 已确认的失败与原因 | 已验证运行方式 | 验证依据 | 失效条件 |
| ------------------ | ------------------ | ---------------- | -------- | -------- |
| 当前低资源 Windows 开发机上，对 CLI、core、executor、mesh 等重型包执行最终包级全测 | 跨包并发或重复启动同一闭包验证，会产生五秒超时、文件锁繁忙或异步等待失败；相关用例隔离和单包复跑均通过 | 启动前确认没有同闭包验证进程；全量构建单独运行，包级全测逐包串行；出现资源型失败时先隔离归因，再以单包结果完成判定 | `unit-16.gen-1.md` X16-02、X16-05、V16-08；`unit-20.gen-1.md` X20-12、V20-23 | 工作台调度规则、测试运行器或本机资源条件变化，并经代表性验证重新确认 |
| CLI 整包 Vitest 首次运行，终端可能截断大量进度输出 | 失败文件和断言未被保留，为取得详情被迫重新运行整包 | 首次运行即用唯一的系统临时路径保存机器可读结果；完成后直接提取失败文件和断言并清理临时文件，不为取证重跑整包 | `unit-18.gen-1.md` V18-17 | 测试运行器或终端能够稳定、完整地保留全部失败详情 |
| 使用 `pnpm --filter <包> exec vitest` 定向运行测试 | 过滤后工作目录已切到包根；继续传仓库根相对路径会得到“无测试文件” | 测试路径始终相对被过滤包的根目录 | 第 21 单元 CLI 定向集以包内路径一次通过 | pnpm 的 `--filter exec` 工作目录语义变化 |
| PowerShell 向 Biome 传递动态文件列表 | 经 `pnpm exec ... -- $files` 转发会把列表合并成一个无效路径 | 调用 `.\node_modules\.bin\biome.cmd check @files`，用数组 splatting 传递文件列表 | 第 21 单元变更文件检查通过 | pnpm 或 PowerShell 的参数转发语义变化 |
| 当前低资源 Windows 开发机上执行 executor 全包测试，机器结果仅出现默认时限附近的超时，且没有功能断言失败 | 既有耐久 IO 用例会被机器 IO 抖动随机击中；改为单 worker 仍会漂移，反复整包运行只会更换超时点 | 首次全包必须保存机器结果。只定向复跑超时用例：定向通过后，以“全包其余结果 + 定向结果”完成判定，禁止再次运行 executor 全包或改用单 worker；定向失败才按功能问题处理。命中本行时，本行覆盖上方“单包复跑”动作。若修改测试预算导致输入变化，再按失效闭包验证；本单元新增的同类测试缺预算时，须为测试组设置显式有界预算 | 第 21 单元三次全包均为 437/438，三个不同超时用例定向均通过；无残留验证进程、无功能断言失败 | executor 测试预算完成系统治理，或当前机器 / Vitest 调度与时限语义变化 |
