# 跨单元验证运行手册

仅记录已经确认由运行方式或环境导致、且正确方式已经验证通过的失败；功能错误和断言失败不得登记为噪声。通用纪律以工作台静态区为准，本表只保存可按具体任务复用的运行方案。执行相同验证前查表，新经验验证成立后在表尾追加一行。

> **验证可行性门禁**：新增强制验证前，先区分功能正确性证据与纯观测/benchmark。只收集信息的性能观测不得成为开发单元同步阻断门禁，也不得与功能测试绑成不可拆分总命令。任何预计超过 10 分钟、无进度或不可断点续跑的本地门禁，必须先证明不可替代性并取得用户明确认可；否则改为按需诊断或低频独立任务。

| 验证任务与适用条件 | 已确认的失败与原因 | 已验证运行方式 | 验证依据 | 失效条件 |
| ------------------ | ------------------ | ---------------- | -------- | -------- |
| 当前低资源 Windows 开发机上，对 CLI、core、executor、mesh 等重型包执行最终包级全测 | 跨包并发或重复启动同一闭包验证，会产生五秒超时、文件锁繁忙或异步等待失败；相关用例隔离和单包复跑均通过 | 启动前确认没有同闭包验证进程；全量构建单独运行，包级全测逐包串行；出现资源型失败时先隔离归因，再以单包结果完成判定 | 重型包并发失败后，隔离与单包复跑均通过 | 工作台调度规则、测试运行器或本机资源条件变化，并经代表性验证重新确认 |
| CLI 整包 Vitest 首次运行，终端可能截断大量进度输出 | 失败文件和断言未被保留，为取得详情被迫重新运行整包 | 首次运行即保存机器可读结果；完成后直接提取失败文件和断言并清理，不为取证重跑整包 | 机器结果一次定位失败文件与断言，定向归因完成 | 测试运行器或终端能够稳定、完整地保留全部失败详情 |
| 使用 `pnpm --filter <包> exec vitest` 定向运行测试 | 过滤后工作目录已切到包根；继续传仓库根相对路径会得到“无测试文件” | 测试路径始终相对被过滤包的根目录 | CLI 定向集改用包内路径后一次通过 | pnpm 的 `--filter exec` 工作目录语义变化 |
| PowerShell 向 Biome 传递动态文件列表 | 经 `pnpm exec ... -- $files` 转发会把列表合并成一个无效路径 | 调用 `.\node_modules\.bin\biome.cmd check @files`，用数组 splatting 传递文件列表 | 动态变更文件列表检查一次通过 | pnpm 或 PowerShell 的参数转发语义变化 |
| 当前低资源 Windows 开发机上执行 executor 全包测试，机器结果仅出现默认时限附近的超时，且没有功能断言失败 | 耐久 IO 用例会被机器负载随机击中；改为单 worker 仍会漂移，反复整包只会更换超时点 | 首次全包保存机器结果；只定向复跑超时项。定向通过后以“全包其余结果 + 定向结果”判定，禁止重跑整包；定向失败才按功能问题处理。修改测试输入后只验证失效闭包；新增耐久 IO 测试复用包内组级有界预算 | 三次全包各仅一项超时且位置漂移，三个超时项定向均通过 | executor 测试预算完成系统治理，或当前机器 / Vitest 调度与时限语义变化 |
| 当前低资源 Windows 开发机上执行 executor 全包，最终状态轮询断言在包负载或连续隔离后超出自身短等待窗口 | 耐久 I/O 与连续进程启动会延迟后台恢复轮；同一用例在无其他验证进程的独立新进程中无需修改即可通过 | 保留首次全包结果；先按失败用例单独启动一个全新的 Vitest 进程，期间不串行夹带其他隔离项。单例通过后与全包其余结果合并；单例仍失败才按功能问题处理，禁止放宽业务断言 | owner cancellation fence 用例在全包及连续隔离后停于短等待窗口，独立新进程 1/1 通过，生产代码未变 | 测试时钟、恢复调度或本机资源条件变化 |
| 当前低资源 Windows 开发机上执行昂贵包级 Vitest | JSON 仅在结束时写结果，dot 不能定位失败；截止过短会丢失失败名称并迫使重跑 | 首次即使用 verbose + JSON，stdout/stderr 分开落盘；硬截止取近期成功耗时的两倍。到期保留日志、终止进程树并只定向归因；结果已登记且失败已归因后删除日志和结果，不为定位重跑整包 | JSON-only 截止后无结果，dot + JSON 只有失败标记；verbose + JSON 一次取得 447 项通过结果及 6 个失败名称 | reporter 输出时机、测试运行器或本机耗时基线变化 |
| PowerShell 验证需要落盘机器结果 | 组合执行“运行、读取、清理”可能被环境策略拦截；从包目录运行时按当前目录拼接仓库级临时路径，会在测试启动前因路径不存在而失败 | 结果文件放工作区临时路径，运行、读取、清理分开执行；从包目录运行时先显式解析仓库根，再构造结果路径。重试前先查进程与结果：已启动则读取，确认未启动才重跑。结果读取、登记且失败归因后，先核验目标位于工作区；`Remove-Item` 被拦截时用文件编辑工具删除文件，再删除空目录。收口前确认零残留 | 拆分后测试一次完成；显式解析仓库根后隔离用例一次通过；策略拦截清理时，文件编辑工具删除结果、空目录删除后零残留 | 仓库目录层级、环境策略、命令执行器或临时文件权限变化 |
| 当前低资源 Windows 开发机上新增 CLI 耐久 IO 集成测试 | 30 秒预算在包级负载下超时，定向运行功能断言通过 | 新增同类测试直接复用包内 120 秒有界预算；失败断言仍立即终止，不以延长预算掩盖逻辑错误 | 定向 5/5、CLI 全包 2436/2436 通过 | 本机资源条件、测试实现或包内既定耐久 IO 预算变化 |
| 修改上游包源码后，从下游包运行跨包测试 | 下游按包导入读取旧 `dist`，会把已修复源码表现成旧行为失败 | 先构建发生变化的上游包，再运行下游定向测试；不得用旧产物结果裁决实现 | 上游重建前 4 项旧行为失败，重建后同一定向集 6/6 通过 | 工作区包解析不再依赖构建产物 |
| 当前低资源 Windows 开发机上执行 owner-kernel 全包测试，机器结果仅有默认 5 秒超时且无功能断言失败 | 包内并发负载会使耐久 resource-governor 用例越过默认时限 | 保留首次全包结果，只隔离超时单例；定向通过后以“全包其余结果 + 定向结果”判定，禁止重跑整包 | 全包 189 项通过、唯一超时项定向 1/1 通过 | 测试预算、本机资源或 Vitest 调度语义变化 |
| 当前低资源 Windows 开发机执行 core 全包或含多项 fsync 的耐久 I/O 整文件测试，仅出现时限超时且无功能断言失败 | 包内并发或文件内累计 I/O 负载会使批次用例越过组级时限 | 保留首次结果，只隔离超时单例；定向通过后合并两份证据判定，禁止重跑原范围 | 全包其余 2449 项与定向 1/1 通过；整文件其余 8 项与定向 1/1 通过 | 测试预算、本机资源或 Vitest 调度语义变化 |
| Windows 后台执行 CLI 全包并重定向机器结果 | `pnpm --filter @zhixing/cli exec vitest` 可能在测试中途由包装层报 `Command "vitest" not found`，零失败断言且不生成 JSON | 从 `packages/cli` 直接用 Node 启动包内 `node_modules/vitest/vitest.mjs`，保留相同 reporter、结果路径与硬截止 | 包装层中止后，直接启动同一测试集 174 文件、2447/2447 通过 | pnpm 包装层或后台进程托管方式变化，并经 CLI 全包验证 |
| 当前低资源 Windows 开发机执行工作区全量构建 | 180 秒外层截止会在递归构建后段关闭输出并触发 `EPIPE`，已完成包被迫面临重复构建 | 首次硬截止按近期完整耗时的两倍设置为至少 450 秒；若外层仍中止，先确认进程已结束并按产物时间识别未完成包，只按依赖顺序补建缺失包 | 递归构建已完成 15/17 包后中止，随后仅补建 executor、CLI，17 包全部成功 | 工作区包数、构建编排、本机性能或外层截止语义变化 |
| 包内 TypeScript 类型检查 | 仓库根 `pnpm exec tsc` 可能解析到非工作区版本并产生大量伪错误 | 使用 `pnpm --filter <包> exec tsc -p tsconfig.json --noEmit`，让命令从目标包解析工作区 TypeScript | core 包过滤命令零错误通过；根命令使用旧版本产生环境型伪错误 | TypeScript 依赖布局或 pnpm 解析语义变化 |
| 当前低资源 Windows 开发机上 core 重耐久 IO 测试文件(authority 层四文件)使用 30 秒组级预算 | 单条耐久用例真实耗时可达 20-30 秒(放宽预算实测 20.7 秒通过),30 秒档被临界抖动随机击穿:同一用例隔离两次卡满 30.08 秒、第三次 20.7 秒通过,零功能断言失败 | 四文件组级预算对齐既有 CLI 先例的 120 秒档(artifact-lifecycle-index、durable-projection-index、authority-storage、surface-assets);断言失败仍立即终止,不以延长预算掩盖逻辑错误 | 对齐后 lifecycle 整文件 22/22、surface-assets 46/46、core 整包 2600/2601(唯一失败为 5 秒档负载超时,隔离 2.2 秒通过) | 本机资源条件、测试实现或 Vitest 调度语义变化 |
| 下游包类型检查与工作区全量构建并发执行 | 下游按包导入解析上游 `dist` 的声明；构建正在改写 `dist` 时解析到半写状态，产生成百的伪错误（实测 CLI 449、runtime-host 3），且错误内容与实现无关 | 类型检查必须等全量构建结束后串行执行；启动前确认没有同闭包构建进程 | 同一交付物上，构建进行中 CLI 449/runtime-host 3，构建结束后串行重跑为 CLI 8（既有基线）/runtime-host 0，其余五包零错 | 下游类型检查不再依赖上游构建产物 |
