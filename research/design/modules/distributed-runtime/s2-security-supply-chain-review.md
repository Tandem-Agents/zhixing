# S2 安全依赖供应链评审

评审日期：2026-07-12。范围仅含 `@zhixing/mesh` 为设备证书与短码配对引入的外部运行时依赖；完整机器清单以 [`packages/mesh/security-dependencies.json`](../../../../packages/mesh/security-dependencies.json) 为单源。

## 裁决

| 直接依赖 | 锁定版本 | 用途边界 | 裁决 |
|---|---:|---|---|
| `@peculiar/webcrypto` | 1.7.1 | 证书签发所需 WebCrypto 兼容层 | 接受；不进入实时 TLS 数据通道 |
| `@peculiar/x509` | 2.0.0 | 短期设备证书签发与解析 | 接受；实时认证由 Node TLS/OpenSSL 承担 |
| `reflect-metadata` | 0.2.2 | X.509 依赖栈的装饰器元数据 | 接受；不执行密码学操作 |
| `@cipherman/pake-js` | 0.1.1 | P-256 SPAKE2+ 短码交换 | 条件接受；审批前仅作开发依赖和未发布适配器，不进入生产安装或产品装配 |

三个生产直接依赖、一个受控开发依赖及其 21 个传递依赖均已核对来源、许可证与安装脚本：许可证为 MIT、Apache-2.0、BSD-3-Clause 或 0BSD，未发现安装生命周期脚本；锁文件保留所有包的 registry 完整性摘要。2026-07-12 使用 npm 官方审计源检查时，本清单闭包未命中已知漏洞。仓库其他依赖的既有告警不属于本评审范围，不得据此宣称仓库级审计通过。

## 强制门禁

- `package.json` 中四个直接安全依赖必须精确锁版；`.npmrc` 强制 frozen lockfile，锁文件与清单不一致即安装失败。
- `pnpm security:supply-chain` 校验直接版本、完整性摘要、完整运行时闭包、许可证、安装脚本和固定向量文件；仓库 `lint` 必经该门禁，脚本也必须可由 `node` 跨平台直跑。
- 四个受管依赖只能由 `@zhixing/mesh` 声明；门禁从 pnpm workspace 实际项目表覆盖 `packages/*`、`packages/channels/*` 与 `apps/*`，不得由其他包直接引入绕过评审。
- 任何升级必须同时更新清单、锁文件、官方漏洞审计结果、受影响测试和本评审，不允许只改版本范围。
- SPAKE2+ 使用项目自持的 RFC 9383 Appendix C P-256/SHA-256 固定向量，逐字节核验 `L/shareP/shareV/Z/V`、全部派生密钥与双向确认值；不得用本实现生成的期望值替代标准向量。
- `@cipherman/pake-js` 为新发布的 pre-1.0 实现。它在审批前只能作为 mesh 的精确锁定开发依赖存在于内部适配器，不进入生产依赖；通用 pairing 与 bootstrap 仅依赖项目接口并显式注入。主 barrel 不导出 pairing，运行时导出门禁从 pairing 子入口机械对账而非维护符号名单；适配器既无 package export、也不进入构建入口。门禁拒绝任何 workspace 生产源码加载适配器或直接引入该依赖。
- 解除阻断必须对当前精确版本及 `@noble/curves`/`@noble/hashes` 闭包完成独立安全审计，或替换为更成熟实现，并登记带摘要的不可变证据后显式增加适配器子入口。替换不得改变协议套件名、wire 字节与应用层耐久限次纪律。

## 接受依据

证书依赖被围在签发路径，实时通道继续使用 Node TLS 1.3/OpenSSL、根指纹钉扎和短期叶证书；PAKE 依赖被物理适配器与 package export 双重隔离，通用模块不加载第三方实现，在线尝试在任何秘密相关响应前已耐久计费，offer 限时、单次且失败封闭。固定标准向量解决互操作与替换一致性，但不被当作第三方安全审计的替代品。

替换评估未发现可直接采用的成熟 Node.js RFC 9383 实现：旧 `spake2` 包面向早期 draft，不能替代当前套件；其他可见实现主要位于 Go、Rust 等生态。自行重写密码学实现的风险高于当前“标准向量 + 窄接口 + 未审计前禁生产挂载”的组合，因此本阶段保留条件接受。
